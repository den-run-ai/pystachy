Pystachy v0.4.0 adds bounded structural matching, a native pytest runner, guarded
list-loop optimization and expanded compiler safety checks. Stabilization corrects
exception-field crashes, collection metadata, comparisons, integer enum exit statuses
and generic annotations. Pystachy remains an experimental compiler for a typed subset
of Python.

## Language and library improvements

- Bounded `match` supports literals, captures, alternatives, guards, fixed-length tuples
  and plain fields of statically known dataclasses. Mapping, starred and general sequence
  patterns remain unsupported.
  [Pattern contract](https://github.com/den-run-ai/pystachy/blob/v0.4.0/docs/language/semantics.md#structural-patterns)
- The native pytest runner checks a documented dialect against original CPython
  collection and outcomes, then runs JIT and AOT. Selected JSON-repair, CPython and
  mypy/mypyc tests are qualified; complete upstream suites remain outside its scope.
  [Runner](https://github.com/den-run-ai/pystachy/blob/v0.4.0/docs/pytest-native.md),
  [upstream selections](https://github.com/den-run-ai/pystachy/blob/v0.4.0/tests/upstream/pytest/README.md)
- Library additions include CPython accelerator ordering in `heapq`, bounded
  `statistics.linear_regression`, exception classes as handler values, iterable defaults
  for `min`/`max`, path and environment APIs, and an updated JSON-repair port.
  [Library contracts](https://github.com/den-run-ai/pystachy/blob/v0.4.0/lib/compatibility.md)

## Correctness repairs

- Base-typed exception fields safely read subclass class defaults. Empty-tuple list
  construction retains GC scanning until its element representation is known.
  [RC.1 corrections](https://github.com/den-run-ai/pystachy/releases/tag/v0.4.0-rc.1)
- Integer enum exit statuses use the member's stored integer, including zero and
  computed flags. Generic annotations no longer compile special methods before module
  globals are declared. Narrowed generator yields pass the IR checker without weakening
  payload guards.
  [RC.2 source notes](https://github.com/den-run-ai/pystachy/blob/bf699eb5ba0bc8ba2371f4d1740683be59594f58/docs/releases/v0.4.0-rc.2.md)
- Nested collection union descriptors separate class identifiers from following member
  lengths, preventing a value from being formatted as the wrong class. Empty-tuple
  descriptors retain their length fields. Nullable values of different user classes
  compare equal when both hold `None`, including explicit `__ne__` methods.
- Tuple membership, `count()` and `index()` recognize the same object held through
  reference unions, including `None`. Custom equality dispatch for class unions and
  some base-typed subclass values remains incomplete.
  [#1432](https://github.com/den-run-ai/pystachy/issues/1432)

## Performance and verification

Guarded list loops remove eligible repeated bounds checks with a checked fallback.
Private scalar dictionary lookups avoid unnecessary boxing. Whole-string prefix and
suffix tests avoid redundant code-point counting. Guarded loop copies preserve eligible
single-use inlining, correcting the floating-point workload regression.
[Optimization contracts](https://github.com/den-run-ai/pystachy/blob/v0.4.0/docs/typed-ir.md#optimizations)

Typed-IR and optional Lean checks cover selected payload guards, bounds, entry liveness,
integer storage and stack copies. Their normalized models and trusted boundaries do not
prove whole-compiler or GC correctness.
[Proof scope](https://github.com/den-run-ai/pystachy/blob/v0.4.0/tools/lean_boundary/README.md)

## Known limits

The earlier RC notes made linear GC scaling and repeated 20% CI headroom prerequisites
for stable. Those engineering targets are explicitly deferred and remain open; they are
not claimed complete. The existing full verification, 15-minute job limits and 600-second
GC guard remain required. RC.2's GC run measured 290.38 seconds; larger-source scaling is
still near quadratic.
[#1178](https://github.com/den-run-ai/pystachy/issues/1178),
[#1179](https://github.com/den-run-ai/pystachy/issues/1179),
[#1181](https://github.com/den-run-ai/pystachy/issues/1181)

Dynamic `Any` and promoting integers remain experimental opt-ins. Known limitations
include tuple searches requiring runtime subclass equality, promoting-integer tuple
membership, class reads through circular-import aliases, missing `ImportError` for
circular from-imports of unbound names, closed standard streams and residual GC cost in
the words benchmark. The broader tuple-dispatch and circular-import prototypes introduce
new rejections and are excluded.
[#1430](https://github.com/den-run-ai/pystachy/issues/1430),
[#1354](https://github.com/den-run-ai/pystachy/issues/1354),
[#1398](https://github.com/den-run-ai/pystachy/issues/1398),
[compatibility reference](https://github.com/den-run-ai/pystachy/blob/v0.4.0/docs/language/compatibility.md)

Async, broader language composition, complex-number support, native compiler wheels and
experimental optimization stacks remain separate work.

## Platforms

| Native archive | Requirements |
|---|---|
| Linux x86-64 / AArch64 | Ubuntu 24.04 or compatible glibc 2.39+ Linux; LLVM 18 |
| macOS arm64 / x86-64 | macOS 15+, Xcode Command Line Tools; LLVM 20 |

Archives and Docker run without Python; the hosted compiler needs Python 3.11+. Full
verification targets Linux x86-64 and ARM64 with CPython 3.13.16. macOS has narrower
installation and release coverage, with Intel macOS secondary. Linux archives are not
manylinux packages.

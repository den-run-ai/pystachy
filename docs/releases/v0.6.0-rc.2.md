Pystachy v0.6.0-rc.2 is the last release candidate for v0.6.0. Since rc.1, it keeps the
numeric defaults of fields typed as a union with a class under dynamic `Any`, finds a dict
entry that a key's `__eq__` moved instead of writing outside the dict, and answers
`isinstance()` and `==` for ranges held as `Any`. Pystachy remains an experimental compiler
for a typed subset of Python.

## Corrections since rc.1

- In a module that opts in to dynamic `Any`, a dataclass or `NamedTuple` field typed as a
  union with a class, as in `y: int | P = 0`, keeps its numeric default when a call leaves
  it out. Since alpha.2, which began to compile such unions, the field read `None`.
  ([#1598](https://github.com/den-run-ai/pystachy/pull/1598))
- A dict lookup whose key's `__eq__` removes the entry it compares and stores the key again
  finds the entry where it moved, as CPython does. Previously `d[k] = v` wrote outside the
  dict there, and reads, `in`, `del` and `pop` answered wrongly. This predates the alphas.
  ([#1580](https://github.com/den-run-ai/pystachy/issues/1580))
- With dynamic `Any`, `isinstance(x, range)` is true for a range, and a range compared with
  a value of another type is unequal instead of raising `AttributeError`.
  ([#1595](https://github.com/den-run-ai/pystachy/pull/1595))

## Features carried from the alphas

- **Typing and fields:** field and annotation types inferred in code like mypy's, sequence
  patterns on lists, and new standard library modules and functions.
  [Alpha.1](https://github.com/den-run-ai/pystachy/releases/tag/v0.6.0-alpha.1)
- **Classes and unions:** more of mypy's class and typing patterns, classes as values,
  objects beside numbers and strings in unions and runtime-length tuples, `__index__` where
  CPython asks for it, and a wider `decimal`.
  [Alpha.2](https://github.com/den-run-ai/pystachy/releases/tag/v0.6.0-alpha.2)
- **Library, types and speed:** `pprint`, `inspect`, `subprocess`, `importlib.resources`,
  `concurrent.futures`, `gc` and `bytearray`; `int` arguments for `float` parameters; native
  `unittest` suites; faster string case methods and numeric paths; and a restructured typed
  IR. [Alpha.3](https://github.com/den-run-ai/pystachy/releases/tag/v0.6.0-alpha.3)
- **Release candidate 1:** in-place operators that call a subclass's method through a value
  typed with its base class, enum members whose `__new__` annotates its return, and the
  undecodable bytes of host paths in `__file__`.
  [rc.1](https://github.com/den-run-ai/pystachy/releases/tag/v0.6.0-rc.1)

## Known limits

Dynamic `Any` and promoting integers remain experimental opt-ins. Known issues that predate
the alphas include reads of a builtin's name where a module global of that name is unbound
([#1512](https://github.com/den-run-ai/pystachy/issues/1512)), star imports from a module
that binds `__all__` inside `try` or `if`
([#1513](https://github.com/den-run-ai/pystachy/issues/1513)), an `except` clause's `as`
name that an import bound ([#1514](https://github.com/den-run-ai/pystachy/issues/1514)),
`isinstance()` of `Any` values that hold `NamedTuple` objects
([#1581](https://github.com/den-run-ai/pystachy/issues/1581)) and `isinstance()` tests
against a second base class ([#1602](https://github.com/den-run-ai/pystachy/issues/1602)).
The
[compatibility reference](https://github.com/den-run-ai/pystachy/blob/v0.6.0-rc.2/docs/language/compatibility.md)
lists the documented deviations.

Mapping patterns, async, full native mypy and broad concurrency remain outside v0.6.0. Fixes
found after this candidate ship in v0.6.0.

## Platforms

| Native archive | Requirements |
|---|---|
| Linux x86-64 / AArch64 | Ubuntu 24.04 or compatible glibc 2.39+ Linux; LLVM 18 |
| macOS arm64 / x86-64 | macOS 15+, Xcode Command Line Tools; LLVM 20 |

Archives and Docker run without Python; the hosted compiler needs Python 3.11+ and reports
`commit unknown` when installed with pip. Full verification targets Linux x86-64 and ARM64
with CPython 3.13.16. Linux archives are not manylinux packages. This prerelease keeps the
stable defaults at v0.5.0.

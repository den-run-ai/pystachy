Pystachy v0.6.0-rc.1 freezes the v0.6.0 feature set for final qualification. Since alpha.3,
it calls a subclass's in-place operator method through a value typed with its base class,
makes enum members whose `__new__` annotates its return, and keeps the undecodable bytes of
host paths in `__file__`. Pystachy remains an experimental compiler for a typed subset of
Python.

## Corrections since alpha.3

- `x += y` and the other in-place operators call the in-place method of the object's class
  where a subclass defines one and the class that `x` is typed with does not, as CPython
  does, so other names for the object see the change. Previously the class's `__add__`
  rebound `x` to a new object, also in the list and dict displays, conditional expressions
  and `int | C` unions that alpha.2 began to compile. Results with no common type are
  rejected. ([#1538](https://github.com/den-run-ai/pystachy/issues/1538))
- An enum class whose `__new__` annotates its return, as in
  `def __new__(cls, value) -> "Coord":`, makes its members as CPython does. Alpha.2 and
  alpha.3 raised `RuntimeError` as each member was made.
  ([#1555](https://github.com/den-run-ai/pystachy/issues/1555))
- In a directory whose name is not valid UTF-8, the native compiler writes the name's bytes
  unchanged into `__file__`, `importlib.metadata`'s search path and debug locations, as the
  hosted compiler does. Previously `os.path.isfile(__file__)` was false there.
  ([#1523](https://github.com/den-run-ai/pystachy/issues/1523))

## Features carried from the alphas

- **Typing and fields:** field and annotation types inferred in code like mypy's, sequence
  patterns on lists, and new standard library modules and functions.
  [Alpha.1](https://github.com/den-run-ai/pystachy/releases/tag/v0.6.0-alpha.1)
- **Classes and unions:** more of mypy's class and typing patterns, classes as values,
  objects beside numbers and strings in unions and runtime-length tuples, `__index__` where
  CPython asks for it, and a wider `decimal`.
  [Alpha.2](https://github.com/den-run-ai/pystachy/releases/tag/v0.6.0-alpha.2)
- **Library, types and speed:** `pprint`, `inspect`, `subprocess`, `importlib.resources`,
  `concurrent.futures`, `gc` and `bytearray`; `int` arguments for `float` parameters; native
  `unittest` suites; faster string case methods and numeric paths; and a restructured typed
  IR. [Alpha.3](https://github.com/den-run-ai/pystachy/releases/tag/v0.6.0-alpha.3)

## Known limits

Dynamic `Any` and promoting integers remain experimental opt-ins. Known issues that predate
the alphas include reads of a builtin's name where a module global of that name is unbound
([#1512](https://github.com/den-run-ai/pystachy/issues/1512)), star imports from a module
that binds `__all__` inside `try` or `if`
([#1513](https://github.com/den-run-ai/pystachy/issues/1513)) and an `except` clause's `as`
name that an import bound ([#1514](https://github.com/den-run-ai/pystachy/issues/1514)). The
[compatibility reference](https://github.com/den-run-ai/pystachy/blob/v0.6.0-rc.1/docs/language/compatibility.md)
lists the documented deviations.

Mapping patterns, async, full native mypy and broad concurrency remain outside v0.6.0.
Release candidates accept fixes within the frozen scope.

## Platforms

| Native archive | Requirements |
|---|---|
| Linux x86-64 / AArch64 | Ubuntu 24.04 or compatible glibc 2.39+ Linux; LLVM 18 |
| macOS arm64 / x86-64 | macOS 15+, Xcode Command Line Tools; LLVM 20 |

Archives and Docker run without Python; the hosted compiler needs Python 3.11+ and reports
`commit unknown` when installed with pip. Full verification targets Linux x86-64 and ARM64
with CPython 3.13.16. Linux archives are not manylinux packages. This prerelease keeps the
stable defaults at v0.5.0.

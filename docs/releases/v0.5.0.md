Pystachy v0.5.0 extends class typing and generics, adds numeric protocols, complex numbers,
a bounded `decimal` module, `hashlib` and `hmac`, and runs the compiler as explicit stages.
It corrects tuple searches, optional-import handlers and cross-module context managers.
Pystachy remains an experimental compiler for a typed subset of Python.

## Language and library improvements

- Classes in hierarchies can store annotated template objects such as
  `defaultdict[str, set[str]]`, take non-scalar `Final` and initialized `ClassVar`
  attributes, and read earlier class-body constants. Generic visitors such as
  `class TextVisitor(Visitor[str])` infer `accept()` results, and fixed-layout classes
  specialize their constructors independently.
  [Generic classes](https://github.com/den-run-ai/pystachy/blob/v0.5.0/docs/language/typing.md#class-templates-and-generic-classes)
- Objects can supply the conversion and rounding methods behind `int()`, `float()`,
  `round()`, `math.floor()`, `math.ceil()` and `math.trunc()`. Builtin numbers on the left
  call supported reflected methods, and comparison methods can return `NotImplemented`.
  [#1340](https://github.com/den-run-ai/pystachy/pull/1340),
  [#1472](https://github.com/den-run-ai/pystachy/pull/1472)
- Complex numbers support literals, `complex()`, arithmetic, comparison, hashing and
  formatting with CPython 3.13's algorithms. Ordering, floor division, modulo and `cmath`
  are not included. [#1408](https://github.com/den-run-ai/pystachy/pull/1408)
- The `decimal` subset covers exact construction, context-rounded arithmetic, comparisons,
  formatting, `quantize()`, `sqrt()` and all eight rounding modes; signals, traps and
  transcendental functions are not included. `hashlib` implements MD5, SHA-1, SHA-224 and
  SHA-256 over `bytes`, and `hmac` builds on them, with `compare_digest()`.
  [Library limits](https://github.com/den-run-ai/pystachy/blob/v0.5.0/lib/compatibility.md)
- Sets and dictionaries accept `None`, optional, runtime-length tuple and identity-hashed
  class-union keys. Numbers keep their identities where they cross into dynamic `Any`,
  including generator yields and runtime-length tuple items.
  [#1412](https://github.com/den-run-ai/pystachy/pull/1412),
  [boundary contract](https://github.com/den-run-ai/pystachy/blob/v0.5.0/docs/dynamic-any.md)
- Native pytest failures show the exception and comparison operands, and node IDs select
  tests. [Runner](https://github.com/den-run-ai/pystachy/blob/v0.5.0/docs/pytest-native.md)

## Compiler, builds and verification

The compiler runs six explicit stages; finalization exposes a typed IR that the hosted
inspection prototype can stop at before LLVM lowering. Wide class hierarchies share
generated method dispatchers, and `pystachy build` links a cached precompiled runtime,
which shortened local builds and enlarged executables.
[Stages](https://github.com/den-run-ai/pystachy/blob/v0.5.0/docs/typed-ir.md#pipeline),
[build measurements](https://github.com/den-run-ai/pystachy/pull/1488#issuecomment-6875913105)

Optional Lean checks now also cover field initialization, promoting-integer storage,
collector arrays, emitted class layouts, identity companions and compiler stage order.
These bounded models do not prove whole-compiler or collector correctness.
[Proof scope](https://github.com/den-run-ai/pystachy/blob/v0.5.0/tools/lean_boundary/README.md)

## Correctness repairs

- Tuple `in`, `count()` and `index()` dispatch equality through runtime subclasses and
  class unions. Under `# pystachy: python-int`, they compare promoting integers with closed
  unions in either direction.
  [#1440](https://github.com/den-run-ai/pystachy/pull/1440),
  [#1506](https://github.com/den-run-ai/pystachy/pull/1506)
- An optional import's handler catches a program-defined subclass of `ImportError` raised by
  the statements after its imports, instead of the program ending.
  [Optional imports](https://github.com/den-run-ai/pystachy/blob/v0.5.0/docs/language/modules.md#optional-imports)
- A cross-module `super()` call to a `contextmanager` method runs the base class's
  generator ([#1470](https://github.com/den-run-ai/pystachy/pull/1470)). The JIT launcher
  finds `libLLVM` through a symlinked `lli`.

## Known limits

Dynamic `Any` and promoting integers remain experimental opt-ins. Known issues include reading
a builtin's name where a module global of that name is unbound
([#1512](https://github.com/den-run-ai/pystachy/issues/1512)), star imports from a module that
binds or extends `__all__` outside its top-level statements
([#1513](https://github.com/den-run-ai/pystachy/issues/1513)) and an `except` clause's `as`
name that an import also binds ([#1514](https://github.com/den-run-ai/pystachy/issues/1514)).

A from-import of a name that a circular import has not bound yet does not raise
`ImportError` ([#1398](https://github.com/den-run-ai/pystachy/issues/1398)), and standard
streams closed at startup are not `None`
([#1182](https://github.com/den-run-ai/pystachy/issues/1182)). The
[compatibility reference](https://github.com/den-run-ai/pystachy/blob/v0.5.0/docs/language/compatibility.md)
lists the other deviations, including the remaining optional-import cases.

`importlib.metadata`, async, full native mypy and broad concurrency remain outside v0.5.0.

## Platforms

| Native archive | Requirements |
|---|---|
| Linux x86-64 / AArch64 | Ubuntu 24.04 or compatible glibc 2.39+ Linux; LLVM 18 |
| macOS arm64 / x86-64 | macOS 15+, Xcode Command Line Tools; LLVM 20 |

Archives and Docker run without Python; the hosted compiler needs Python 3.11+ and reports
`commit unknown` when installed with pip. Full verification targets Linux x86-64 and ARM64
with CPython 3.13.16. Linux archives are not manylinux packages.

Pystachy v0.4.0-alpha.4 fixes optional exception identity, adds a generated
runner for a bounded pytest dialect, and broadens dynamic payload verification.
It also removes temporary boxes from private scalar dictionary lookups and
extends AddressSanitizer instrumentation to generated AOT and extension code.
Pystachy remains an experimental compiler for a typed subset of Python.

## Correctness and testing

- Preserve exception identity through optional fields, locals and parameters,
  including both operand orders, repeated catches and `None`. Caught wrappers
  now use the existing canonical identity with a null guard; equality behavior,
  object representations and allocation behavior are unchanged. This fixes the
  pre-existing issue disclosed for alpha.3.
  [#1231](https://github.com/den-run-ai/pystachy/issues/1231)
- Add a hosted collector that generates typed test programs for CPython, native
  JIT or native AOT execution. The supported dialect includes static
  parametrization, module-defined function-scoped fixtures, teardown,
  `raises`, skips and expected failures.
  Original-source comparison with real pytest is enabled by default and checks
  collected IDs, order and setup/call/teardown outcomes. Explicit `--no-compare`
  runs are labelled unverified and are intended for previously qualified,
  unchanged inputs. Imported test classes fail collection; comparison catches
  behavior hidden in imported objects, including autouse fixtures. Explicit
  parametrization IDs retain pytest's Unicode and control-character escaping.
  [#1232](https://github.com/den-run-ai/pystachy/pull/1232),
  [runner contract](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.4/docs/pytest-native.md)
- Include bounded consumers for JSON repair, ported libraries and standard
  library APIs, plus an unchanged mypyc `NameGenerator` component. Selected
  `unittest` methods can be exported to the same runner with explicit limits.
  These are component and adapted-suite checks; upstream pytest itself and
  arbitrary mypy/mypyc or CPython test suites are not compiled. The runner is a
  source-checkout development tool, and requires the pinned development pytest
  for comparison. Direct execution benchmarks are measured after oracle
  qualification; they exclude rerunning the oracle in every timed sample.
  [examples](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.4/examples/pytest_native/README.md),
  [mypyc scope](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.4/examples/pytest_native_mypyc/README.md)

## Dynamic boundaries and Lean verification

- Extend the optional Lean bridge to real typed-IR control flow, private storage,
  calls, exception edges, phi nodes and short-circuit guards. Descriptor sets
  cover supported class/subclass, integer/bool and container payload layouts.
  Full slot names distinguish assignment flags and identity companions; valid
  identity arguments begin with unknown tags, while malformed companions are
  rejected. This resolves the diagnostic gap tracked in #1230.
  [#1224](https://github.com/den-run-ai/pystachy/pull/1224),
  [#1226](https://github.com/den-run-ai/pystachy/pull/1226),
  [#1234](https://github.com/den-run-ai/pystachy/pull/1234)
- Add whole-snapshot checking and a corpus gate for test programs that opt in to
  dynamic `Any` or directly or transitively import a module that does. It accounts for every exported
  payload read, fails on rejected, unsupported or malformed payload functions,
  and records programs with no reads separately. The selector uses the same
  pragma-byte interpretation as the compiler, including a UTF-8 BOM.
  [#1228](https://github.com/den-run-ai/pystachy/pull/1228)
- With `PYSTACHY_IRCHECK=1`, require compatible tag evidence for every reachable
  `dyn.payload` read, including class and container reads, using the compiler's
  separate analysis and emitted descriptor tables.
  [#1233](https://github.com/den-run-ai/pystachy/pull/1233)
- Check that the documented boundary inventory covers every dynamic-`Any`
  opt-in in `lib/` and `ports/`, rejecting missing, duplicate and stale rows.
  Reviewers still assess whether each open boundary is justified.
  [#1223](https://github.com/den-run-ai/pystachy/pull/1223)

The Lean theorem establishes payload-tag safety in the normalized model.
Snapshot fidelity, the Python bridge, descriptor correspondence, runtime
layouts, object lifetime, identity, GC and LLVM lowering remain trusted or
outside the proof. The compiler's independent verifier is not itself proved
by Lean. The Pystachy-specific model and proofs remain MIT-licensed, with no
copied CPython-formalization implementation or new external Lake packages.
Lean 4.35.0 is an external development tool with its own license, not a runtime
or installation dependency. Dynamic `Any` and promoting integers remain
experimental opt-ins; broader containment
[#1210](https://github.com/den-run-ai/pystachy/issues/1210) remains open.
[Proof scope and provenance](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.4/tools/lean_boundary/README.md)

## Compiler optimization and sanitizer coverage

- Keep eligible private `dict.get()` scalar results in presence/payload slots,
  preserving one key evaluation, callback exceptions and the value snapshot
  before later mutation. Escaping values, copies, non-`None` defaults,
  generators, dynamic-`Any` and promoting-integer programs retain the existing
  boxed path. This is a bounded allocation optimization, not a new identity
  policy. [#1220](https://github.com/den-run-ai/pystachy/pull/1220)
- `PYSTACHY_CFLAGS=-fsanitize=address` now instruments generated AOT and
  extension functions separately before linking their already-instrumented
  runtime. Constructor handling preserves independently sanitized native
  objects in either link order. Retained frontend IR remains uninstrumented;
  JIT instrumentation still covers the runtime only, and managed allocator
  arenas do not provide individual object redzones. Use the documented
  `ASAN_OPTIONS=detect_stack_use_after_return=0` setting.
  [#1221](https://github.com/den-run-ai/pystachy/pull/1221),
  [sanitizer limits](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.4/docs/internals.md)

These two implementations are original Pystachy work informed by PyJS design
ideas; no PyJS code or tests were copied. Historical workload measurements
retain their original compiler, toolchain and input limits. No release-wide
performance improvement is claimed.

## Contribution policy

Contribution rights and AI-assistance acknowledgment now follow a simpler,
LLVM-inspired process. Original Pystachy code remains MIT-licensed, third-party
notices remain required, and contributions still require review and passing
checks. A non-blocking bot reminder replaces the custom DCO registry and
certification requirement.
[#1235](https://github.com/den-run-ai/pystachy/pull/1235)

## Platforms and known limits

The distribution policy is unchanged:

| Native archive | Requirements |
|---|---|
| Linux x86-64 | Ubuntu 24.04 or compatible glibc 2.39+ Linux; LLVM 18 |
| Linux AArch64 | Little-endian ARM64, Ubuntu 24.04 or compatible glibc 2.39+ Linux; LLVM 18 |
| macOS arm64 | Apple Silicon, macOS 15+, Xcode Command Line Tools; LLVM 20 |
| macOS x86-64 | Intel, macOS 15+, Xcode Command Line Tools; LLVM 20 |

Docker targets Linux amd64/arm64 and includes LLVM 18. Native archives and Docker
run the compiler without Python. Source/hosted installation requires Python
3.11+; recordings and full verification use pinned CPython 3.13.16. Full
verification runs on Linux x86-64 and ARM64; macOS retains narrower installation
and release-consumer coverage, with Intel macOS a secondary target. Explicit
LLVM selections retain the prior release's validation limits.
[Installation policy](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.4/docs/install.md),
[inherited LLVM limits](https://github.com/den-run-ai/pystachy/blob/070c8137edeb610e11d8d81653e506ad64a9ce6d/docs/releases/v0.4.0-alpha.2.md#known-issues-and-experimental-scope)

- Closed standard streams retain documented differences in direct access and
  `print()`. When stdin is open but not readable, `input()` reports `EOFError`
  instead of CPython's `OSError`.
  [#1182](https://github.com/den-run-ai/pystachy/issues/1182)
- Manually enabling promoting integers in `lib/_pystachy_bytescan.py` retains
  its configuration-specific LLVM/verifier gap. Shipped fixed-width helper
  parameters avoid it for normal opted-in callers.
  [#1207](https://github.com/den-run-ai/pystachy/issues/1207)
- PGO, native compiler wheels, broader numeric-value module policy, libuv I/O
  and restricted numerical-worker drafts remain deferred pending independent
  review and combined supported-platform qualification. General shared-heap
  threading and distributed execution remain outside this release.
  [Release tracker](https://github.com/den-run-ai/pystachy/issues/1186)
- CI retains the 20-job PR budget, two workers per group, 15-minute job limit
  and 600-second GC self-compilation bound. Headroom work remains tracked in
  [#1178](https://github.com/den-run-ai/pystachy/issues/1178),
  [#1179](https://github.com/den-run-ai/pystachy/issues/1179) and
  [#1181](https://github.com/den-run-ai/pystachy/issues/1181).

Pystachy v0.4.0-alpha.4 fixes two correctness bugs, adds a native runner for a bounded
pytest dialect, extends dynamic payload verification, avoids boxing private scalar
`dict.get()` results and extends AddressSanitizer to generated code. Pystachy is an
experimental compiler for a typed subset of Python.

## Fixes

- A dynamic `Any` key whose `__hash__` or `__eq__` mutated another dictionary could crash
  an optimized lookup instead of raising `KeyError`, a crash alpha.3 already had.
  Operations that may run user code, including error formatting, now invalidate those
  lookups.
  [#1236](https://github.com/den-run-ai/pystachy/pull/1236)
- Exceptions keep their identity through optional fields, locals and parameters, in both
  operand orders, across repeated catches and against `None`, fixing the issue disclosed
  for alpha.3.
  [#1231](https://github.com/den-run-ai/pystachy/issues/1231)

## Native pytest runner

A hosted collector turns pytest-style tests into typed programs for CPython, native JIT or
native AOT. Its dialect covers static parametrization with `pytest.param` IDs and marks,
module-defined function-scoped fixtures and their aliases, teardown, `raises`, skips and
expected failures. Selected `unittest` methods can also be exported to it.
[#1232](https://github.com/den-run-ai/pystachy/pull/1232),
[runner contract](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.4/docs/pytest-native.md)

By default, the runner also runs the original tests under the pinned development pytest
and compares collected IDs, order and outcomes, catching behavior hidden in imported
objects such as autouse fixtures; `--no-compare` runs are labelled unverified. Imported
test classes fail collection. The runner is a source-checkout development tool.

Shared pytest checks now cover 19 examples and all 25 delivered pyperformance workloads
with 172 cases. Upstream qualification passes 53 unchanged JSON-repair cases and 16
selected `unittest` methods from CPython's `fnmatch`, `textwrap` and `statistics` and
mypyc's `NameGenerator` in their original suite, adapted pytest, generated CPython, JIT
and AOT, excluding two known `statistics` compiler gaps. Neither pytest itself nor complete
mypy, mypyc or CPython suites are compiled.
[#1238](https://github.com/den-run-ai/pystachy/pull/1238),
[#1240](https://github.com/den-run-ai/pystachy/pull/1240),
[examples](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.4/examples/pytest_native/README.md),
[mypyc scope](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.4/examples/pytest_native_mypyc/README.md),
[selection details](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.4/tests/upstream/pytest/README.md)

## Dynamic payload verification

- With `PYSTACHY_IRCHECK=1`, the IR verifier requires compatible tag evidence for every
  reachable `dyn.payload` read, including class and container reads.
  [#1233](https://github.com/den-run-ai/pystachy/pull/1233)
- The optional Lean bridge now models real typed-IR control flow, private storage, calls,
  exception edges, guards and class, integer, bool and container payloads, and tells
  assignment flags from identity companions (#1230). Lean now checks every payload read
  in test programs that opt in to dynamic `Any`, directly or through imports.
  [#1224](https://github.com/den-run-ai/pystachy/pull/1224),
  [#1226](https://github.com/den-run-ai/pystachy/pull/1226),
  [#1228](https://github.com/den-run-ai/pystachy/pull/1228),
  [#1234](https://github.com/den-run-ai/pystachy/pull/1234)

The Lean theorem proves payload-tag safety in the normalized model. Snapshot fidelity, the
Python bridge, descriptor correspondence, runtime layouts, lifetime, identity, GC, LLVM
lowering and the compiler's own verifier are trusted or outside the proof. Lean 4.35.0 is a
development tool, not a runtime or installation dependency. The MIT-licensed models copy
no CPython formalization and add no external Lake packages.
[Proof scope and provenance](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.4/tools/lean_boundary/README.md)

## Optimization and sanitizer coverage

- Private `dict.get()` lookups with scalar results no longer allocate a box. Escaping
  values, copies, non-`None` defaults, generators and programs using dynamic `Any` or
  promoting integers keep the boxed path. [#1220](https://github.com/den-run-ai/pystachy/pull/1220)
- `PYSTACHY_CFLAGS=-fsanitize=address` now also instruments generated AOT and extension
  functions, in either link order with the instrumented runtime. JIT
  instrumentation still covers only the runtime, retained frontend IR stays
  uninstrumented, and managed allocator arenas have no per-object redzones. Use
  `ASAN_OPTIONS=detect_stack_use_after_return=0`.
  [#1221](https://github.com/den-run-ai/pystachy/pull/1221),
  [sanitizer limits](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.4/docs/internals.md)

Both are original Pystachy work informed by PyJS design ideas; no PyJS code or tests were
copied.

## Known limits

- Dynamic `Any` and promoting integers remain experimental opt-ins; containment work
  continues in [#1210](https://github.com/den-run-ai/pystachy/issues/1210).
- Closed standard streams differ from CPython in direct access and `print()`, and
  `input()` raises `EOFError` instead of `OSError` when stdin is open but not readable
  ([#1182](https://github.com/den-run-ai/pystachy/issues/1182)).
- Manually enabling promoting integers in `lib/_pystachy_bytescan.py` hits an LLVM and
  verifier gap that the shipped fixed-width helper avoids for normal callers
  ([#1207](https://github.com/den-run-ai/pystachy/issues/1207)).
- PGO, native compiler wheels, broader numeric-value module policy, libuv I/O and
  numerical-worker drafts are deferred, and general shared-heap threading and distributed
  execution are outside this release.
  [Release tracker](https://github.com/den-run-ai/pystachy/issues/1186)

## Platforms

| Native archive | Requirements |
|---|---|
| Linux x86-64 | Ubuntu 24.04 or compatible glibc 2.39+ Linux; LLVM 18 |
| Linux AArch64 | Little-endian ARM64, Ubuntu 24.04 or compatible glibc 2.39+ Linux; LLVM 18 |
| macOS arm64 | Apple Silicon, macOS 15+, Xcode Command Line Tools; LLVM 20 |
| macOS x86-64 | Intel, macOS 15+, Xcode Command Line Tools; LLVM 20 |

Native archives and the Docker image run the compiler without Python; a source or hosted
installation needs Python 3.11+. Full verification runs on Linux x86-64 and ARM64 with
CPython 3.13.16. macOS has narrower installation and release coverage, and Intel macOS is
a secondary target. Other explicitly selected LLVM versions keep their
[earlier validation limits](https://github.com/den-run-ai/pystachy/blob/070c8137edeb610e11d8d81653e506ad64a9ce6d/docs/releases/v0.4.0-alpha.2.md#known-issues-and-experimental-scope).

Pystachy v0.4.0-alpha.2 fixes cache invalidation, iteration, import and JIT bugs, adds an
LLJIT runner and LLVM 19–23 support on Linux, and expands bounded library support.
Pystachy is an experimental compiler for a typed subset of Python.

## Fixes

- Native Linux program-cache keys now include source-line metadata and C-runtime caching
  settings and tell unset from empty values, so cached launches keep their validation
  errors. Older cache entries are not reused.
  [#1171](https://github.com/den-run-ai/pystachy/pull/1171)
- `zip()` over dynamic `Any` iterators takes items left to right, even when a later
  `__next__` mutates an earlier container; comprehensions, `list()`, `sum()` and `map()`
  share the fix. [#1172](https://github.com/den-run-ai/pystachy/pull/1172)
- Imports accept only directories as namespace-package portions and skip non-regular
  `.py` and `__init__.py` candidates, such as directories and FIFOs, but still accept
  symlinks to regular files. Cache validation notices a candidate changing between file
  and directory.
  [#1173](https://github.com/den-run-ai/pystachy/pull/1173),
  [#1187](https://github.com/den-run-ai/pystachy/pull/1187)
- `input()` raises CPython's lost-stream errors in CPython's order for a standard stream
  closed at startup, even after its file descriptor is reused.
  [#1174](https://github.com/den-run-ai/pystachy/pull/1174)
- JIT launches close their input descriptors before user code runs and keep deliberately
  closed standard streams and inherited signals. ORC replaces the last MCJIT path,
  removing the leftover jitdump descriptor tracked in #1167.
  [#1176](https://github.com/den-run-ai/pystachy/pull/1176),
  [#1189](https://github.com/den-run-ai/pystachy/pull/1189)
- Exception handlers no longer see stale or unset values under `PYSTACHY_JIT_CODEGEN=0`.
  [#1188](https://github.com/den-run-ai/pystachy/pull/1188)
- Invalid JIT inlining settings fail before cache locks or temporary launch files are
  created, and the compiler ignores a stray inherited `PYSTACHY_ARGV0`.
  [#1187](https://github.com/den-run-ai/pystachy/pull/1187)

## JIT runner

On supported Linux toolchains, JIT programs run in a cached, self-checked LLJIT runner
that honors the selected code-generation level without installing LLVM's signal handlers.
macOS, unsupported or unusable toolchains and `PYSTACHY_JIT_LAUNCHER=lli` use the `lli`
fallback.
[#1192](https://github.com/den-run-ai/pystachy/pull/1192)

## Language and library support

- Scalar arithmetic on conditional and boolean operands compiles where the surrounding
  closed union cannot support the operation. Speculative conversion of mixed fixed-width
  and promoting integers in `or` and `and`, including `dict.get()` defaults, is fixed.
  [#1199](https://github.com/den-run-ai/pystachy/pull/1199),
  [#1202](https://github.com/den-run-ai/pystachy/pull/1202)
- Generic class constructors, including `collections.Counter`, bind `Iterable[T]` from
  generator arguments. [#1203](https://github.com/den-run-ai/pystachy/pull/1203)
- `min()` and `max()` of one iterable accept `default=`, also with `key=`. A typed default
  must match the item type or be `None`; dynamic results accept other boxed defaults.
  Inputs other than lists and dynamic values are materialized as documented.
  [#1204](https://github.com/den-run-ai/pystachy/pull/1204)
- `os.path` gains string-path `basename`, `dirname`, `split`, `splitext`, `isabs`,
  `normpath`, `abspath`, `relpath`, `expanduser` and `commonprefix`, plus path constants.
  `bytes` paths, `commonpath` and `expandvars` are unsupported.
  [#1200](https://github.com/den-run-ai/pystachy/pull/1200)
- `os.makedirs()` accepts `exist_ok=`, and `os.environ` supports reads, writes, deletion,
  membership and `get()`; invalid deletions fail in CPython's order. Iterating
  `os.environ` or passing it as a value is unsupported. [#1205](https://github.com/den-run-ai/pystachy/pull/1205)
- Typed `bytes.decode()` and `str.encode()` calls accept `encoding` and `errors` keywords
  in parameter order; other orders and the dynamic `Any` path keep their limits.
  [#1194](https://github.com/den-run-ai/pystachy/pull/1194)
- String equality and searches of integer, boolean and string lists skip generic
  descriptor walks; other lists keep the general comparison path.
  [#1201](https://github.com/den-run-ai/pystachy/pull/1201)
- The adapted `json_repair` port follows upstream 0.64.8, and its schema-free corpus grows
  from 837 to 943 cases, replayed in native JIT and AOT. Schema and file APIs stay
  excluded, stray-slash recovery is a documented deviation, and older benchmark results
  reflect earlier upstream versions.
  [#1190](https://github.com/den-run-ai/pystachy/pull/1190),
  [#1191](https://github.com/den-run-ai/pystachy/pull/1191),
  [#1195](https://github.com/den-run-ai/pystachy/pull/1195)
- Small scanned lists are stored within their headers and the IR shares repeated
  temporaries, so compiler GC stress retains fewer objects.
  [#1193](https://github.com/den-run-ai/pystachy/pull/1193)
- The PyPI description uses absolute links, which follow `main`, so documentation and
  example links work outside GitHub.
  [#1170](https://github.com/den-run-ai/pystachy/pull/1170)

## LLVM toolchains

Explicitly selected Linux LLVM 19–23 toolchains are now accepted. LLVM 18 on Linux and
LLVM 20 on macOS remain the CI and distribution defaults.
[#1196](https://github.com/den-run-ai/pystachy/pull/1196)

On Linux x86-64, LLVM 23 passed bootstrap and full differential tests, and LLVM 20 and 22
passed bootstrap and selected tests. LLVM 19 and 21, and other LLVM versions on macOS, are
untested. Assertion-enabled LLVM 22 and 23
builds reject the generator intrinsic upgrade and are outside the verified configuration.

## Known limits

- Closed standard streams keep documented differences in direct access and `print()`, and
  `input()` raises `EOFError` instead of CPython's `OSError` when stdin is open but not
  readable. [#1182](https://github.com/den-run-ai/pystachy/issues/1182)
- Dynamic `Any` and promoting integers remain experimental opt-ins; the
  [compatibility guide](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.2/docs/language/compatibility.md)
  lists supported behavior and other limits.
- Native socket I/O, libuv I/O and restricted numerical workers remain separate
  experimental work, and general shared-heap threading and distributed execution are
  outside this release.

and [changes since alpha.1](https://github.com/den-run-ai/pystachy/compare/v0.4.0-alpha.1...v0.4.0-alpha.2).

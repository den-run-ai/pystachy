Pystachy v0.4.0-alpha.2 fixes compiler cache invalidation, iteration and import
behavior, and JIT launch cleanup. It includes the optional local tools introduced
in alpha.1. Pystachy remains an experimental compiler for a typed subset of Python.

## Correctness and launch behavior

- Include source-line metadata and C-runtime caching settings in native Linux
  program-cache identity. Distinguish unset and empty setting values so a cached
  launch preserves their validation errors. The new cache-identity format
  prevents reuse of prior entries.
  [#1171](https://github.com/den-run-ai/pystachy/pull/1171)
- Preserve left-to-right item retrieval in `zip()` loops with dynamic `Any`
  iterators. Prevent wrong results and crashes when a later `__next__` mutates
  an earlier list, dict or set input.
  Shared lowering also covers comprehensions, `list()`, `sum()` and `map()`.
  [#1172](https://github.com/den-run-ai/pystachy/pull/1172)
- Accept only directories as namespace-package portions. Extensionless files no
  longer suppress an `ImportError` fallback, and program-cache validation detects
  candidates changing between files and directories.
  [#1173](https://github.com/den-run-ai/pystachy/pull/1173)
- Ignore non-regular `.py` and `__init__.py` import candidates, including directories
  and FIFOs, while preserving symlinks to regular files and later search paths.
  The driver's `ffi.py` probes follow the same rule.
  [#1183](https://github.com/den-run-ai/pystachy/issues/1183)
- Match CPython's `input()` lost-stream errors when a standard stream was closed
  at startup, including error order before prompt conversion. Reusing its file
  descriptor later does not turn that stream into a valid input source.
  [#1174](https://github.com/den-run-ai/pystachy/pull/1174)
- Close the driver's JIT input descriptors before user code runs, preserve
  deliberately closed standard streams, and restore inherited signal
  dispositions after LLVM startup. Remove the private MCJIT dump directory;
  the remaining LLVM-owned descriptor is described below.
  [#1176](https://github.com/den-run-ai/pystachy/pull/1176)
- Reject invalid JIT inlining settings before acquiring cache locks or creating
  temporary launch files. Ignore a stray inherited `PYSTACHY_ARGV0` when starting
  the compiler, while retaining the compiled program's argument handoff.
  [#1184](https://github.com/den-run-ai/pystachy/issues/1184)

## Packaging and verification

- Use absolute repository links in the PyPI description so documentation and
  example links work outside GitHub. These links currently follow `main`.
  [#1170](https://github.com/den-run-ai/pystachy/pull/1170)
- Include existing cache, source-line and FFI-schema unit tests in hosted coverage
  measurement, and add differential cases for previously untested dynamic `Any`
  paths. Coverage measures execution; it does not establish correctness by itself.
  [#1175](https://github.com/den-run-ai/pystachy/pull/1175)
- Rebalance GC identity case weights after separating identity and JIT execution
  jobs. Preserve the complete corpus, stress intervals and execution partitions.
  [#1177](https://github.com/den-run-ai/pystachy/pull/1177)

## Known issues and experimental scope

- With LLVM perf support, opt-in `PYSTACHY_JIT_CODEGEN=0` (MCJIT) retains LLVM's
  own close-on-exec jitdump descriptor until process exit. It remains visible to
  the running program and is closed across `exec`; full descriptor-table parity
  remains tracked in [#1167](https://github.com/den-run-ai/pystachy/issues/1167).
- Closed standard streams still have documented differences in direct stream
  access and `print()`. Separately, `input()` reports `EOFError` instead of
  CPython's `OSError` when stdin is open but not readable
  ([#1182](https://github.com/den-run-ai/pystachy/issues/1182)). Dynamic `Any` and
  promoting integers remain experimental opt-ins. Consult the
  [compatibility guide](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.2/docs/language/compatibility.md)
  for supported behavior and other limitations.
- Optional native/socket I/O, libuv I/O and restricted numerical-worker stacks
  remain separate experimental work. This release adds no general shared-heap
  threading or distributed execution.
- CI capacity remains under investigation in
  [#1178](https://github.com/den-run-ai/pystachy/issues/1178),
  [#1179](https://github.com/den-run-ai/pystachy/issues/1179) and
  [#1181](https://github.com/den-run-ai/pystachy/issues/1181). PR limits remain
  20 jobs, two workers per group and 15 minutes per job; the `gc-self` stress
  interval and ten-minute bound are unchanged. No release-wide performance
  improvement is claimed.

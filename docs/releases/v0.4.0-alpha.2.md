Pystachy v0.4.0-alpha.2 fixes compiler cache invalidation, iteration, imports
and JIT execution. It expands bounded library support and reduces selected
compiler and runtime costs. It includes the optional local tools introduced in
alpha.1. Pystachy remains an experimental compiler for a typed subset of Python.

## Correctness and launch behavior

- Include source-line metadata and C-runtime caching settings in native Linux
  program-cache identity. Distinguish unset and empty setting values so a cached
  launch preserves their validation errors. The new cache-identity format
  prevents reuse of prior entries.
  [#1171](https://github.com/den-run-ai/pystachy/pull/1171)
- Preserve left-to-right item retrieval in `zip()` loops with dynamic `Any`
  iterators, including when a later `__next__` mutates an earlier container.
  Shared lowering also covers comprehensions, `list()`, `sum()` and `map()`.
  [#1172](https://github.com/den-run-ai/pystachy/pull/1172)
- Accept only directories as namespace-package portions. Ignore non-regular
  `.py` and `__init__.py` candidates, including directories and FIFOs, while
  preserving symlinks to regular files and later search paths. Cache validation
  detects candidates changing between files and directories.
  [#1173](https://github.com/den-run-ai/pystachy/pull/1173),
  [#1187](https://github.com/den-run-ai/pystachy/pull/1187)
- Match CPython's `input()` lost-stream errors when a standard stream was closed
  at startup, including error order before prompt conversion. Reusing its file
  descriptor later does not turn that stream into a valid input source.
  [#1174](https://github.com/den-run-ai/pystachy/pull/1174)
- Close JIT input descriptors before user code runs and preserve deliberately
  closed standard streams and inherited signals. Replace the remaining MCJIT
  path with ORC, removing the residual jitdump descriptor tracked in #1167.
  [#1176](https://github.com/den-run-ai/pystachy/pull/1176),
  [#1189](https://github.com/den-run-ai/pystachy/pull/1189)
- Fix stale or unset values in exception handlers under
  `PYSTACHY_JIT_CODEGEN=0` by splitting critical edges before code generation.
  [#1188](https://github.com/den-run-ai/pystachy/pull/1188)
- On supported Linux toolchains, build and cache a self-checked LLJIT runner
  that honors the selected code-generation level without installing LLVM's
  signal handlers. macOS, unsupported or unusable toolchains, and
  `PYSTACHY_JIT_LAUNCHER=lli` use the `lli` fallback; with codegen 0 that fallback
  links an `llc -O0` object through ORC.
  [#1192](https://github.com/den-run-ai/pystachy/pull/1192)
- Reject invalid JIT inlining settings before acquiring cache locks or creating
  temporary launch files. Ignore a stray inherited `PYSTACHY_ARGV0` when starting
  the compiler while retaining the compiled program's explicit argument handoff.
  [#1187](https://github.com/den-run-ai/pystachy/pull/1187)

## Type inference and builtin APIs

- Accept scalar arithmetic on conditional and boolean operands where the
  surrounding closed union cannot support that operation. Preserve existing
  accepted-program behavior for supported union operations and dynamic `Any`
  operands. Also fix speculative conversion of mixed fixed-width and promoting
  integers in `or`/`and`, including `dict.get()` defaults.
  [#1199](https://github.com/den-run-ai/pystachy/pull/1199),
  [#1202](https://github.com/den-run-ai/pystachy/pull/1202)
- Bind `Iterable[T]` from generator arguments to generic class constructors,
  including `collections.Counter`.
  [#1203](https://github.com/den-run-ai/pystachy/pull/1203)
- Accept `default=` for the single-iterable form of `min()` and `max()`, also
  with `key=`. Typed defaults must match the item type or be `None`; dynamic
  results also accept other boxed defaults. Lists and dynamic inputs stay live
  while keys or comparisons run. Other inputs retain the documented
  materialization behavior, without requesting an object's length hint.
  [#1204](https://github.com/den-run-ai/pystachy/pull/1204)
- Add string-path builtins for `os.path.basename`, `dirname`, `split`, `splitext`,
  `isabs`, `normpath`, `abspath`, `relpath`, `expanduser` and `commonprefix`, plus
  path constants. `bytes` paths, `commonpath` and `expandvars` remain unsupported.
  [#1200](https://github.com/den-run-ai/pystachy/pull/1200)
- Add `os.makedirs()` with `exist_ok=` and process-environment reads, writes,
  deletion, membership and `get()` through `os.environ`. Invalid deletions
  preserve CPython's error ordering; overflowing directory modes raise before
  creating the leaf while preserving parent-creation behavior. Iterating or passing the environment
  mapping as a value remains unsupported.
  [#1205](https://github.com/den-run-ai/pystachy/pull/1205)
- Avoid generic descriptor walks for string equality and eligible list searches
  over integers, booleans and strings. Deterministic probes verify use of these
  fast paths; other list representations retain the general comparison path.
  [#1201](https://github.com/den-run-ai/pystachy/pull/1201)

## Libraries, compiler costs and toolchains

- Accept `encoding` and `errors` keywords in parameter order for typed
  `bytes.decode()` and `str.encode()` calls. Other keyword ordering and the
  dynamic `Any` path retain their existing limits.
  [#1194](https://github.com/den-run-ai/pystachy/pull/1194)
- Update the adapted `json_repair` port to upstream 0.64.8 and expand its recorded
  schema-free corpus from 837 to 943 cases. Schema and file APIs remain excluded;
  the port's stray-slash recovery is documented as a deviation. Older benchmark
  results remain tied to their measured upstream versions.
  [#1190](https://github.com/den-run-ai/pystachy/pull/1190),
  [#1195](https://github.com/den-run-ai/pystachy/pull/1195)
- Reduce objects retained during compiler GC stress by storing small scanned
  lists within their headers and sharing repeated IR temporary structures.
  The stress interval and ten-minute limit are unchanged; the broader scaling
  work in #1181 remains open.
  [#1193](https://github.com/den-run-ai/pystachy/pull/1193)
- Accept explicitly selected Linux LLVM 19–23 toolchains while retaining LLVM 18
  on Linux and LLVM 20 on macOS as the CI and distribution defaults. Generator
  IR, float literals, `fmod` behavior and allocator inlining are adjusted for
  these versions. Validation depth and assertion-build limits are described
  below.
  [#1196](https://github.com/den-run-ai/pystachy/pull/1196)

## Packaging and verification

- Use absolute repository links in the PyPI description so documentation and
  example links work outside GitHub. These links currently follow `main`.
  [#1170](https://github.com/den-run-ai/pystachy/pull/1170)
- Include existing cache, source-line and FFI-schema unit tests in hosted
  coverage measurement and add differential cases for previously untested
  dynamic `Any` paths. Coverage measures execution, not correctness by itself.
  [#1175](https://github.com/den-run-ai/pystachy/pull/1175)
- Require native JIT and AOT replay of the JSON repair corpus in verification.
  The CPython-extension replay explicitly reports interpreter-dependent skips,
  which the FFI gate rejects rather than silently omitting the work.
  [#1191](https://github.com/den-run-ai/pystachy/pull/1191)
- Rebalance GC identity weights and move the PR program-cache probe to the
  first JIT/variants worker. Preserve every required case, mode, stress interval
  and aggregate check; full runs retain both runtime-cache probes.
  [#1177](https://github.com/den-run-ai/pystachy/pull/1177),
  [#1197](https://github.com/den-run-ai/pystachy/pull/1197)

## Known issues and experimental scope

- Closed standard streams retain documented differences in direct stream
  access and `print()`. Separately, `input()` reports `EOFError` instead of
  CPython's `OSError` when stdin is open but not readable.
  [#1182](https://github.com/den-run-ai/pystachy/issues/1182)
- Dynamic `Any` and promoting integers remain experimental opt-ins. Consult the
  [compatibility guide](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.2/docs/language/compatibility.md)
  for supported behavior and other limitations.
- Additional LLVM validation is Linux x86-64 evidence: LLVM 23 passed bootstrap
  and full differential tests; LLVM 20 and 22 passed bootstrap and selected
  tests. LLVM 19 and 21, and other LLVM versions on macOS, remain untested.
  Assertion-enabled LLVM 22/23 builds reject the generator intrinsic upgrade;
  those builds are outside the verified configuration.
- Optional native/socket I/O, libuv I/O and restricted numerical-worker stacks
  remain separate experimental work for conditional alpha.3 qualification.
  General shared-heap threading and distributed execution remain outside this
  release; broader research drafts are not included.
- CI headroom remains tracked in
  [#1178](https://github.com/den-run-ai/pystachy/issues/1178),
  [#1179](https://github.com/den-run-ai/pystachy/issues/1179) and
  [#1181](https://github.com/den-run-ai/pystachy/issues/1181). PR limits remain
  20 jobs, two workers per group and 15 minutes per job. No release-wide
  performance improvement is claimed.

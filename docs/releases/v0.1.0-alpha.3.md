Pystachy compiles a subset of Python to native code through LLVM: `pystachy run` for JIT
execution and `pystachy build` for standalone executables. This third alpha extends the
experimental dynamic `Any` implementation, adds `tomllib.loads()` and more JSON operations,
and strengthens compiler/runtime checks and performance monitoring since
[v0.1.0-alpha.2](https://github.com/den-run-ai/pystachy/releases/tag/v0.1.0-alpha.2).

**Pystachy remains experimental. Dynamic `Any` remains experimental and opt-in.** Its remaining
silent semantic differences are listed below; this release does not establish a stable dynamic
contract or enable dynamic `Any` by default. Most PyPI packages do not compile unchanged.

## Highlights

- **TOML parsing.** Adapted CPython 3.13.16 `tomllib.loads()` compiles with dynamic `Any`,
  including tables, arrays, datetimes, `parse_float` and `TOMLDecodeError` (#794, #795).
  `types.MappingProxyType` supplies a read-only live dict view. Binary-file `tomllib.load()`
  remains unsupported; see the
  [library scope](https://github.com/den-run-ai/pystachy/blob/v0.1.0-alpha.3/lib/compatibility.md#tomllib).
- **Dynamic containers and calls.** Compatible containers such as `dict[str, Any]` and
  `list[dict[str, Any]]` share mutable storage with `Any` aliases (#821, #829, #830).
  Dynamic function/method calls accept supported keyword and statically unpacked arguments
  (#826); dict union and in-place union preserve their documented mutation behavior (#833).
  `abs()` accepts dynamic values and dispatches supported `__abs__` methods (#863).
- **JSON through dynamic storage.** `json.loads()` can return dynamic containers without
  copying their aliases. `json.dumps()` of `Any` values supports tuples, numeric/boolean/null
  keys, `skipkeys`, `check_circular` and a `default` callback (#823). Callback-driven dict traversal
  deviations are explicitly retained (#839). The ordinary typed `JSONValue` API retains its
  narrower contract; both modes retain the prototype's integer and nesting limits. See
  [JSON scope](https://github.com/den-run-ai/pystachy/blob/v0.1.0-alpha.3/docs/json-prototype.md).
- **Comparison correctness.** Cross-type comparison bodies with concrete operand annotations,
  supported structural fields and missing-field reads now execute their effects and first
  exceptions (#865, #867, #870). Direct equality/inequality between supported differently typed
  builtin fields uses each operand's own layout (#875). Unsupported bodies can still fall back
  without executing the method; the known-issues table describes this remaining gap.
- **Numeric identity.** Fixes preserve object provenance across supported copies, global reads,
  conditional/assignment expressions, closure cells and comprehensions (#807, #859, #864,
  #868, #871). Known-dynamic displays capture same-typed numeric binding identities before
  later items rebind them, including duplicate NaN keys/items (#874). Remaining typed-boundary
  and display cases are documented; numeric equality is not a substitute for identity.
- **More compatibility coverage.** `difflib.context_diff()` now compiles. Six additional
  CPython-derived differential programs cover JSON, heterogeneous dicts, deque effects and
  context-diff formatting. The maintained pyperformance adaptations grow from 18 to 22 with
  comprehensions, generators, JSON encoding and decoding (#876). These are adapted programs,
  not the official pyperformance harness or the complete CPython test suite.

## Compatibility removals

The unused VM-facing `opcode`/`_opcode`, `_ast` and `_imp` prototypes have been removed,
as have the constrained `pyaes` and `pyfiglet` demonstration ports (#846). These capabilities
were present in alpha.2 and are not native compatibility guarantees in alpha.3. The maintained
third-party port list now contains 13 packages. Programs using those removed modules should
run that portion under CPython, through the explicit
[CPython bridge](https://github.com/den-run-ai/pystachy/blob/v0.1.0-alpha.3/docs/ffi.md#calling-cpython-libpyobjpy)
where its conversion contract fits, or remain on alpha.2 pending migration. Installing an
upstream package does not make it compile natively.

## Compiler and runtime reliability

- Reset source-module policy between hosted compilations and inventory module-container
  ownership/writers, including annotation-only declarations (#818, #845, #849, #856).
  Broader speculative-state isolation remains tracked in
  [#767](https://github.com/den-run-ai/pystachy/issues/767).
- Verify typed-IR union payload proofs and named string ABI/layout boundaries, plus GC-root
  reachability (#840, #842, #843). These checks supplement native execution and collector stress.
  Nullable-string read checks and builder ownership remain manual, with automated enforcement
  tracked in [#25](https://github.com/den-run-ai/pystachy/issues/25).
- AddressSanitizer now instruments generated `runtime.py` memory accesses as well as the C
  runtime (#860). Per-managed-object bounds and reclamation poisoning remain follow-up work
  in [#23](https://github.com/den-run-ai/pystachy/issues/23).
- Differential fuzzing, typed/dynamic parity in normal and GC-stressed JIT/AOT, and a corpus-wide
  opt-in sweep are maintained CI checks (#834, #844, #850). The opt-in sweep retains five exact
  expected rejection cases, and documented deviations are not CPython parity passes.

## Performance and monitoring

Paired CI smoke comparisons now cover text, numeric/ML kernels, JSON parsing and mixed-value
processing, numeric identity costs and cyclic graph copying. Weekly comparisons against a fixed reference
supplement adjacent-commit comparisons (#853, #855, #869). These are advisory checks; retained
memory and broader application acceptance remain open under
[#202](https://github.com/den-run-ai/pystachy/issues/202) and
[#780](https://github.com/den-run-ai/pystachy/issues/780). TOML application acceptance also
remains pending under [#108](https://github.com/den-run-ai/pystachy/issues/108) and those trackers.

The graph-processing regression introduced by compatible dynamic layouts was substantially
reduced by avoiding integer-query boxes on safe dictionary reads (#873). In the recorded
15-process interleaved experiment, processing CPU fell about 24% JIT and 20% AOT versus the
pre-fix revision. Residual median overhead versus the historical parent was about 13%/14%,
with uncertainty spanning the 20% alert threshold. Complete recovery is not established;
see [measurement provenance and remaining scope](https://github.com/den-run-ai/pystachy/issues/780).

Scalar arithmetic proofs avoid the earlier local/global numeric boxing regressions without
removing observable snapshots (#864, #866). Literal-string membership also avoids temporary
lists (#851). None of these establishes a general JSON-repair or whole-application speedup.
The separate JSON-repair accumulator and bulk-scanning bottlenecks remain
[#861](https://github.com/den-run-ai/pystachy/issues/861) and
[#862](https://github.com/den-run-ai/pystachy/issues/862).

## Known issues and workarounds

| Area | Remaining behavior | Practical route |
|---|---|---|
| Dynamic cross-type comparisons ([#803](https://github.com/den-run-ai/pystachy/issues/803)) | Unsupported method bodies can be skipped, losing side effects, results or exceptions. Differing set/user-class field layouts, custom lookup and other unsupported body forms remain outside the bounded adapters. | Keep comparison-sensitive code in supported typed paths, or execute it through CPython. Verify method effects and first exceptions as well as the final boolean. |
| Numeric identity ([#858](https://github.com/den-run-ai/pystachy/issues/858)) | Identity can change across typed parameters/defaults/returns, typed-container items, fields and folded constants. Displays that discover dynamic storage late, or retype a numeric local between int and float, retain deviations. | Keep identity-sensitive values in dynamic storage from creation where supported, avoid those typed crossings, or use CPython. Do not replace identity with equality for NaNs or identity-keyed algorithms. |
| Five opt-in corpus exceptions ([#773](https://github.com/den-run-ai/pystachy/issues/773), [#777](https://github.com/den-run-ai/pystachy/issues/777), [#782](https://github.com/den-run-ai/pystachy/issues/782)) | Nested generator yield channels, two typed-list crossings and two template-return contexts reject programs accepted without the opt-in. The [manifest](https://github.com/den-run-ai/pystachy/blob/v0.1.0-alpha.3/tools/dynany_optin_exceptions.json) pins every case/mode/diagnostic. | Keep affected modules on inference-only `Any`. For dynamic containers, declare compatible `list[Any]`/dict storage from the start. Copy explicitly only when losing alias sharing is acceptable. |
| Dynamic protocols and calls ([#773](https://github.com/den-run-ai/pystachy/issues/773), [#774](https://github.com/den-run-ai/pystachy/issues/774), [#775](https://github.com/den-run-ai/pystachy/issues/775)) | User objects are not iterable through `Any`; some builtins, runtime argument unpacking and callable values remain unsupported. Sets, bytes and exception objects cannot become `Any` values. | Narrow to a supported concrete type before the operation or keep that operation in typed code. Use documented argument shapes and an explicit `dict.setdefault(key, default)`. |
| JSON mutation and limits | Unsorted dynamic encoding can traverse delete/reinsert or clear/repopulate mutations differently from CPython. Integers are signed 64-bit; codec depth is limited to 256 containers. File APIs, indentation and decoding hooks remain unsupported. | Keep dict structure stable during callbacks, use supported text APIs, and validate size/depth. Use CPython for semantics or APIs outside the documented prototype. |
| Integer/text compatibility | General integers are checked signed 64-bit values; Unicode case mapping is incomplete, and text/file-position deviations remain. | Keep arithmetic in range, run the Unicode porting audit for byte-oriented assumptions, or use CPython through the explicit bridge where needed. |
| Platform coverage ([#708](https://github.com/den-run-ai/pystachy/issues/708)) | Full differential verification uses LLVM 18 on Linux. macOS LLVM 20 receives installation/package JIT/AOT/GC smoke coverage rather than the full Linux corpus. | Use the documented platform toolchain and verify your application on its deployment target. |

Multiple inheritance, native `async`/`await`, `match`, `bytearray` and binary filesystem I/O
remain unsupported. The full
[compatibility reference](https://github.com/den-run-ai/pystachy/blob/v0.1.0-alpha.3/docs/language/compatibility.md),
[dynamic deviations](https://github.com/den-run-ai/pystachy/blob/v0.1.0-alpha.3/docs/dynamic-any.md#deviations)
and [library guide](https://github.com/den-run-ai/pystachy/blob/v0.1.0-alpha.3/lib/README.md)
define the supported scope. Unsupported programs are not always rejected at compile time.

## Verification and packages

The release process requires CI, Installation, Lint and Packages on the exact source commit.
Compiler and runtime bootstraps must reach byte-identical fixed points. Native archives are
rebuilt and smoke-tested on Linux x86-64, macOS arm64 and macOS x86-64; Docker is Linux amd64.
Archive tests check relocation, read-only resources, external caching, normal/GC JIT and AOT,
JSON/Unicode output and warm runtime-cache reuse (including the Linux shared library). Publication records the source commit and
checksums. The release tracker links the final evidence:
[#877](https://github.com/den-run-ai/pystachy/issues/877).

## Install

Native compiler archives require LLVM 18 on Linux x86-64 (glibc 2.39+, such as Ubuntu 24.04),
or LLVM 20 on macOS 15+ with the Xcode Command Line Tools. Built ordinary executables need
neither Python nor LLVM. The CPython bridge remains an explicit runtime dependency when used.

```sh
# Linux x86-64. On macOS use its archive and shasum -a 256 -c.
sudo apt install clang-18 llvm-18 llvm-18-runtime
base=https://github.com/den-run-ai/pystachy/releases/download/v0.1.0-alpha.3
curl -LO "$base/pystachy-v0.1.0-alpha.3-linux-x86_64.tar.gz"
curl -LO "$base/pystachy-v0.1.0-alpha.3-linux-x86_64.tar.gz.sha256"
sha256sum -c pystachy-v0.1.0-alpha.3-linux-x86_64.tar.gz.sha256
tar -xzf pystachy-v0.1.0-alpha.3-linux-x86_64.tar.gz
pystachy-v0.1.0-alpha.3-linux-x86_64/bin/pystachy --version
```

The Docker image includes LLVM 18:

```sh
docker run --rm dta67/pystachy:v0.1.0-alpha.3 --version
docker run --rm --user "$(id -u):$(id -g)" -v "$PWD:/work" dta67/pystachy:v0.1.0-alpha.3 run demo.py
```

Prereleases do not update `latest`. See the
[installation guide](https://github.com/den-run-ai/pystachy/blob/v0.1.0-alpha.3/docs/install.md)
for PATH setup, Docker on macOS and source builds.

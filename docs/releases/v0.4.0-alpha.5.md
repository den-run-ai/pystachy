Pystachy v0.4.0-alpha.5 improves first-use LLVM downloads, adds Lean checks for
unchecked container accesses, and ships a reproducible native pytest benchmark
harness. Compiler, runtime and library sources are unchanged from alpha.4.
Pystachy remains an experimental compiler for a typed subset of Python.

## Installation reliability

Ubuntu 24.04 source installations can recover from a temporary failure of the
dated Ubuntu snapshot service by trying the official archive for their CPU
architecture. Both sources must provide the same pinned LLVM 18.1.3 package
bytes, verified by SHA-256 before extraction. Retryable failures include selected
HTTP errors, timeouts and temporary DNS resolution failures; checksum,
certificate, permanent DNS and local file errors still stop installation.

The download retains its three-attempt budget per package and reports the failed
URL when recovery is exhausted. Existing caches, explicit `PYSTACHY_LLVM`
selection and macOS download sources are unchanged.
[#1255](https://github.com/den-run-ai/pystachy/pull/1255),
[installation](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.5/docs/install.md)

## Unchecked-access verification

The optional Lean tooling now checks unchecked list reads and dictionary/set
entry accesses in completed typed-IR snapshots. It requires evidence that a
list index is in bounds and a reused entry is still live, including paths across
calls, mutations and exception edges. The adapter accounts for negated guards,
conditional reads, set deletion and source-entry reads inside equality lookups.
The dynamic-`Any` corpus gate records access results separately from its existing
payload-tag results.
[#1241](https://github.com/den-run-ai/pystachy/pull/1241),
[access model and coverage](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.5/tools/lean_boundary/ACCESS.md)

The theorem proves safety in the normalized model when its certificate checker
accepts. Snapshot fidelity, Python normalization, runtime contracts and effect
summaries remain trusted; source/LLVM equivalence, GC, allocation and broader
aliasing are outside this proof. The compiled checker also trusts the Lean
compiler, runtime and JSON front end. The historical broader corpus sweep is
labelled separately from the selected dynamic-`Any` corpus gate.

Lean 4.35.0 remains an external development tool, with no compiler-runtime or
user-installation dependency. The Pystachy models remain MIT-licensed and add no
external Lake packages. Ordinary differential, JIT/AOT and GC checks remain
required alongside these proofs.
[Trust and provenance](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.5/tools/lean_boundary/README.md)

## Native pytest benchmark

The benchmark compares ordinary CPython pytest, prepared generated CPython,
native JIT and prebuilt AOT across fixture-heavy tests, JSON repair and numeric
work. It also measures complete first-use, unchanged-rerun and edit/rebuild
commands with the independent pytest oracle enabled, with the compiler and LLVM
already installed. These timings exclude compiler installation and bootstrap.

Failed or interrupted runs invalidate prior reports. New reports retain exact
case and phase inventories, source identities and the actual selected LLVM
tool/library fingerprints. The included timing results remain historical
alpha.3 measurements with their recorded provenance limits; they are not
alpha.5 performance measurements. Prebuilt execution, preparation, compilation
and complete development-command costs remain distinct.
[#1242](https://github.com/den-run-ai/pystachy/pull/1242),
[benchmark and replay instructions](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.5/bench/pytest_native/README.md)

## Platforms and known limits

| Native archive | Requirements |
|---|---|
| Linux x86-64 | Ubuntu 24.04 or compatible glibc 2.39+ Linux; LLVM 18 |
| Linux AArch64 | Little-endian ARM64, Ubuntu 24.04 or compatible glibc 2.39+ Linux; LLVM 18 |
| macOS arm64 | Apple Silicon, macOS 15+, Xcode Command Line Tools; LLVM 20 |
| macOS x86-64 | Intel, macOS 15+, Xcode Command Line Tools; LLVM 20 |

Docker targets Linux amd64/arm64 and includes LLVM 18. Native archives and Docker
run the compiler without Python. Hosted installation requires Python 3.11+;
recordings and full verification use pinned CPython 3.13.16. Full verification
runs on Linux x86-64 and ARM64; macOS retains narrower installation and release
consumer coverage, with Intel macOS a secondary target. Explicit LLVM selections
retain the existing validation limits.
[Inherited platform limits](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.4/docs/releases/v0.4.0-alpha.4.md#platforms-and-known-limits)

Dynamic `Any` and promoting integers remain experimental opt-ins; broader
containment [#1210](https://github.com/den-run-ai/pystachy/issues/1210), standard
stream differences [#1182](https://github.com/den-run-ai/pystachy/issues/1182) and
the manual bytescan promoting-integer configuration gap
[#1207](https://github.com/den-run-ai/pystachy/issues/1207) remain open.
Additional language features, optimization experiments, PGO/native compiler
wheels, libuv and numerical-worker drafts remain outside this release.
The native pytest runner still supports its documented bounded dialect and
selected upstream components, not arbitrary pytest or CPython suites.
[Runner scope](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.5/docs/pytest-native.md),
[release tracker](https://github.com/den-run-ai/pystachy/issues/1186)

This prerelease does not advance GitHub stable or Docker `latest`.

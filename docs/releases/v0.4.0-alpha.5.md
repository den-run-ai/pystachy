Pystachy v0.4.0-alpha.5 removes per-item bounds checks from eligible list loops, extends
the optional Lean safety checks, lets Ubuntu source installations recover from LLVM
download failures and adds a native pytest benchmark. Pystachy is an experimental compiler
for a typed subset of Python.

## Guarded list loops

Eligible forward `range` loops now test once, before the loop, that every list they index
is long enough, then read and assign items without bounds checks, which helps LLVM
vectorize them. If the test fails, the original checked loop runs, so an invalid index
raises at the same point.

Loops that may change a list's length, run user code, suspend a generator or fall outside
the documented structural bounds keep their checks, as do list assignments in programs
using dynamic `Any` or promoting integers. An optimized loop keeps both copies, so code can
grow; `PYSTACHY_OPT=-listguard` disables the pass.
[#1247](https://github.com/den-run-ai/pystachy/pull/1247),
[#1268](https://github.com/den-run-ai/pystachy/pull/1268),
[optimization contract](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.5/docs/typed-ir.md#optimizations)

## Lean safety checks

The optional Lean checkers for typed-IR snapshots now prove that unchecked list access
stays in bounds and dictionary and set entries stay live, including in the guarded loop
copies. New checks also cover promoting-integer fit and storage, checked `+`, `-` and `*`
before promoting-integer reconstruction, and complete stack-tuple copies.

In two examples, the checkers prove seven union reads and show that six null checks were
already redundant in the graph before the pass removed them, which does not prove the pass
as a whole. A wider survey does not pass yet: alias, effect, storage and representation
gaps remain ([#1270](https://github.com/den-run-ai/pystachy/issues/1270)).

The proofs cover normalized models and trust snapshot fidelity, the Python adapters,
runtime representations and operation contracts, layout and alias assumptions, LLVM
lowering and Lean itself. They do not prove whole-compiler correctness, Python equivalence,
GC safety or general memory safety. Lean 4.35.0 is a development tool, not an installation
or runtime dependency, and the MIT-licensed models add no external Lake packages.

## Installation recovery

When Ubuntu's dated snapshot service is temporarily unavailable, Ubuntu 24.04 source
installations now fetch the pinned LLVM 18.1.3 packages from the official archive for their
architecture. Both sources must serve the same bytes, verified by SHA-256 before extraction.

Pinned LLVM downloads, including from the unchanged macOS source, now retry timeouts and
selected HTTP, DNS, connection, TLS EOF and incomplete-read failures within the existing
three attempts per package. Certificate, permanent DNS or proxy, and local-file errors
still fail at once, and the final error lists each URL tried and why.
[#1255](https://github.com/den-run-ai/pystachy/pull/1255),
[#1271](https://github.com/den-run-ai/pystachy/pull/1271),
[installation](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.5/docs/install.md)

## Native pytest benchmark

A reproducible benchmark compares ordinary CPython pytest, prepared generated CPython,
native JIT and prebuilt AOT on fixture-heavy tests, JSON repair and numeric work, reporting
execution, preparation and compilation separately. With the compiler and LLVM installed, it
also times complete first-use, unchanged-rerun and edit-and-rebuild commands with the pytest
oracle enabled.

A failed or interrupted run invalidates earlier reports. The included timings are
historical alpha.3 measurements, not alpha.5 results.
[#1242](https://github.com/den-run-ai/pystachy/pull/1242),
[benchmark and replay](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.5/bench/pytest_native/README.md)

## Known limits

- Dynamic `Any` and promoting integers remain experimental opt-ins; containment work
  continues in [#1210](https://github.com/den-run-ai/pystachy/issues/1210).
- Closed standard streams still differ from CPython
  ([#1182](https://github.com/den-run-ai/pystachy/issues/1182)), as does a manual byte-scan
  configuration with promoting integers
  ([#1207](https://github.com/den-run-ai/pystachy/issues/1207)).
- A `heapq` comparison callback that mutates its heap can leave different contents than
  CPython's C accelerator. This pre-existing difference is outside the promised parity;
  [#1257](https://github.com/den-run-ai/pystachy/pull/1257) is the follow-up.
  [Accelerator differences](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.5/lib/compatibility.md#pure-python-accelerators)
- The native pytest runner accepts its documented dialect and selected upstream
  components, not arbitrary pytest or CPython suites.
  [Runner scope](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.5/docs/pytest-native.md)
- Language-composition features, numeric-value module policy, PGO, native compiler wheels,
  libuv I/O and numerical-worker drafts are not in this release.

## Platforms

| Native archive | Requirements |
|---|---|
| Linux x86-64 | Ubuntu 24.04 or compatible glibc 2.39+ Linux; LLVM 18 |
| Linux AArch64 | Little-endian ARM64, Ubuntu 24.04 or compatible glibc 2.39+ Linux; LLVM 18 |
| macOS arm64 | Apple Silicon, macOS 15+, Xcode Command Line Tools; LLVM 20 |
| macOS x86-64 | Intel, macOS 15+, Xcode Command Line Tools; LLVM 20 |

Native archives and the Docker image run the compiler without Python; a hosted installation
needs Python 3.11+. Full verification runs on Linux x86-64 and ARM64 with CPython 3.13.16.
macOS has narrower installation and release coverage, and Intel macOS is a secondary
target. Linux archives are not manylinux packages. Other explicitly selected LLVM versions
keep their [earlier validation limits](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.4/docs/releases/v0.4.0-alpha.4.md#platforms-and-known-limits).

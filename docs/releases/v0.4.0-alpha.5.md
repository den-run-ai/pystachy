Pystachy v0.4.0-alpha.5 adds guarded list-loop optimization, broadens optional
Lean safety checks, and provides a reproducible native pytest benchmark harness.
Pystachy remains an experimental compiler for a typed subset of Python.

## Guarded list-loop optimization

Eligible forward range loops can run a copy with unchecked list item reads and
assignments after entry tests establish that every accessed list is long enough.
This removes repeated bounds checks and helps LLVM retain item pointers and
vectorize the loop. When the entry tests fail, the original checked loop runs,
preserving the point at which an invalid index raises an exception.

The optimization excludes loops that may change a list's length, run user code,
suspend a generator, or cross its documented structural bounds. Programs using
dynamic `Any` or promoting integers keep list assignments checked. Eligible
loops gain a second code path; this can increase generated code size. Disable
the pass with `PYSTACHY_OPT=-listguard` for comparisons.
[#1247](https://github.com/den-run-ai/pystachy/pull/1247),
[optimization contract](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.5/docs/typed-ir.md#optimizations)

Integration fixes preserve field effects and tuple-layout provenance when
instructions are cloned, and correctly account for rewrites so post-pass
verification runs. Focused mutation controls cover missing metadata and guards.
These compiler changes are included alongside the proof tooling.
[#1268](https://github.com/den-run-ai/pystachy/pull/1268)

## Bounded Lean safety checks

The optional development tooling now checks additional obligations in completed
typed-IR snapshots:

| Check | What it establishes in the modeled program |
|---|---|
| Unchecked container access | List reads/stores are in bounds and dictionary/set entries remain live across modeled mutations, calls and exception edges. |
| Promoting-integer fit | Recognized conditions justify discarding large-integer digits; changed reconstruction shapes cannot silently remove obligations. |
| Checked arithmetic reconstruction | Uses of checked `+`, `-` and `*` result words follow the matching no-overflow edge before promoting-integer reconstruction. |
| Promoting-integer storage | Numeric low-word uses, marker-guarded tuple digit reads and recognized tuple conversions meet their representation contracts. |
| Stack-tuple transport | Recognized complete copies retain their words under the explicit full-layout stack ABI premise. |
| Null and closed-union guards | Inventoried reads have nonnull/member facts, and removed null checks are redundant in the captured before-pass graph, within the bounded examples below. |

The access checker covers the guarded loop copies. Storage qualification follows
imports into promoting-integer modules and retains per-function and proof-batch
inventories. Rejected, unsupported or missing obligations fail their applicable
gate. CI retains its existing job and worker limits.
[#1241](https://github.com/den-run-ai/pystachy/pull/1241),
[#1253](https://github.com/den-run-ai/pystachy/pull/1253),
[#1254](https://github.com/den-run-ai/pystachy/pull/1254),
[#1265](https://github.com/den-run-ai/pystachy/pull/1265),
[#1267](https://github.com/den-run-ai/pystachy/pull/1267)

The access adapter independently scans visible function bodies and propagates
writes through direct callees, so understated effect summaries cannot preserve
stale access facts. Recognized closure-cell reads and range facts extend the
supported cases. The arithmetic checker follows actual overflow flags and
retains unsupported reconstruction shapes in its inventory; other inline
arithmetic remains outside that extracted-IR proof scope.

The null/union CI gate covers **seven union reads and six removed null checks in
two explicit examples**. Potential box writes and opaque calls before later
union reads fail conservatively. Unproved value transports and ambiguous removals
remain visible in reports. Broader alias, effect, storage and representation
gaps remain in [#1270](https://github.com/den-run-ai/pystachy/issues/1270); the wider
survey is explicitly non-passing. Null-check proofs establish redundancy in the
before-pass graph, not whole-pass transformation equivalence. These limits do
not establish compiler bugs in the rejected or unsupported cases.
[#1269](https://github.com/den-run-ai/pystachy/pull/1269),
[guard proof scope](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.5/tools/lean_boundary/GUARDS.md)

These proofs establish bounded properties of normalized models. Snapshot
fidelity, Python adapters, runtime representation and operation contracts,
layout/alias assumptions and LLVM lowering remain trusted or outside the proof.
They do not prove whole-compiler correctness, Python equivalence, GC safety or
general memory safety. Compiled checker execution additionally trusts Lean's
compiler, runtime and JSON front end. Ordinary CPython differential, JIT/AOT,
sanitizer and GC checks remain required.

Lean 4.35.0 remains an external development tool, not a compiler-runtime or
user-installation dependency. The Pystachy models remain MIT-licensed and add no
external Lake packages. Historical proof inventories retain their source and
scope; they are not substituted for exact release qualification.
[Proof scope and provenance](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.5/tools/lean_boundary/README.md)

## Installation recovery

Ubuntu 24.04 source installations can recover from a temporary failure of the
dated Ubuntu snapshot service by trying the official archive for their CPU
architecture. Both endpoints must provide the same pinned LLVM 18.1.3 package
bytes, verified by SHA-256 before extraction.

The bounded retries cover selected HTTP errors, timeouts, temporary DNS failures,
and explicit connection-reset/refusal, TLS EOF and incomplete-read exceptions.
Each new response starts a fresh destination file and digest. Silent short responses
still fail checksum validation; certificate, permanent DNS/proxy and local-file
errors remain terminal. The three-attempt budget per package is unchanged,
and terminal network diagnostics retain every attempted URL and reason.

Existing caches, explicit `PYSTACHY_LLVM` selection, package pins and macOS
download sources remain unchanged. The connection-recovery rules also apply
to downloads from the unchanged macOS endpoint.
[#1255](https://github.com/den-run-ai/pystachy/pull/1255),
[#1271](https://github.com/den-run-ai/pystachy/pull/1271),
[installation](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.5/docs/install.md)

## Native pytest benchmark

The benchmark compares ordinary CPython pytest, prepared generated CPython,
native JIT and prebuilt AOT across fixture-heavy tests, JSON repair and numeric
work. With the compiler and LLVM already installed, it also measures complete
first-use, unchanged-rerun and edit/rebuild commands with the independent pytest
oracle enabled. Installation and compiler bootstrap are outside those timings.

Failed or interrupted runs invalidate prior reports. New reports retain case
and phase inventories, source identities and selected LLVM tool/library
fingerprints. Included timings remain historical alpha.3 measurements with
their recorded provenance limits; they are not alpha.5 performance measurements.
Prebuilt execution, preparation, compilation and complete development-command
costs remain distinct. No release-wide speedup is claimed.
[#1242](https://github.com/den-run-ai/pystachy/pull/1242),
[benchmark and replay](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.5/bench/pytest_native/README.md)

## Platforms and known limits

| Native archive | Requirements |
|---|---|
| Linux x86-64 | Ubuntu 24.04 or compatible glibc 2.39+ Linux; LLVM 18 |
| Linux AArch64 | Little-endian ARM64, Ubuntu 24.04 or compatible glibc 2.39+ Linux; LLVM 18 |
| macOS arm64 | Apple Silicon, macOS 15+, Xcode Command Line Tools; LLVM 20 |
| macOS x86-64 | Intel, macOS 15+, Xcode Command Line Tools; LLVM 20 |

Docker targets Linux amd64/arm64 and includes LLVM 18. Native archives and Docker
run the compiler without Python. Hosted installation requires Python 3.11+;
recordings and full verification use pinned CPython 3.13.16. Full verification
runs on Linux x86-64 and ARM64; macOS retains narrower installation and release
consumer coverage, with Intel macOS a secondary target. These Linux archives
do not claim manylinux compatibility. Explicit LLVM selections retain the
existing validation limits.
[Inherited platform limits](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.4/docs/releases/v0.4.0-alpha.4.md#platforms-and-known-limits)

Dynamic `Any` and promoting integers remain experimental opt-ins. Broader
containment [#1210](https://github.com/den-run-ai/pystachy/issues/1210), standard
stream differences [#1182](https://github.com/den-run-ai/pystachy/issues/1182) and
the manual bytescan promoting-integer configuration gap
[#1207](https://github.com/den-run-ai/pystachy/issues/1207) remain open.

`heapq` comparators that mutate their heap can leave different contents from
CPython's C accelerator. This pre-existing pure-Python library limitation remains
outside promised accelerator parity; [#1257](https://github.com/den-run-ai/pystachy/pull/1257)
tracks the unmerged follow-up.
[Accelerator differences](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.5/lib/compatibility.md#pure-python-accelerators)

Language-composition features, numeric-value module policy, PGO/native compiler
wheels, libuv and numerical-worker drafts remain outside this candidate.
The native pytest runner supports its documented bounded dialect and selected
upstream components, not arbitrary pytest or CPython suites.
[Runner scope](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.5/docs/pytest-native.md)

This prerelease does not advance GitHub stable or Docker `latest`.

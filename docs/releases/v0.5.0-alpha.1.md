Pystachy v0.5.0-alpha.1 repairs tuple comparisons and cross-module context managers,
and expands the optional compiler verification tools. It starts the v0.5.0 series
from v0.4.0; class, library and numeric extensions will follow in later alphas.
Pystachy remains an experimental compiler for a typed subset of Python.

## Correctness repairs

- Tuple membership, `count()` and `index()` dispatch equality through runtime
  subclasses and members of class unions. Comparisons that the subset cannot compile
  retain the documented fallback boundary.
  [Tuple dispatch](https://github.com/den-run-ai/pystachy/pull/1440),
  [compatibility](https://github.com/den-run-ai/pystachy/blob/v0.5.0-alpha.1/docs/language/compatibility.md)
- NamedTuple fields retain promoting integers when the object may be `None`, including
  tuple searches and formatting. The combined tuple-dispatch path preserves this
  behavior for class unions.
  [Promoting integers](https://github.com/den-run-ai/pystachy/pull/1443)
- A cross-module `super()` call to a `contextmanager` method executes the base class's
  generator instead of redispatching to the child. Explicit class-method calls retain
  their class's implementation and argument evaluation order for nullable receivers,
  with the documented constructor restriction. Contextmanager metadata inspection is
  null-safe, and packed arguments preserve promoting integers within the port's
  documented reflection limits.
  [Context managers](https://github.com/den-run-ai/pystachy/pull/1470)
- Typed-IR checks validate the storage domain of union values read from tuple slots,
  including transported and merged addresses.
  [Tuple-slot checks](https://github.com/den-run-ai/pystachy/pull/1293)

## Verification and performance reporting

Optional Lean checks now cover additional removed null checks, field initialization,
promoting-integer storage and collector-array obligations, including generator paths.
A generated report records input identities, proved obligations, unsupported cases
and rejected functions. These bounded models do not prove whole-compiler or collector
correctness. Checker processes and shared results reduce repeated verification work.
[Scope and report](https://github.com/den-run-ai/pystachy/blob/v0.5.0-alpha.1/tools/lean_boundary/README.md)

Integration hardens checker timeouts when a process stops reading and keeps field
contracts aligned with runtime arguments when a `None` parameter is omitted. Negative
controls check both boundaries. Resuming proof runs requires clean source identities
and matching checker executables. A separate weekly performance workflow compares the
adapted pyperformance ports and microbenchmarks, retaining explicit failures and
incomplete measurements within its time budget.
[Release tracking](https://github.com/den-run-ai/pystachy/issues/1476)

## Known limits and platforms

Dynamic `Any` and promoting integers remain experimental opt-ins. Circular-import
readiness, closed standard streams, sustained CI headroom and GC scaling retain their
existing limitations. Async, full native mypy, broader numeric types and experimental
concurrency are outside this alpha.
[Compatibility](https://github.com/den-run-ai/pystachy/blob/v0.5.0-alpha.1/docs/language/compatibility.md)

Native archives target Linux x86-64/AArch64 with glibc 2.39+ and LLVM 18, and macOS
arm64/x86-64 with macOS 15+, Xcode Command Line Tools and LLVM 20. Linux archives
are not manylinux packages. Archives and Docker run without Python; the hosted
compiler needs Python 3.11+. Full verification uses Linux x86-64/ARM64 and CPython
3.13.16; macOS has installation and release coverage. Prereleases leave stable
`latest` unchanged.

Pystachy v0.4.0-alpha.6 adds bounded structural pattern matching, fixes selected
CPython compatibility gaps, and strengthens native pytest qualification. This is
the final feature alpha for v0.4.0; subsequent release-candidate work is limited
to correctness, CI, packaging and release qualification. Pystachy remains an
experimental compiler for a typed subset of Python.

## Bounded structural pattern matching

`match` supports literals, wildcards, captures, `as`, alternatives, guards, fixed
tuples and plain fields of statically known dataclasses. It evaluates the subject
once and tests cases in source order. Captures bind after the whole pattern
succeeds and before its guard runs; a false guard retains those bindings.

The lowering uses ordinary assignments and branches. Mapping patterns, starred
or general sequence patterns, arbitrary class patterns, dataclass hierarchies,
custom `__match_args__` and attribute hooks remain unsupported. Tuple and
dataclass patterns require concrete subject types; existing equality and type
inference restrictions still apply. This does not claim general Python pattern
matching or a release-wide performance improvement.
[#1272](https://github.com/den-run-ai/pystachy/pull/1272),
[pattern contract](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.6/docs/language/semantics.md#structural-patterns)

## CPython compatibility

The `heapq` heap functions and their `_max` variants now follow CPython 3.13.16's
C accelerator: sifting preserves the heap contents visible to comparison
callbacks, size-changing callbacks raise its `RuntimeError`, and `heapify()`
above 2,500 items uses its cache-friendly comparison order. This resolves the
accelerator differences disclosed in alpha.5. `heapq.merge` remains unsupported,
and top-k functions still materialize non-list iterables before processing.
[#1257](https://github.com/den-run-ai/pystachy/pull/1257),
[heapq limits](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.6/lib/compatibility.md#heapq)

`statistics.linear_regression` now compiles for compatible numeric sequences,
including proportional fits. Weighted `fmean` and proportional regression retain
the documented 64-bit integer-product limit. `statistics.kde` passes its pattern
dispatch but still cannot compile its heterogeneous function storage and
function `__doc__` assignments.
[#1258](https://github.com/den-run-ai/pystachy/pull/1258),
[statistics limits](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.6/lib/compatibility.md#statistics)

Exception handlers can take exception class objects from variables, parameters,
fields, calls and flat tuples. The expression is evaluated when the handler is
reached, and every class must derive from `BaseException` before matching begins.
Integration fixes reject nested handler tuples and validate invalid class
objects even after an earlier tuple member would match. These restrictions do
not change the separate nested-tuple behavior of `isinstance` and `issubclass`.
[#1259](https://github.com/den-run-ai/pystachy/pull/1259),
[exception class values](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.6/docs/language/semantics.md#exception-classes-as-values)

Uninitialized module-level `Any` annotations no longer apply the local variable
restriction. A later concrete assignment can determine their native storage,
including generator-valued module globals. This does not enable general dynamic
storage without its existing opt-in.
[#1283](https://github.com/den-run-ai/pystachy/pull/1283),
[annotation rules](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.6/docs/language/typing.md)

## Native pytest qualification

The source-pinned upstream qualifier now covers all five mypyc NameGenerator
test methods, three of its eleven literal-encoder test methods and both mypy
`teststubinfo` test methods. The selected statistics suite has five test methods, including
the original weighted-`fmean` test enabled by exception class-object handlers.
Each selected method is checked through its original suite, adapted pytest,
generated CPython, native JIT and AOT stages. Inventories and exclusions remain
explicit; this is not qualification of the complete mypy or CPython suites.
[#1289](https://github.com/den-run-ai/pystachy/pull/1289),
[upstream scope](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.6/tests/upstream/pytest/README.md)

A narrow extraction from #1287 fixes relative compiler paths when the
runner or qualifier changes directory. Commands such as `--compiler ./pystachy`
and `--compiler 'python3 pystachy.py'` keep the invocation directory's meaning;
Python options, module names, script arguments and virtual-environment symlinks
retain their behavior. The broader class and fixture expansion is not
included.
[#1287](https://github.com/den-run-ai/pystachy/pull/1287),
[runner contract](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.6/docs/pytest-native.md)

## CI stabilization and release scope

The full x86-64 Lean corpus and integer checks move from the crowded runtime-cache
job into the existing GC JIT job. The checks remain sequential, and their proof
scope, artifacts, job count, worker limits and timeouts are preserved. This
addresses the demonstrated packed-job timeout; broader CI headroom qualification
remains tracked separately.
[#1290](https://github.com/den-run-ai/pystachy/pull/1290),
[#1178](https://github.com/den-run-ai/pystachy/issues/1178)

Lint builds the selected Lean checker once and runs its boundary tests once,
requiring the checker when selected. Runtime ABI, cache and GC controls move
intact into the existing second native JIT/variant worker on PRs and the x86-64
`gc-jit-0` job on full runs. Sanitizer setup and positive and negative CPU-buffer
checks remain required. These changes give the lint job more room without
adding jobs or concurrent workers.
[CI coverage](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.6/docs/testing.md#continuous-integration)

Async, broader language-composition and class/inference work, numeric-value
module policy, expanded Lean and pytest drafts, optional library additions and
compiler refactors remain outside this release. Active development branches are
preserved. The scope decisions and exact release evidence are tracked in
[#1186](https://github.com/den-run-ai/pystachy/issues/1186).

## Platforms and known limits

| Native archive | Requirements |
|---|---|
| Linux x86-64 | Ubuntu 24.04 or compatible glibc 2.39+ Linux; LLVM 18 |
| Linux AArch64 | Little-endian ARM64, Ubuntu 24.04 or compatible glibc 2.39+ Linux; LLVM 18 |
| macOS arm64 | Apple Silicon, macOS 15+, Xcode Command Line Tools; LLVM 20 |
| macOS x86-64 | Intel, macOS 15+, Xcode Command Line Tools; LLVM 20 |

Docker targets Linux amd64/arm64 and includes LLVM 18. Native archives and Docker
run the compiler without Python. Hosted installation requires Python 3.11+;
recordings and full verification use pinned CPython 3.13.16. Full verification
runs on Linux x86-64 and ARM64. macOS retains narrower installation and release
consumer coverage; Intel macOS is a secondary target. Linux archives do not
claim manylinux compatibility.
[Installation](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.6/docs/install.md)

Dynamic `Any` and promoting integers remain experimental opt-ins. Their broader
containment work [#1210](https://github.com/den-run-ai/pystachy/issues/1210), the
documented standard-stream differences tracked in
[#1182](https://github.com/den-run-ai/pystachy/issues/1182), and the manual bytescan
promoting-integer configuration gap
[#1207](https://github.com/den-run-ai/pystachy/issues/1207) remain outside this
release's fixes. The native pytest runner retains its documented bounded dialect.

This prerelease does not advance GitHub stable or Docker `latest`.

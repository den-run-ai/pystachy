Pystachy v0.4.0-alpha.6 is the last feature alpha before v0.4.0. It compiles bounded
`match` statements, closes CPython compatibility gaps in `heapq`, `statistics` and
exception handlers, and qualifies more upstream tests with the native pytest runner.
Pystachy is an experimental compiler for a typed subset of Python.

## Structural pattern matching

`match` statements now compile for literal, wildcard, capture, `as`, alternative and guard
patterns, fixed-length tuples, and plain fields of dataclasses known at compile time. The
subject is evaluated once and cases are tried in source order. Captures bind when the whole
pattern succeeds, before its guard runs, and stay bound if the guard is false.
[#1272](https://github.com/den-run-ai/pystachy/pull/1272)

Tuple and dataclass patterns need a subject of known type. Mapping, starred and general
sequence patterns, other class patterns, dataclass hierarchies and custom `__match_args__`
are not supported yet ([#1305](https://github.com/den-run-ai/pystachy/issues/1305)); see the
[pattern contract](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.6/docs/language/semantics.md#structural-patterns).

## CPython compatibility

- `heapq` heap functions and their `_max` variants follow CPython 3.13.16's C accelerator:
  a comparison callback sees every heap item, a callback that resizes the heap raises
  `RuntimeError`, and `heapify()` of more than 2,500 items compares in the C order. This
  removes the difference disclosed in alpha.5. `heapq.merge` is still unsupported, and the
  top-k functions copy non-list inputs first.
  [#1257](https://github.com/den-run-ai/pystachy/pull/1257),
  [`heapq` limits](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.6/lib/compatibility.md#heapq)
- `statistics.linear_regression` compiles for compatible numeric sequences, including
  proportional fits, within the documented 64-bit integer-product limit that weighted
  `fmean` shares. `statistics.kde` still does not compile: it stores heterogeneous functions
  and assigns their `__doc__`.
  [#1258](https://github.com/den-run-ai/pystachy/pull/1258),
  [`statistics` limits](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.6/lib/compatibility.md#statistics)
- `except` clauses accept exception classes from variables, parameters, fields, calls and
  flat tuples. The expression is evaluated when the handler is reached, and every class in
  it must derive from `BaseException` before matching starts. Nested tuples are rejected.
  [#1259](https://github.com/den-run-ai/pystachy/pull/1259),
  [exception classes as values](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.6/docs/language/semantics.md#exception-classes-as-values)
- A module-level `Any` annotation without a value no longer falls under the local-variable
  restriction: a later concrete assignment, including a generator, decides its native
  storage. Dynamic storage still requires the dynamic `Any` opt-in.
  [#1283](https://github.com/den-run-ai/pystachy/pull/1283),
  [annotation rules](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.6/docs/language/typing.md)
- Differently typed optional values compare equal when both hold `None`, including dotted
  value patterns in `match`. [#1316](https://github.com/den-run-ai/pystachy/pull/1316)

## Native pytest qualification

The source-pinned upstream qualifier now runs all five mypyc `NameGenerator` test methods,
three of the eleven literal-encoder methods, both mypy `teststubinfo` methods and five
`statistics` methods, including the original weighted-`fmean` test. Each method must pass
in its original suite, adapted pytest, generated CPython, native JIT and AOT. The complete
mypy and CPython suites are not qualified.
[#1289](https://github.com/den-run-ai/pystachy/pull/1289),
[upstream scope](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.6/tests/upstream/pytest/README.md)

Relative compiler paths, such as `--compiler ./pystachy` or
`--compiler 'python3 pystachy.py'`, keep their meaning when the runner or qualifier changes
directory. The test-class and fixture support proposed in the same pull request is not
included. [#1287](https://github.com/den-run-ai/pystachy/pull/1287),
[runner contract](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.6/docs/pytest-native.md)

## Known limits

- Dynamic `Any` and promoting integers remain experimental opt-ins; containment work
  continues in [#1210](https://github.com/den-run-ai/pystachy/issues/1210).
- Closed standard streams still differ from CPython
  ([#1182](https://github.com/den-run-ai/pystachy/issues/1182)), as does a manual byte-scan
  configuration with promoting integers
  ([#1207](https://github.com/den-run-ai/pystachy/issues/1207)).
- The native pytest runner accepts its documented dialect, not arbitrary pytest suites.
- An exception subclass that shadows a base field with a mutable class attribute can
  crash on a base-typed field read. Its isolated correction is tracked for RC.1 in
  [#1333](https://github.com/den-run-ai/pystachy/issues/1333).
- Async functions, broader language composition, class and inference work, numeric-value
  module policy and optional library additions are not in this release;
  [#1186](https://github.com/den-run-ai/pystachy/issues/1186) tracks the v0.4.0 scope.

## Platforms

| Native archive | Requirements |
|---|---|
| Linux x86-64 | Ubuntu 24.04 or compatible glibc 2.39+ Linux; LLVM 18 |
| Linux AArch64 | Little-endian ARM64, Ubuntu 24.04 or compatible glibc 2.39+ Linux; LLVM 18 |
| macOS arm64 | Apple Silicon, macOS 15+, Xcode Command Line Tools; LLVM 20 |
| macOS x86-64 | Intel, macOS 15+, Xcode Command Line Tools; LLVM 20 |

Native archives and the Docker image run the compiler without Python; a hosted installation
needs Python 3.11+. Full verification runs on Linux x86-64 and ARM64 with CPython 3.13.16.
macOS has narrower installation and release coverage, and Intel macOS is a secondary
target. Linux archives are not manylinux packages.
[Installation](https://github.com/den-run-ai/pystachy/blob/v0.4.0-alpha.6/docs/install.md)

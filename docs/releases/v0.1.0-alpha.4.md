Pystachy compiles a subset of Python to native code through LLVM: `pystachy run` for JIT
execution and `pystachy build` for standalone executables. This fourth alpha adds experimental
arbitrary-precision integers, expands dynamic iteration and numeric protocols, and includes
an adapted in-memory JSON-repair library since
[v0.1.0-alpha.3](https://github.com/den-run-ai/pystachy/releases/tag/v0.1.0-alpha.3).

**Pystachy remains experimental. Promoting integers and dynamic `Any` are opt-ins that can
be enabled together; neither is enabled by default.** Documented correctness and performance limits remain.
Most PyPI packages do not compile unchanged.

## Highlights

- **Native Linux ARM64 distribution.** Linux ARM64 joins x86-64 in the full
  LLVM 18 verification matrix and gains `linux-aarch64` archives and a native
  `linux/arm64` Docker image. macOS Apple Silicon remains a primary target;
  Intel Mac archives remain secondary. Both Linux architectures retain the
  explicit glibc 2.39 baseline while older-baseline packaging is investigated
  ([#998](https://github.com/den-run-ai/pystachy/issues/998)).
- **Catchable recursion limits.** `sys.setrecursionlimit()` bounds recursive calls in JIT
  and AOT: direct and mutual recursion, including methods, calls the compiler cannot
  follow (dynamic callbacks, runtime-called special methods) and active generator bodies.
  Exceeding the limit raises `RecursionError` and runs ordinary exception/finally
  cleanup; optimized tail recursion also retains the limit. Functions that cannot be
  entered again while active do not count, so exact depth differs from CPython, and
  excessively raised limits can still exhaust the physical stack
  ([#988](https://github.com/den-run-ai/pystachy/issues/988)).
- **Integers beyond 64 bits.** A module beginning with `# pystachy: python-int` can promote
  integer arithmetic beyond signed 64-bit range, using native scalar fast paths while values
  fit. Supported parameters, returns, fields, closures, fixed tuples, integer containers and
  generator yield/return channels preserve large values. Exact integer/float comparisons,
  true division, parsing, formatting and modular powers are included. Other modules retain
  checked 64-bit integers; the [boundary reference](https://github.com/den-run-ai/pystachy/blob/v0.1.0-alpha.4/docs/python-int.md#64-bit-boundaries)
  lists remaining narrowing points. The separate experimental
  [`mpz` API](https://github.com/den-run-ai/pystachy/blob/v0.1.0-alpha.4/docs/mpz.md)
  provides explicit arbitrary-precision values without opting an entire module in.
- **Promoting integers with dynamic `Any`.** Both pragmas may appear in one module.
  Wide values cross supported typed/dynamic calls, fields, closures and fresh displays
  without narrowing, and supported integer containers retain wide values in dynamic
  programs. Numeric identity is preserved through the supported channels, extending
  [#981](https://github.com/den-run-ai/pystachy/pull/981)'s in-range companion repair.
  Boxed arithmetic promotes on overflow in a combined module; dynamic-only modules
  accept wide operands but keep checked overflow for two in-range operands
  ([#997](https://github.com/den-run-ai/pystachy/pull/997)). Explicit fixed-width
  destinations and other documented storage limits remain.
- **Lower identity and dictionary overhead.** Identity tracking is scoped to modules that
  can observe it ([#973](https://github.com/den-run-ai/pystachy/pull/973)). Typed dictionaries
  using CPython-compatible hashes inline their string/integer hash path while retaining
  exact table and probe behavior ([#980](https://github.com/den-run-ai/pystachy/pull/980)).
  Follow-up string probes and checked removal of JSON scanner companions further reduce
  the typed decoder overhead ([#983](https://github.com/den-run-ai/pystachy/pull/983),
  [#984](https://github.com/den-run-ai/pystachy/pull/984)).
- **Fewer allocations in AOT builds.** LLVM can now delete objects, fixed tuples and
  tuple-return wrappers that nothing reads. In pyperformance, raytrace allocates 33.6%
  fewer objects and executes about 30% fewer instructions, chaos 26.3% and 5.8%, and
  spectral_norm's 52,000 allocations disappear. Builds of programs that allocate objects
  take a late inlining step, measured at 2–7% more build instructions;
  `PYSTACHY_OPT=-allocelide` disables the optimization
  ([#1020](https://github.com/den-run-ai/pystachy/pull/1020)).
- **Bulk JSON string scanning.** The native decoder shared by typed `JSONValue` and
  dynamic `Any` scans ordinary string content eight bytes at a time. Long ordinary strings
  execute about 41% fewer instructions and sparse escapes 46% fewer, but keys and strings
  just past its 16-byte scalar prefix cost more: the broad pyperformance JSON workload
  executes 9.6% more instructions ([#1004](https://github.com/den-run-ai/pystachy/pull/1004);
  see below).
- **Dynamic iteration and generators.** `Any` can hold ranges, supported builtin/user
  iterators and generators with boxable yields. Loops, `iter()`, `next()`, supported
  `reversed()` calls and consuming builtins retain lazy advancement and shared iterator state
  ([#951](https://github.com/den-run-ai/pystachy/pull/951)). Typed/dynamic generator crossings
  preserve yield, send and return channels separately, including boxed `None`; compatible
  fresh list yields can adopt the caller's layout without copying existing mutable aliases
  ([#950](https://github.com/den-run-ai/pystachy/pull/950)). This does not add generator
  `send`/`throw`/`close` calls through `Any` or legacy `__getitem__` iteration.
- **Dynamic numeric protocols.** `int()` and `float()` use supported boxed-object conversion
  methods and their `__index__` fallback. Builtin indexing and slicing also accept supported
  boxed index objects, preserving conversion order and exceptions
  ([#949](https://github.com/den-run-ai/pystachy/pull/949)). [#997](https://github.com/den-run-ai/pystachy/pull/997)
  additionally supports wide boxed integers without changing their Python type or
  the size of a dynamic box.
- **Comparison and identity fixes.** More cross-type comparison bodies execute their helpers,
  callbacks and missing-field writes. Numeric identities survive supported typed calls,
  defaults, instance fields and numeric-list operations. A selected comparison body that
  cannot compile now raises an explicit `TypeError`; same-hierarchy helpers and imported
  unavailable declarations preserve method selection
  ([#995](https://github.com/den-run-ai/pystachy/pull/995)). Some typed-container crossings still lose identity;
  see [the dynamic contract](https://github.com/den-run-ai/pystachy/blob/v0.1.0-alpha.4/docs/dynamic-any.md#deviations).
  Chained comparisons whose link always raises now compile and preserve the first exception
  ([#911](https://github.com/den-run-ai/pystachy/pull/911)). A retired lazy field-sharing
  candidate now stays retired, preserving field values and identity across mutating callbacks
  ([#974](https://github.com/den-run-ai/pystachy/pull/974)).
- **Optional typed length hints.** `list()`, `sorted()` and `list.extend()` ignore
  `TypeError` from an optional user `__len__`, including subclasses, after obtaining the
  iterator. Other errors, direct `len()` and outer handled exceptions retain their behavior.
  This also repairs `statistics.fmean` with unsized weights
  ([#977](https://github.com/den-run-ai/pystachy/pull/977)).
- **Adapted `json_repair` 0.64.1.** The maintained ports package adds in-memory `loads()` and
  `repair_json()` without embedded CPython. Schema/Pydantic support, files and the CLI are
  excluded. The pinned replay matches pristine upstream in **645/645 cases** on CPython
  and under native JIT/AOT, including per-allocation GC stress. Additional regressions address
  large integers disappearing or changing valid JSON's Unicode/strict-mode behavior:
  the dynamic decoder now promotes the overflowing token directly, while typed `JSONValue`
  decoding remains fixed-width. Comment-related value loss in arrays and objects is fixed.
  Deep malformed input reaches the native recursion limit at upstream's CPython nesting
  depths and raises upstream's `ValueError`. Bounded string accumulation removes repeated
  growing-prefix copies, with measured memory and cross-engine tradeoffs, and ordinary
  text is repaired in spans ([#1007](https://github.com/den-run-ai/pystachy/pull/1007)).
  On the release candidate, AOT repairs ten small LLM-style records 5.2× faster than
  pristine json_repair on CPython and escape-heavy strings about 180× faster, because
  upstream rescans those quadratically. Valid JSON gains 1.4–2.6×; non-ASCII malformed
  text gains nothing. See the
  [port scope](https://github.com/den-run-ai/pystachy/blob/v0.1.0-alpha.4/ports/json_repair/PORT.md)
  and [measurements](https://github.com/den-run-ai/pystachy/blob/v0.1.0-alpha.4/bench/json_repair/README.md).
- **Compatibility checks.** A maintained promoting-integer corpus sweep checks output and
  exact expected failures rather than assuming an opt-in preserves compatibility. Added
  CPython-derived `shlex` and `posixpath` cases, and 96 test methods mechanically extracted
  from 20 more CPython test files, extend the differential corpus
  ([#1023](https://github.com/den-run-ai/pystachy/pull/1023)). These are adapted tests, not
  the complete CPython test suite. pyperformance's `pidigits` now runs with promoting
  integers, bringing the adapted suite to 23 benchmarks; this big-integer workload is
  slower than CPython ([#1022](https://github.com/den-run-ai/pystachy/pull/1022)).

## Performance and remaining risks

The retained JSON decoder controls were re-measured on the release candidate (main
`c3aaa068`) against the actual alpha.3 tag, each built by its own compiler with LLVM 18.1.3.
They count whole-process AOT instructions, not wall time, and every output matched CPython.
The broad workload's timed loop discards its results: it runs the **typed `JSONValue`
decoder inside a dynamic-Any program**.

| Workload | Measured result | Limit |
|---|---|---|
| Typed JSON decoding, 300 loops | 1,428.5M instructions versus 1,300.4M for alpha.3: **9.85% above the tag**. The count stayed between −0.2% and +0.5% of alpha.3 until [#1004](https://github.com/den-run-ai/pystachy/pull/1004)'s byte scanner, whose call costs more than it saves on keys and strings just past its 16-byte scalar prefix. | Instruction counts. Nine paired wall-time runs on a shared host were inconclusive (medians 138.7 and 138.2 ms before and after #1004). Long strings still execute about 41% fewer instructions. |
| JSON follow-up controls | Typed 32-key controls are 1.9–4.1% above alpha.3. Observed-`Any` 32-key controls range from 1.5% below to 4.9% above; the short Any control is 1.7% above. | The [#987](https://github.com/den-run-ai/pystachy/pull/987) result that closed [#969](https://github.com/den-run-ai/pystachy/issues/969), with every control below alpha.3, no longer holds. The controls do not recover the missing historical 124M-instruction input. |
| JSON repair | AOT repairs ten small LLM-style records 5.2× faster than pristine json_repair on CPython and 2,000-escape strings 183× faster. Valid JSON gains 1.4–2.6×; non-ASCII malformed text runs at 0.91–1.01× CPython's speed. | Synthetic checked workloads on a shared VM, excluding startup and compilation. On malformed non-ASCII input, building the discarded `JSONDecodeError` takes 41% of instructions, mostly `repr()` of the whole document. |
| pyperformance suite, AOT | Across the 22 benchmarks both releases run, the candidate executes a geometric mean of **+2.35%** more instructions than alpha.3; every output matches CPython. Paired wall times on a shared host follow loosely (scimark 1.15×, barnes_hut 1.08×, raytrace 0.93×). Dropping only #888's `pys_list_set` line brings the geometric mean to +0.71% in a scratch build. The [JSON control counts](https://github.com/den-run-ai/pystachy/blob/v0.1.0-alpha.4/bench/smoke/results/json-controls-2026-11-02.json)
retain commands, binary hashes, the bisect and per-function attribution; the
[JSON-repair measurements](https://github.com/den-run-ai/pystachy/blob/v0.1.0-alpha.4/bench/json_repair/README.md)
retain every timing process. The [29 October report](https://github.com/den-run-ai/pystachy/blob/06e3ad5d08514ba31fb231fe4636a962fe6578e3/docs/reports/json-acceptance-controls-2026-10-29.md)
records the earlier counts that closed #969, before #1004 merged.

Earlier preparation also reduced plain AOT executable sizes by 12.6–29.3% and spectral/richards
build times by 19.3%/17.6% relative to the evaluated preparation baseline. That bounded result
is partial mitigation for [#706](https://github.com/den-run-ai/pystachy/issues/706), not a claim
of alpha.3 parity or a general application speedup; the
[AOT report](https://github.com/den-run-ai/pystachy/blob/06e3ad5d08514ba31fb231fe4636a962fe6578e3/docs/reports/aot-plain-runtime-2026-10-28.md)
and [original sweep](https://github.com/den-run-ai/pystachy/blob/06e3ad5d08514ba31fb231fe4636a962fe6578e3/docs/reports/release-sweep-2026-10-28.md)
retain their baselines and limits. On the final candidate, AOT executables of the measured
benchmarks are 12% larger and single builds 22% slower than alpha.3's (geometric means),
partly from #1020's late inlining step. Broad retained-memory behavior was not measured.

## Known issues and workarounds

| Area | Remaining behavior | Practical route |
|---|---|---|
| Recursion | `sys.setrecursionlimit()` now raises catchable `RecursionError` for recursive calls, but non-recursive frames do not count, so native and CPython depths differ. Excessively raised limits, large native frames or foreign calls can still exhaust the physical stack without recoverable unwinding. | Keep limits conservative and validate recursive workloads on the deployment stack; see the [native recursion policy](https://github.com/den-run-ai/pystachy/blob/v0.1.0-alpha.4/docs/language/compatibility.md#errors-and-control-flow). |
| Promoting integers | The two opt-ins can be combined, and wide values pass through `Any` without narrowing. Some closed-union/container, library, index and FFI destinations still require 64-bit values; CPython-accepted values can raise `OverflowError` or be rejected during compilation. Direct typed integer `is` remains restricted. | Follow the [promoting-int boundary list](https://github.com/den-run-ai/pystachy/blob/v0.1.0-alpha.4/docs/python-int.md#64-bit-boundaries); keep unsupported operations in CPython. |
| Dynamic comparisons and identity | Selecting an unsupported comparison body raises an explicit `TypeError` where CPython would execute it. Numeric identity remains incomplete through typed tuple/dict/set items, optional/union list items and typed generator yields. | Use supported typed paths or CPython for comparison-sensitive code. Check effects and first exceptions as well as final values ([#803](https://github.com/den-run-ai/pystachy/issues/803), [#858](https://github.com/den-run-ai/pystachy/issues/858)). |
| Private names | Class-private names are not mangled; attribute access can differ silently from CPython. | Use explicit nonprivate field names in compiled code or retain the affected classes in CPython ([#151](https://github.com/den-run-ai/pystachy/issues/151)). |
| JSON | Dynamic JSON integers promote; typed `JSONValue` integers remain signed 64-bit. Nesting is limited to 256 containers. File APIs, hooks and indentation remain unsupported. Callback-driven structural dict mutations can encode differently from CPython. | Validate size/depth and keep dict structure stable during callbacks; use CPython outside the documented [JSON scope](https://github.com/den-run-ai/pystachy/blob/v0.1.0-alpha.4/docs/json.md). |
| JSON repair | Malformed-input repair reports the native recursion limit through the facade's `ValueError`, as upstream does; valid JSON nested beyond 256 containers raises the native decoder's `RecursionError` instead of being decoded ([#1021](https://github.com/den-run-ai/pystachy/issues/1021)). Forced repair can still discard primitive roots, following upstream heuristics. Non-ASCII malformed text repairs at about CPython's speed, and each JIT run compiles the package first (about 1.2 s). | Keep the default decoder path for valid scalars; validate repaired values and nesting depth. Use AOT builds for repeated short runs. |
| Platform coverage | Full differential verification uses LLVM 18 on Linux. macOS LLVM 20 receives installation/package JIT/AOT/GC smoke coverage. | Verify applications on their deployment platform ([#708](https://github.com/den-run-ai/pystachy/issues/708)). |

Unsupported native features still include multiple inheritance, `async`/`await`, `match`,
`bytearray` and binary filesystem I/O. Concrete annotations can introduce runtime type
checks absent from CPython. Opt-in corpus exceptions remain explicit compatibility gaps,
not parity passes. The [language compatibility reference](https://github.com/den-run-ai/pystachy/blob/v0.1.0-alpha.4/docs/language/compatibility.md)
and [library guide](https://github.com/den-run-ai/pystachy/blob/v0.1.0-alpha.4/lib/README.md)
define the supported scope.

## Verification and installation

The [release tracker](https://github.com/den-run-ai/pystachy/issues/976) records preparation
blockers and the final source. Publication requires CI, Installation, Lint and Packages to
pass on that exact release commit. Compiler/runtime bootstraps must reach byte-identical fixed points. Native archives
are built and smoke-tested on Linux x86-64/ARM64 and macOS arm64/x86-64; Docker provides
native Linux amd64 and arm64 variants from the corresponding verified archives.
Linux ARM64 joins the full LLVM 18 verification matrix, with independent bootstrap,
JIT/AOT, GC, sanitizer, FFI and report gates. These are release requirements, not a
claim that a prerelease is already published.
The port also validates platform-specific thread stack-size limits, compiler-rt
builtins needed by sanitized JIT code, and the native two-word integer return ABI.
Package checks cover relocation, external caching, normal/GC-stressed JIT and AOT,
JSON/Unicode behavior and warm runtime-cache reuse. Passing these checks does not remove
the documented limitations above.

Use the [installation guide](https://github.com/den-run-ai/pystachy/blob/v0.1.0-alpha.4/docs/install.md)
for archives, checksums, Docker and source builds. Native compiler archives require LLVM 18
on Linux x86-64/ARM64 (glibc 2.39+) or LLVM 20 on macOS 15+ with Xcode Command Line Tools.
The Linux ARM64 archive target is `linux-aarch64`. Intel Mac builds remain available
as a secondary target. Manylinux and compiler pip/uv wheels are follow-up distribution
work; this release does not lower the Linux glibc baseline.
Ordinary compiled executables require neither Python nor LLVM; the explicit CPython bridge
retains its CPython dependency. Prereleases do not advance `latest`.

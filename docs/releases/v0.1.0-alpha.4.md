**Preparation draft; alpha.4 has not been published.** The
[release tracker](https://github.com/den-run-ai/pystachy/issues/976) records the remaining
correctness, performance and verification gates. Versioned links below are intended for
the eventual release tag.

Pystachy compiles a subset of Python to native code through LLVM: `pystachy run` for JIT
execution and `pystachy build` for standalone executables. This fourth alpha adds experimental
arbitrary-precision integers, expands dynamic iteration and numeric protocols, and includes
an adapted in-memory JSON-repair library since
[v0.1.0-alpha.3](https://github.com/den-run-ai/pystachy/releases/tag/v0.1.0-alpha.3).

**Pystachy remains experimental. Promoting integers and dynamic `Any` are separate opt-ins;
neither is enabled by default.** Documented correctness gaps and performance regressions remain.
Most PyPI packages do not compile unchanged.

## Highlights

- **Integers beyond 64 bits.** A module beginning with `# pystachy: python-int` can promote
  integer arithmetic beyond signed 64-bit range, using native scalar fast paths while values
  fit. Supported parameters, returns, fields, closures, fixed tuples, integer containers and
  generator yield/return channels preserve large values. Exact integer/float comparisons,
  true division, parsing, formatting and modular powers are included. Other modules retain
  checked 64-bit integers; the [boundary reference](https://github.com/den-run-ai/pystachy/blob/v0.1.0-alpha.4/docs/python-int.md#64-bit-boundaries)
  lists remaining narrowing points. The separate experimental
  [`mpz` API](https://github.com/den-run-ai/pystachy/blob/v0.1.0-alpha.4/docs/mpz.md)
  provides explicit arbitrary-precision values without opting an entire module in.
- **Dynamic iteration and generators.** `Any` can hold ranges, supported builtin/user
  iterators and generators with boxable yields. Loops, `iter()`, `next()`, supported
  `reversed()` calls and consuming builtins retain lazy advancement and shared iterator state
  ([#951](https://github.com/den-run-ai/pystachy/pull/951)). Typed/dynamic generator crossings
  preserve yield, send and return channels separately, including boxed `None`; compatible
  fresh list yields can adopt the caller's layout without copying existing mutable aliases
  ([#950](https://github.com/den-run-ai/pystachy/pull/950)). This does not add generator
  `send`/`throw`/`close` calls through `Any` or legacy `__getitem__` iteration.
- **Dynamic numeric protocols.** `int()` and `float()` use supported boxed-object conversion
  methods and their `__index__` fallback. Builtin indexing and slicing also accept supported
  boxed index objects, preserving conversion order and exceptions
  ([#949](https://github.com/den-run-ai/pystachy/pull/949)). Dynamic integers still use the
  signed-64-bit representation; this is separate from promoting integers.
- **Comparison and identity fixes.** More cross-type comparison bodies execute their helpers,
  callbacks and missing-field writes. Numeric identities survive supported typed calls,
  defaults, instance fields and numeric-list operations. Remaining unsupported comparison
  bodies can still be skipped, and some typed-container crossings still lose identity;
  see [the dynamic contract](https://github.com/den-run-ai/pystachy/blob/v0.1.0-alpha.4/docs/dynamic-any.md#deviations).
  Chained comparisons whose link always raises now compile and preserve the first exception
  ([#911](https://github.com/den-run-ai/pystachy/pull/911)).
- **Adapted `json_repair` 0.64.1.** The maintained ports package adds in-memory `loads()` and
  `repair_json()` without embedded CPython. Schema/Pydantic support, files and the CLI are
  excluded. The 645-case replay matches pristine upstream in all cases on CPython and in
  644 cases under native JIT/AOT, including per-allocation GC stress; the remaining case
  exceeds the native JSON integer range. Bounded string accumulation removes repeated
  growing-prefix copies, with measured memory and cross-engine tradeoffs. See the
  [port scope](https://github.com/den-run-ai/pystachy/blob/v0.1.0-alpha.4/ports/json_repair/PORT.md)
  and [measurements](https://github.com/den-run-ai/pystachy/blob/v0.1.0-alpha.4/bench/json_repair/ACCUMULATOR.md).
- **Compatibility checks.** A maintained promoting-integer corpus sweep checks output and
  exact expected failures rather than assuming an opt-in preserves compatibility. Added
  CPython-derived `shlex` and `posixpath` cases extend the differential corpus. These are
  adapted tests, not the complete CPython test suite.

## Performance and remaining release risks

The [28 October sweep](https://github.com/den-run-ai/pystachy/blob/v0.1.0-alpha.4/docs/reports/release-sweep-2026-10-28.md)
compared alpha.3 with main at `2eb0f36e` on one shared Linux host, using interleaved,
CPU-pinned runs. These historical measurements predate the preparation fixes and do not
describe a final release commit:

| Workload | Measured change from alpha.3 | Scope |
|---|---|---|
| Typed numeric field loop after importing `tomllib` | About 11× slower | Whole-program numeric identity companions affect callers that do not opt in ([#969](https://github.com/den-run-ai/pystachy/issues/969)). |
| Opt-in dynamic `json.loads` benchmark | 1.56× slower AOT; 1.75× slower JIT | Typed `JSONValue` decoding was unchanged in the sweep. |
| AOT build of the `richards` benchmark | About 26% longer | Re-optimizing the larger runtime affects ordinary typed programs too ([#706](https://github.com/den-run-ai/pystachy/issues/706)). |
| Hello-world executable | 45% larger | Historical comparison: 28,648 to 41,408 bytes on that toolchain. |

Follow-up measurements on pinned candidate trees separate demonstrated improvements from
remaining release blockers:

| Candidate and workload | Follow-up result | Remaining limit |
|---|---|---|
| #974: typed field loop with `tomllib` | About 5.2× faster than main `5bd492b3`, but still 1.84× slower than alpha.3 | #969 remains a release blocker. |
| #974: opt-in `json.loads` | AOT and warm-JIT loops 20.4% and 32.6% faster than main `5bd492b3` | AOT remains slower than alpha.3 in all seven pairs; the median paired overhead is 7.2%, with uncertain magnitude. Warm-JIT differences from alpha.3 are inconclusive. |
| #973: the same typed field loop | Within alpha.3's measured range | Required CI exposes a pre-existing promoting-int/`Any` identity wrong result; the candidate remains excluded from integration until fixed. |
| #975: four plain AOT programs | Executables 12.6–29.3% smaller than main `5bd492b3`; spectral and richards builds 19.3% and 17.6% faster, with separated sample ranges | The opt-in text executable grows 2.2%; its timing differences are inconclusive. This is partial mitigation for #706. |

The [identity-scope report](https://github.com/den-run-ai/pystachy/blob/v0.1.0-alpha.4/docs/reports/identity-scope-performance-2026-10-28.md),
[JSON report](https://github.com/den-run-ai/pystachy/blob/v0.1.0-alpha.4/docs/reports/json-loads-performance-2026-10-28.md)
and [AOT report](https://github.com/den-run-ai/pystachy/blob/v0.1.0-alpha.4/docs/reports/aot-plain-runtime-2026-10-28.md)
record sources, samples, ranges and reproduction inputs. These candidate measurements do not
certify the final combined source or clear its CI requirements. No execution regression was
confirmed in the bounded AOT comparison; that is not a claim about all workloads.

Other pyperformance changes did not separate reliably from host noise. The original sweep did not
measure warm JIT-cache reuse or broad retained-memory behavior. The JSON-repair accumulator's
targeted improvement does not establish a general application speedup.

## Known issues and workarounds

| Area | Remaining behavior | Practical route |
|---|---|---|
| Promoting integers | A module cannot also opt into dynamic `Any`. Many mixed-container, library, index and FFI boundaries still narrow to 64 bits; some values accepted by CPython raise `OverflowError` or are rejected during compilation. Integer `is` is rejected in an opted-in module. Passing an in-range promoting integer to a different dynamic module can lose alias identity while converting it to `Any`. | Follow the [promoting-int boundary list](https://github.com/den-run-ai/pystachy/blob/v0.1.0-alpha.4/docs/python-int.md#64-bit-boundaries); keep unsupported operations in CPython. |
| Dynamic comparisons and identity | Unsupported cross-type comparison bodies can still lose their effects, results or exceptions. Numeric identity remains incomplete through typed tuple/dict/set items, optional/union list items and typed generator yields. | Use supported typed paths or CPython for comparison-sensitive code. Check effects and first exceptions as well as final values ([#803](https://github.com/den-run-ai/pystachy/issues/803), [#858](https://github.com/den-run-ai/pystachy/issues/858)). |
| Typed length hints | `list()` and `sorted()` can propagate a `TypeError` from an optional user `__len__` where CPython ignores the hint. | Avoid a failing optional hint or use CPython for that conversion ([#94](https://github.com/den-run-ai/pystachy/issues/94)). |
| Private names | Class-private names are not mangled; attribute access can differ silently from CPython. | Use explicit nonprivate field names in compiled code or retain the affected classes in CPython ([#151](https://github.com/den-run-ai/pystachy/issues/151)). |
| JSON | Native JSON integers remain signed 64-bit and nesting is limited to 256 containers. File APIs, hooks and indentation remain unsupported. Callback-driven structural dict mutations can encode differently from CPython. | Validate size/depth and keep dict structure stable during callbacks; use CPython outside the documented [JSON scope](https://github.com/den-run-ai/pystachy/blob/v0.1.0-alpha.4/docs/json-prototype.md). |
| Platform coverage | Full differential verification uses LLVM 18 on Linux. macOS LLVM 20 receives installation/package JIT/AOT/GC smoke coverage. | Verify applications on their deployment platform ([#708](https://github.com/den-run-ai/pystachy/issues/708)). |

Unsupported native features still include multiple inheritance, `async`/`await`, `match`,
`bytearray` and binary filesystem I/O. Concrete annotations can introduce runtime type
checks absent from CPython. Opt-in corpus exceptions remain explicit compatibility gaps,
not parity passes. The [language compatibility reference](https://github.com/den-run-ai/pystachy/blob/v0.1.0-alpha.4/docs/language/compatibility.md)
and [library guide](https://github.com/den-run-ai/pystachy/blob/v0.1.0-alpha.4/lib/README.md)
define the supported scope.

## Verification and installation

The [release tracker](https://github.com/den-run-ai/pystachy/issues/976) records preparation
blockers and the final source. Publication requires CI, Installation, Lint and Packages to
pass on that exact release commit. Compiler/runtime bootstraps must reach byte-identical fixed points. Native archives
are built and smoke-tested on Linux x86-64 and macOS arm64/x86-64; Docker is Linux amd64.
Package checks cover relocation, external caching, normal/GC-stressed JIT and AOT,
JSON/Unicode behavior and warm runtime-cache reuse. Passing these checks does not remove
the documented limitations above.

Use the [installation guide](https://github.com/den-run-ai/pystachy/blob/v0.1.0-alpha.4/docs/install.md)
for archives, checksums, Docker and source builds. Native compiler archives require LLVM 18
on Linux x86-64 (glibc 2.39+) or LLVM 20 on macOS 15+ with Xcode Command Line Tools.
Ordinary compiled executables require neither Python nor LLVM; the explicit CPython bridge
retains its CPython dependency. Prereleases do not advance `latest`.

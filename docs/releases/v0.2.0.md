Pystachy compiles a typed subset of Python to native code through LLVM. This
pre-1.0 release improves compiler correctness and expands the library subset
for command-line tools and data processing. Dynamic `Any` and promoting integers
remain experimental and opt-in.

## Compiler and runtime

- Private names follow Python's class-name mangling rules. Native stack checks
  bound recursive calls, and promoting integers work across more builtins and
  container operations ([correctness changes](https://github.com/den-run-ai/pystachy/pull/1058)).
- Generic class declarations wait for dependencies, and recursive uses reuse the
  same specialization. Typed IR list checks and pass contracts are shared by
  more compiler paths ([generics](https://github.com/den-run-ai/pystachy/pull/1056),
  [typed IR](https://github.com/den-run-ai/pystachy/pull/1055)).
- With dynamic `Any` enabled, a native `list[int]` keeps its identity and storage
  when passed to `Any`. Mutations through the dynamic alias enforce the native
  integer contract ([list boundary](https://github.com/den-run-ai/pystachy/pull/1057)).

## Libraries and workflows

- Install the hosted compiler from a pinned GitHub revision with pip or uv
  ([source installation](https://github.com/den-run-ai/pystachy/blob/v0.2.0/docs/install.md#install-from-github-with-pip-or-uv)).
- Checked `argparse` declarations cover common options, conversions, defaults,
  help and errors. The native JSON repair CLI exercises parsing, file I/O, repair,
  and output. The library also expands binary I/O, logging, copy, pathlib, glob
  and shutil ([argparse](https://github.com/den-run-ai/pystachy/pull/1059),
  [binary files](https://github.com/den-run-ai/pystachy/pull/1049),
  [library additions](https://github.com/den-run-ai/pystachy/pull/1047)).
- Compiler-known `Enum`, `IntEnum`, `StrEnum`, `Flag` and `IntFlag` declarations
  cover more member and mask cases. The compiler also supports a limited
  method-only secondary base. General multiple inheritance and dynamic enum
  construction remain outside the supported subset
  ([flags](https://github.com/den-run-ai/pystachy/pull/1072),
  [inheritance](https://github.com/den-run-ai/pystachy/pull/1068)).
- The adapted `json_repair` port includes a standalone CLI and a locally built
  Linux x86-64 companion wheel for CPython. The native extension matched all
  645 cases in the pinned upstream corpus in the recorded verification. The
  wheel was exercised on CPython 3.12 and 3.13 and installs the
  `pystachy_json_repair` API and `json-repair-native` command
  ([verification](https://github.com/den-run-ai/pystachy/pull/1073),
  [wheel](https://github.com/den-run-ai/pystachy/pull/1076)).
- Work on mypy's stub generator and mypyc's name generator led to two general
  optimizations. Regex matching can reject a missing literal prefix early, and
  joining a contiguous string-list slice can avoid copying it. The experiments
  cover selected components of mypy and mypyc
  ([regex](https://github.com/den-run-ai/pystachy/pull/1066),
  [string joins](https://github.com/den-run-ai/pystachy/pull/1065)).

## Compatibility evidence

The [compatibility census](https://github.com/den-run-ai/pystachy/pull/1062)
records the evidence and its scope. All 24 adapted pyperformance workloads
matched CPython in JIT and AOT. The pinned 11-package execution sample matched
4/11 imports, 3/12 API calls and 1/2 workflows. Those results are separate from
root-wheel import compilation and selected CPython test-method coverage.
The [annotation-widening gate](https://github.com/den-run-ai/pystachy/pull/1061)
first checks transformed programs on CPython and then checks their native results.

## Known limits

The parser requires literal schemas. General multiple inheritance, dynamic enum
construction, and some typed/dynamic identity boundaries remain outside the
verified subset. See the [language compatibility guide](https://github.com/den-run-ai/pystachy/blob/v0.2.0/docs/language/compatibility.md)
and [standard library guide](https://github.com/den-run-ai/pystachy/blob/v0.2.0/docs/stdlib.md)
for supported APIs and limits.

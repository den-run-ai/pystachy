Pystachy v0.4.0-rc.2 continues the frozen v0.4.0 feature set with corrections to integer
enum exit statuses, generator checks and generic annotations. Whole-string
prefix and suffix tests avoid redundant code-point counting. Pystachy remains an
experimental compiler for a typed subset of Python.
The features and earlier repairs are described in the
[RC.1 notes](https://github.com/den-run-ai/pystachy/releases/tag/v0.4.0-rc.1).

## Integer enum exit statuses

`sys.exit()` and `SystemExit` use an `IntEnum`, `IntFlag` or integer-mixin enum member's
stored integer as the process status. Previously, supported programs could print the
member and exit with status 1, including a member whose integer was zero. The correction
also covers base-typed views, computed flags, aliases and `SystemExit` subclasses.
[#1392](https://github.com/den-run-ai/pystachy/pull/1392)

The status comes from the integer recorded when the member was created. Overridden
`__index__()` or `__int__()` methods and later changes to `_value_` do not alter it. The
compiler's stored integer is hidden from ordinary attribute lookup and reflection.
Noninteger enums and ordinary objects retain their message-based exit behavior.

Exception arguments retain the documented construction-time formatting behavior. In
particular, a custom `__str__()` can run earlier than it does in CPython when an exception
value is constructed. This release does not introduce general dynamic-`Any` support for
integer enum objects.
[Enum contract](https://github.com/den-run-ai/pystachy/blob/v0.4.0-rc.2/lib/compatibility.md),
[exception contents](https://github.com/den-run-ai/pystachy/blob/v0.4.0-rc.2/docs/language/compatibility.md#exception-contents)

## Compiler corrections

- Generators yielding a narrowed union member pass the IR checker, which now interprets
  the yielded bits as the generator's element type. Mismatched or unguarded payloads
  still fail verification. Generated program behavior is unchanged.
  [#1411](https://github.com/den-run-ai/pystachy/pull/1411)
- A function annotation such as `Box[int]` no longer compiles the generic class's
  special methods before module globals are declared. Its `__repr__` and `__str__`
  can read those globals, including through imported class aliases. Default-expression
  evaluation and checks for unbound globals are preserved.
  [#1418](https://github.com/den-run-ai/pystachy/issues/1418)

## String prefix and suffix tests

Whole-string `startswith()` and `endswith()` compare bytes without first counting every
code point. Partial and negative bounds retain code-point indexing. Regression checks
cover Unicode, empty needles, extreme bounds and the absence of unnecessary counting.
The separate GC cost in the historical words benchmark remains unresolved.
[#1332](https://github.com/den-run-ai/pystachy/pull/1332),
[#1301](https://github.com/den-run-ai/pystachy/issues/1301)

## Qualification and remaining work

Regression coverage checks normal and GC-stressed JIT/AOT behavior, stored and caught
exceptions, immutable exit values, reflected attributes and noninteger message controls.
The compiler comparison and complete platform GC matrix are qualified separately for
this candidate. The release tracker records source identities and validation evidence.
[#1186](https://github.com/den-run-ai/pystachy/issues/1186)

Stable-release qualification still requires the repeated CI headroom and GC scaling
criteria. Passing one release's jobs does not establish those requirements.
[#1178](https://github.com/den-run-ai/pystachy/issues/1178),
[#1179](https://github.com/den-run-ai/pystachy/issues/1179),
[#1181](https://github.com/den-run-ai/pystachy/issues/1181)

Dynamic `Any` and promoting integers remain experimental opt-ins. Pre-existing limitations
include promoting-integer tuple membership, class reads through circular-import aliases,
missing `ImportError` for circular from-imports of unbound names, and closed standard
streams. The circular from-import correction also needs preservation of optional-import
handlers and remains separate work.
[#1398](https://github.com/den-run-ai/pystachy/issues/1398)

Async and broader language-composition, inference and native
packaging changes remain separate work.
[Compatibility reference](https://github.com/den-run-ai/pystachy/blob/v0.4.0-rc.2/docs/language/compatibility.md)

## Platforms

| Native archive | Requirements |
|---|---|
| Linux x86-64 / AArch64 | Ubuntu 24.04 or compatible glibc 2.39+ Linux; LLVM 18 |
| macOS arm64 / x86-64 | macOS 15+, Xcode Command Line Tools; LLVM 20 |

Archives and Docker run without Python; the hosted compiler needs Python 3.11+. Full
verification targets Linux x86-64 and ARM64 with CPython 3.13.16. macOS has narrower
installation and release coverage, with Intel macOS secondary. Linux archives are not
manylinux packages.

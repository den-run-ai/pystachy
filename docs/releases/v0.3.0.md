Pystachy v0.3.0 improves compiler foundations and extends bounded language and
native interoperability support. Pystachy remains an experimental compiler for a
typed subset of Python.

- Preserve list lengths and read effects in typed IR, prove selected loop bounds,
  and index exception bindings once per function.
- Reduce selected tuple, optional-scalar and large-literal allocations and LLVM
  text construction. Shared class-name tables avoid repeated inherited-field
  error paths while preserving concrete diagnostics.
- Cache eligible native Linux ORC programs with source, import, compiler/runtime
  and toolchain validation. Ineligible programs retain the ordinary execution path.
- Support canonical class values, exact-type reducer registries, bounded stored-class
  reconstruction and supported runtime argument packs in Dynamic `Any`.
- Add static ctypes declarations over native FFI, retained CPU buffers for embedded
  CPython and an optional DLPack CPU bridge using NumPy in the host.
- Generate guarded, precompiled callback variants with a generic fallback; move
  nine helpers into the compiled subset runtime; add opt-in LLVM source-line tables.
- Add byte-BPE, dense-ID filtering and raylib GUI examples. Preserve optional tuple
  identity, multilingual JSON-repair content and efficient text-read behavior.

Dynamic `Any` and promoting integers remain experimental opt-ins. Interoperability
and GUI APIs are bounded; they do not provide complete ctypes, DLPack or copyreg
compatibility. Callback specialization does not use online profiling or generate
new variants at run time. The existing collector and concurrency model remain;
general threading, native async and distributed execution are outside this release.
Performance depends on the workload; no release-wide BPE or microGPT speedup is
claimed.

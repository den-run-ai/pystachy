Pystachy v0.7.0-rc.1 freezes the v0.7.0 feature set for final qualification. Since alpha.3, objects of class templates read a class attribute's current value, an object of a `list` or `dict` subclass reaches another class's comparison method as itself again, and `NamedTuple` and integer or string enum classes that define only `__eq__` keep the builtin `!=`. Pystachy remains an experimental compiler for a typed subset of Python.

## Corrections since alpha.3

- Objects of a class template, and of a subclass of one, read a class attribute with its current value after the program rebinds it through the class, as in `Box.limit = 10` or `cls.limit += 1`, until they assign it themselves. Alpha.3 kept the original value. ([#1724](https://github.com/den-run-ai/pystachy/issues/1724), [#1726](https://github.com/den-run-ai/pystachy/pull/1726), [#1727](https://github.com/den-run-ai/pystachy/pull/1727), [typing](https://github.com/den-run-ai/pystachy/blob/v0.7.0-rc.1/docs/language/typing.md))
- Compared with an object whose class defines `__eq__`, `__ne__` or an ordering method, an object of a `list` or `dict` subclass is that method's argument as it is, in either operand order: `isinstance(other, Stack)` holds there and `type(other)` is `Stack`. Alpha.3 passed a plain `list` or `dict` and printed wrong results for programs that alpha.2 rejected. ([#1739](https://github.com/den-run-ai/pystachy/issues/1739), [#1736](https://github.com/den-run-ai/pystachy/pull/1736))
- A `NamedTuple`, `IntEnum`, `IntFlag` or `StrEnum` class that defines `__eq__` but not `__ne__` keeps the builtin `!=`, as CPython does: `Pair(1) != ""` is `True`. Previously `!=` inverted the class's `__eq__`. ([#1738](https://github.com/den-run-ai/pystachy/pull/1738))
- The `threading` module's dynamic `Any` opt-in is recorded as a contract, with a test of the timers and argument packs that need it. ([#1734](https://github.com/den-run-ai/pystachy/pull/1734), [dynamic Any boundaries](https://github.com/den-run-ai/pystachy/blob/v0.7.0-rc.1/docs/dynamic-any-boundaries.md))

## Features carried from the alphas

- **Classes and typed IR:** nested and local classes, subclasses of `list`, `dict` and `collections.abc` classes, `__getattr__`, `int` where `float` is annotated, most of `enum`, and the typed IR as a checked text form with source locations. [Alpha.1](https://github.com/den-run-ai/pystachy/releases/tag/v0.7.0-alpha.1)
- **WebAssembly and installation:** an experimental WebAssembly target for snippets from a source checkout, fewer library modules that need dynamic `Any`, and `pystachy doctor`. [Alpha.2](https://github.com/den-run-ai/pystachy/releases/tag/v0.7.0-alpha.2)
- **Errors, templates and verification:** CPython-style tracebacks in executables, subclasses of class template specializations, tuples in closed unions, `==` that falls back to the reflected method and identity, `pystachy check --semantic`, generators and callbacks in the direct Wasm backend, and more typed IR verifier checks. [Alpha.3](https://github.com/den-run-ai/pystachy/releases/tag/v0.7.0-alpha.3)

## Known limits

Dynamic `Any` and promoting integers remain experimental opt-ins, and the WebAssembly target runs only from a source checkout. Known issues that predate the alphas include star imports from packages without a top-level export list ([#1513](https://github.com/den-run-ai/pystachy/issues/1513)), reads of a builtin's name where a module global of that name is unbound ([#1512](https://github.com/den-run-ai/pystachy/issues/1512)), an `except` clause's `as` name that an import bound ([#1514](https://github.com/den-run-ai/pystachy/issues/1514)) and `isinstance()` tests against a second base class ([#1602](https://github.com/den-run-ai/pystachy/issues/1602)).

The verifier's allocation cost under GC stress and the remaining Lean report rejections are still tracked ([#1644](https://github.com/den-run-ai/pystachy/issues/1644), [#1643](https://github.com/den-run-ai/pystachy/issues/1643)). The [compatibility reference](https://github.com/den-run-ai/pystachy/blob/v0.7.0-rc.1/docs/language/compatibility.md) lists the documented deviations.

Moving the list and string core into `runtime.py`, `Protocol` and `object` storage, and the portable LLVM download wait for 0.8.0. Fixes found after this candidate ship in a second candidate or in v0.7.0.

## Platforms

| Native archive | Requirements |
|---|---|
| Linux x86-64 / AArch64 | Ubuntu 24.04 or compatible glibc 2.39+ Linux; LLVM 18 |
| macOS arm64 / x86-64 | macOS 15+, Xcode Command Line Tools; LLVM 20 |

Archives and Docker run without Python; the hosted compiler needs Python 3.11+ and reports `commit unknown` when installed with pip. Full verification targets Linux x86-64 and ARM64 with CPython 3.13.16. Linux archives are not manylinux packages. This prerelease keeps the stable defaults at v0.6.1.

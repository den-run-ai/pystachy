Pystachy v0.6.0 compiles more of the Python found in typed code such as mypy's: classes as
values, objects beside numbers and strings in unions, more inferred field types, `bytearray`
and more of the standard library. It also runs `unittest` suites natively and repairs
results that v0.5.0 got wrong. Pystachy remains an experimental compiler for a typed subset
of Python.

## Classes, unions and generics

- `type[C]` holds the class object of `C` or a subclass in variables, fields and
  containers. Class objects answer `isinstance()` and `issubclass()`, construct objects
  and call class and static methods; `type[object]` also holds builtin classes such as `int`.
  ([alpha.2](https://github.com/den-run-ai/pystachy/releases/tag/v0.6.0-alpha.2))
- A union may hold `int`, `float`, `bool` or `str` beside objects of the program's classes,
  and runtime-length tuples hold objects. `isinstance()`, `callable()`, `None` and truth
  tests of `x.a` narrow the reads that follow.
- A class may have several method-only secondary bases, such as mypyc traits, take type
  variables from its bases and derive from `Iterator[...]`. `TypeVar` takes bounds and
  constraints, and enum members may come from `__new__` and run `__init__`.

## Inference and the language

- Fields take their types from more expressions, such as `and` and `or` operands,
  comprehensions, module globals and other classes' attributes. Annotations read
  `Literal[...]`, `TypeGuard`, `TypeIs`, `TYPE_CHECKING` imports and `NewType`.
  ([alpha.1](https://github.com/den-run-ai/pystachy/releases/tag/v0.6.0-alpha.1))
- An `int` argument may reach a `float` parameter of a function called directly. Its body
  computes with `int` operations, as CPython's does, under Pystachy's 64-bit integer limits.
  ([#1533](https://github.com/den-run-ai/pystachy/pull/1533))
- Sequence patterns match lists, with starred names. Subscripts, slices, `range()` and `%`
  formatting ask objects for `__index__()`, `%(name)s` formats a mapping, and dict `keys()`
  and `items()` views act as sets in `in` and comparisons.
- `bytearray` supports indexing, slicing, slice assignment and its in-place methods;
  library functions still take `bytes`.
  ([#1478](https://github.com/den-run-ai/pystachy/pull/1478))

## Standard library

- New: `pprint`, `inspect.Signature`, `subprocess` over fork and exec,
  `importlib.resources`, `importlib.metadata`, `sysconfig`, `platform`, `base64` and `gc`.
  `concurrent.futures` runs a `ThreadPoolExecutor` on the program's one thread.
  ([library reference](https://github.com/den-run-ai/pystachy/blob/v0.6.0/lib/README.md))
- `functools.cached_property` and `total_ordering`, `contextlib.ExitStack` and modules'
  `__file__` are available. `decimal` adds `exp()`, `ln()`, `log10()` and `Decimal` powers,
  rounded as libmpdec rounds them, and `str` case methods follow CPython's Unicode rules.
  ([limits](https://github.com/den-run-ai/pystachy/blob/v0.6.0/lib/compatibility.md))

## Testing and performance

- The native pytest runner runs `unittest.TestCase` classes, layered `conftest.py` files,
  marks, `-k` and `-m`, fixture scopes and parameters, `tmp_path`, `capsys`, `capfd` and
  `monkeypatch`. ([#1287](https://github.com/den-run-ai/pystachy/pull/1287))
- `str` case methods and character tests read generated Unicode tables, taking 0.3 to 1.9
  times CPython's time on Russian, Chinese and French text
  ([measurements](https://github.com/den-run-ai/pystachy/blob/v0.6.0/bench/unicode_case/README.md)).
  Float powers, rounding, `%`, `//` and comparisons of ints with floats run inline.
- As opt-ins, `PYSTACHY_JIT_OPT=2` runs LLVM's -O2 pipeline in the JIT, and
  `PYSTACHY_PROFILE_GENERATE` and `PYSTACHY_PROFILE_USE` build an executable from a profile
  of its own runs. The `PYSTACHY_UNICODE_AUDIT` setting is removed.

## Correctness repairs

Programs that v0.5.0 compiled now do what CPython does:

- `==` and `!=` between a value of a union of classes and an object compare the object, by
  its class's `__eq__` or by identity, where v0.5.0 could print `False` for equal objects.
  ([fix](https://github.com/den-run-ai/pystachy/commit/20e1ff25b9d849b50067c704248921b14dcbc7f4))
- `x += y` through a value typed with a base class calls the in-place method of the
  object's subclass. Where the results have no common type, the program is rejected.
  ([#1538](https://github.com/den-run-ai/pystachy/issues/1538))
- A dict lookup whose key's `__eq__` removes and stores its entry again finds it where it
  moved, where v0.5.0 could write outside the dict.
  ([#1580](https://github.com/den-run-ai/pystachy/issues/1580))
- On Linux AArch64, the collector scans the registers saved above `main`'s frame, where a
  live object could be freed. ([#1553](https://github.com/den-run-ai/pystachy/pull/1553))
- Host paths such as `sys.prefix` keep their non-ASCII characters and undecodable bytes,
  and with dynamic `Any`, ranges answer `isinstance()` and `==` as CPython does.
  ([#1517](https://github.com/den-run-ai/pystachy/issues/1517),
  [#1523](https://github.com/den-run-ai/pystachy/issues/1523),
  [#1595](https://github.com/den-run-ai/pystachy/pull/1595))

## Known limits

Dynamic `Any` and promoting integers remain experimental opt-ins. Known issues include
reads of a builtin's name where a module global of that name is unbound
([#1512](https://github.com/den-run-ai/pystachy/issues/1512)), star imports from a module
that binds `__all__` inside `try` or `if`
([#1513](https://github.com/den-run-ai/pystachy/issues/1513)), `isinstance()` of `Any`
values that hold `NamedTuple` objects
([#1581](https://github.com/den-run-ai/pystachy/issues/1581)) and `isinstance()` tests
against a second base class ([#1602](https://github.com/den-run-ai/pystachy/issues/1602)).
The
[compatibility reference](https://github.com/den-run-ai/pystachy/blob/v0.6.0/docs/language/compatibility.md)
lists the documented deviations.

Mapping patterns, async, full native mypy and broad concurrency remain outside v0.6.0.

## Platforms

| Native archive | Requirements |
|---|---|
| Linux x86-64 / AArch64 | Ubuntu 24.04 or compatible glibc 2.39+ Linux; LLVM 18 |
| macOS arm64 / x86-64 | macOS 15+, Xcode Command Line Tools; LLVM 20 |

Archives and Docker run without Python; the hosted compiler needs Python 3.11+ and reports
`commit unknown` when installed with pip. Full verification targets Linux x86-64 and ARM64
with CPython 3.13.16. Linux archives are not manylinux packages.

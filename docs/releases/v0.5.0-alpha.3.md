Pystachy v0.5.0-alpha.3 expands numeric protocols, complex numbers and container keys,
adds a bounded Decimal implementation, and improves generic constructors and numeric
identity across typed and dynamic code. It remains an experimental compiler for a typed
subset of Python.

## Constructors and value identity

Classes with fixed field layouts can specialize their constructors independently,
including supported inheritance hierarchies and imported constructor dependencies.
Generic class checks agree across typed code, dynamic `Any` and helpers that do not
opt in. Unused classes retain lazy validation.
[#1493](https://github.com/den-run-ai/pystachy/pull/1493),
[generic classes](https://github.com/den-run-ai/pystachy/blob/v0.5.0-alpha.3/docs/language/typing.md#class-templates-and-generic-classes)

Numeric generator yields and runtime-length tuple items preserve their identities when
crossing into dynamic `Any`. Optional numeric lists and tuples preserve the corresponding
identities as well. The compiler records these companion reads and writes for its storage
checks; typed yields avoid allocating an identity box until a consumer needs one.
[#1486](https://github.com/den-run-ai/pystachy/pull/1486),
[#1491](https://github.com/den-run-ai/pystachy/pull/1491),
[boundary contract](https://github.com/den-run-ai/pystachy/blob/v0.5.0-alpha.3/docs/dynamic-any.md)

## Numeric protocols and Decimal

Objects can supply the supported conversion and rounding methods used by `int()`,
`float()`, `round()`, `math.floor()`, `math.ceil()` and `math.trunc()`. Builtin numbers
on the left can call supported reflected arithmetic methods, including IntEnum and
IntFlag members. Comparison methods can decline with `NotImplemented`, allowing the
next comparison candidate to run in Python's order.
[#1340](https://github.com/den-run-ai/pystachy/pull/1340),
[#1426](https://github.com/den-run-ai/pystachy/pull/1426),
[#1472](https://github.com/den-run-ai/pystachy/pull/1472)

Combined comparison checks cover declining user methods, nullable enum receivers and
Decimal/complex equality, including exact comparisons with the real float component.

The new `decimal` subset supports exact construction from strings, integers and floats;
context-rounded arithmetic; comparisons; hashing; formatting; `quantize()`; `sqrt()`;
integer powers; and all eight rounding modes. `Context`, `getcontext()` and
`localcontext()` expose the supported precision, rounding and exponent settings.
[#1341](https://github.com/den-run-ai/pystachy/pull/1341),
[library limits](https://github.com/den-run-ai/pystachy/blob/v0.5.0-alpha.3/lib/compatibility.md)

Decimal signal flags and configurable traps, transcendental functions, construction from
another Decimal, Decimal subclasses and `sum()` of Decimals remain unsupported. General
reflected arithmetic between two user objects and unrestricted uses of the
`NotImplemented` value remain outside this subset.

## Complex numbers

Imaginary literals, `complex()` and complex annotations work with arithmetic,
comparison, hashing, absolute values and formatting. Complex values also participate
in supported closed scalar unions and dynamic `Any`, with identities retained across
those boundaries. Arithmetic follows the CPython 3.13 algorithms, including their
IEEE exceptional values.
[#1408](https://github.com/den-run-ai/pystachy/pull/1408),
[#1409](https://github.com/den-run-ai/pystachy/pull/1409),
[#1421](https://github.com/den-run-ai/pystachy/pull/1421)

Ordering, floor division, modulo, attribute assignment and `sum()` of complex numbers
remain unsupported. Equal complex literals can be distinct objects, as documented;
the `cmath` module is not included.

## Container keys

Sets and dictionaries accept `None` and supported optional key types. Runtime-length
tuples of supported scalar items can be keys, and equal fixed and runtime-length tuples
find the same entry. Unions of ordinary classes can be keys when all possible classes
use identity hashing and equality.
[#1412](https://github.com/den-run-ai/pystachy/pull/1412),
[#1467](https://github.com/den-run-ai/pystachy/pull/1467),
[#1475](https://github.com/den-run-ai/pystachy/pull/1475)

Optional fixed-shape tuple keys preserve promoting integers through set algebra and
dictionary operations. Mixed object sets consistently support removing and discarding
`None`; missing `None` keys produce `KeyError` without dereferencing an absent object.

## Verification, limits and platforms

Expanded Lean boundary checks validate emitted class layouts, selected alias preservation
and collector trace edges, and numeric identity companions. These bounded models do not
prove general aliasing or collector correctness. Dynamic `Any` and promoting integers
remain experimental opt-ins; async, full native mypy and broad concurrency remain outside
this release.
[Verification scope](https://github.com/den-run-ai/pystachy/blob/v0.5.0-alpha.3/tools/lean_boundary/README.md)

Native archives target Linux x86-64/AArch64 with glibc 2.39+ and LLVM 18, and macOS
arm64/x86-64 with macOS 15+, Xcode Command Line Tools and LLVM 20. Linux archives
are not manylinux packages. Archives and Docker run without Python; the hosted compiler
needs Python 3.11+. This prerelease keeps stable defaults at v0.4.0.

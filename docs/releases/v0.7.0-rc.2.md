Pystachy v0.7.0-rc.2 is the second and last candidate for v0.7.0. Since rc.1, an object of a `list` or `dict` subclass reaches another class's comparison methods as itself where the whole program allows it, and ordering an integer or string enum member against an unrelated value raises CPython's `TypeError`. Pystachy remains an experimental compiler for a typed subset of Python.

## Corrections since rc.1

- An object of a `list` or `dict` subclass reaches another class's `__eq__`, `__ne__`, ordering method or reflected method as itself, as CPython passes it, when every such comparison in the program compiles with the object. Otherwise the whole program compiles as with rc.1, and those methods receive a plain `list` or `dict`. ([#1739](https://github.com/den-run-ai/pystachy/issues/1739), [#1736](https://github.com/den-run-ai/pystachy/pull/1736), [typing](https://github.com/den-run-ai/pystachy/blob/v0.7.0-rc.2/docs/language/typing.md))
- Ordering an `IntEnum`, `IntFlag` or `StrEnum` member against a value that `int` or `str` cannot order, such as a `list`, lets the other operand's reflected method answer, and otherwise raises CPython's `TypeError`, which names the operator as written and the operands in source order. Rc.1 named the reflected operator. ([#1745](https://github.com/den-run-ai/pystachy/issues/1745), [#1760](https://github.com/den-run-ai/pystachy/pull/1760))
- The WebAssembly command-line runner runs guests on a 256 MiB stack, so recursion that Python's limit allows no longer stops after about 11,000 frames. ([#1721](https://github.com/den-run-ai/pystachy/pull/1721))
- The program cache's test of line tables reads the cached executable's sections; since alpha.3 it had passed whether or not the entry had them. ([#1730](https://github.com/den-run-ai/pystachy/issues/1730))

## Features carried from the alphas

- **Classes and typed IR:** nested and local classes, subclasses of `list`, `dict` and `collections.abc` classes, `__getattr__`, `int` where `float` is annotated, most of `enum`, and the typed IR as a checked text form with source locations. [Alpha.1](https://github.com/den-run-ai/pystachy/releases/tag/v0.7.0-alpha.1)
- **WebAssembly and installation:** an experimental WebAssembly target for snippets from a source checkout, fewer library modules that need dynamic `Any`, and `pystachy doctor`. [Alpha.2](https://github.com/den-run-ai/pystachy/releases/tag/v0.7.0-alpha.2)
- **Errors, templates and verification:** CPython-style tracebacks in executables, subclasses of class template specializations, tuples in closed unions, `==` that falls back to the reflected method and identity, `pystachy check --semantic`, generators and callbacks in the direct Wasm backend, and more typed IR verifier checks. [Alpha.3](https://github.com/den-run-ai/pystachy/releases/tag/v0.7.0-alpha.3)

## Known limits

Two wrong results from alpha.3's class changes remain in part. A program in which any such comparison cannot compile with a `list` or `dict` subclass object passes a plain `list` or `dict` to all of them, and tuple searches compare such objects without calling the method ([#1739](https://github.com/den-run-ai/pystachy/issues/1739), [#1763](https://github.com/den-run-ai/pystachy/issues/1763)).

A class method that assigns `cls.x`, called through an object of a subclass of a class template, changes the base class's attribute instead of giving the subclass its own; called that way, a class method also gets the template as `cls`, so `cls.__name__` and `cls.x` read the template's ([#1744](https://github.com/den-run-ai/pystachy/issues/1744)).

Dynamic `Any` and promoting integers remain experimental opt-ins, and the WebAssembly target runs only from a source checkout. Known issues that predate the alphas include star imports from packages without a top-level export list ([#1513](https://github.com/den-run-ai/pystachy/issues/1513)), reads of a builtin's name where a module global of that name is unbound ([#1512](https://github.com/den-run-ai/pystachy/issues/1512)), an `except` clause's `as` name that an import bound ([#1514](https://github.com/den-run-ai/pystachy/issues/1514)) and `isinstance()` tests against a second base class ([#1602](https://github.com/den-run-ai/pystachy/issues/1602)).

The verifier's allocation cost under GC stress and the remaining Lean report rejections are still tracked ([#1644](https://github.com/den-run-ai/pystachy/issues/1644), [#1643](https://github.com/den-run-ai/pystachy/issues/1643)). The [compatibility reference](https://github.com/den-run-ai/pystachy/blob/v0.7.0-rc.2/docs/language/compatibility.md) lists the documented deviations.

Moving the list and string core into `runtime.py`, `Protocol` and `object` storage, and the portable LLVM download wait for 0.8.0.

## Platforms

| Native archive | Requirements |
|---|---|
| Linux x86-64 / AArch64 | Ubuntu 24.04 or compatible glibc 2.39+ Linux; LLVM 18 |
| macOS arm64 / x86-64 | macOS 15+, Xcode Command Line Tools; LLVM 20 |

Archives and Docker run without Python; the hosted compiler needs Python 3.11+ and reports `commit unknown` when installed with pip. Full verification targets Linux x86-64 and ARM64 with CPython 3.13.16. Linux archives are not manylinux packages. This prerelease keeps the stable defaults at v0.6.1.

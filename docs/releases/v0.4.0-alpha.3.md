Pystachy v0.4.0-alpha.3 adds checks and inspection reports for dynamic `Any` boundaries,
moves private TOML parser state to typed nodes and includes an optional native I/O
example. Pystachy is an experimental compiler for a typed subset of Python.

## Dynamic `Any` boundaries

- With `PYSTACHY_IRCHECK=1`, the IR verifier requires a tag guard before each reachable
  dynamic payload read, exact for `float`, `str` and `bool`, and `int` or `bool` for
  integers, tracking guards through copies, private slots, joins and loop back edges.
  Opaque identity payloads may only be compared for equality.
  [#1213](https://github.com/den-run-ai/pystachy/pull/1213),
  [#1227](https://github.com/den-run-ai/pystachy/pull/1227)
- Consistent private slot names stop assignment flags and numeric identity companions from
  colliding with value storage and rejecting valid programs. Slice bounds no longer read
  an integer payload from `None`, dynamic `sum()` checks its accumulator's tag first, and
  a stale boolean implication across loop phi assignments is fixed.
  [#1222](https://github.com/den-run-ai/pystachy/pull/1222),
  [#1227](https://github.com/den-run-ai/pystachy/pull/1227)
- Inspection reports show each compilation attempt's module identity policy, active or
  discarded identity-inert hints, full-graph fallback and exact crossing reason, with
  typed-IR footprint totals. They are static observations, not runtime costs or proof of
  minimal containment.
  [#1214](https://github.com/den-run-ai/pystachy/pull/1214),
  [inspection guide](https://github.com/den-run-ai/pystachy/blob/ad3d0c0eda3ccf2ae2a35d38c92f345205e853ab/docs/compiler-inspection.md#dynamic-boundaries-and-numeric-identity)
- The TOML parser keeps private namespace flags in typed nodes instead of dynamic
  dictionaries, reducing dynamic operations without changing results. The public
  `parse_float` boundary stays dynamic.
  [#1211](https://github.com/den-run-ai/pystachy/pull/1211),
  [measurements at their original commits](https://github.com/den-run-ai/pystachy/blob/ad3d0c0eda3ccf2ae2a35d38c92f345205e853ab/bench/toml_boundary/results/2026-11-09/README.md)
- An optional Lean 4.35.0 checker, a development dependency only, proves one selected
  function's payload guards from an inspection snapshot in a normalized tag-state model,
  including loops. It trusts the Python bridge's correspondence to the IR and does not
  cover the compiler's own guard analysis. The models are MIT-licensed.
  [#1212](https://github.com/den-run-ai/pystachy/pull/1212),
  [scope, provenance and trust limits](https://github.com/den-run-ai/pystachy/blob/ad3d0c0eda3ccf2ae2a35d38c92f345205e853ab/tools/lean_boundary/README.md)

These checks do not prove source-language or LLVM equivalence, runtime layout or lifetime
safety, GC correctness or complete identity containment. Inheritance and container
payloads still rely on frontend obligations, and integer and bool shared layouts are
checked by the verifier, not the Lean model.

## Optional native I/O example

`examples/netio` is a separately built C bridge for bounded IPv4 TCP, local socket pairs,
binary pipe reads and persistent readiness with Linux epoll or macOS kqueue. Resources have
explicit ownership and cleanup. The example adds no default dependency, does not implement
`socket`, `selectors` or `asyncio`, and is not bundled with archives, Docker images or the
PyPI compiler.
[#1145](https://github.com/den-run-ai/pystachy/pull/1145),
[contract and setup](https://github.com/den-run-ai/pystachy/blob/b220019d90a20d3a47584bddb6c172fa1facbc6e/examples/netio/README.md)

Its compiler-pipe consumers apply deadlines and output limits and are checked against the
standard library, including kqueue and pipe draining on macOS ARM64. Receives still copy
from native to managed memory, and selector file-object storage keeps an `Any` boundary
because of the `Socket | int` compiler limitation.
[#1156](https://github.com/den-run-ai/pystachy/pull/1156),
[#1161](https://github.com/den-run-ai/pystachy/pull/1161),
[#1216](https://github.com/den-run-ai/pystachy/pull/1216)

The example needs one owner thread; DNS, IPv6, UDP, TLS, Windows and general asynchronous
Python are outside its contract. The
[socket](https://github.com/den-run-ai/pystachy/blob/37a9db95268b767e75f05091c5a8946a42300c77/examples/netio/results/README.md)
and [drain](https://github.com/den-run-ai/pystachy/blob/37a9db95268b767e75f05091c5a8946a42300c77/examples/netio/results/2026-11-08-drain.md)
measurements are historical, with their original source, platform and workload limits.

## Known limits

- Identity comparisons of optional exception values (`BaseException | None`) can report
  `False` for the same exception in ordinary typed programs. The issue predates alpha.3; a
  checked accessor returning nonoptional `BaseException` preserves identity in the
  reported case. A fix is planned for alpha.4.
  [#1231](https://github.com/den-run-ai/pystachy/issues/1231)
- Closed standard streams differ from CPython in direct access and `print()`, and
  `input()` raises `EOFError` instead of `OSError` when stdin is open but not readable
  ([#1182](https://github.com/den-run-ai/pystachy/issues/1182)).
- Manually enabling promoting integers in `lib/_pystachy_bytescan.py` can produce invalid
  LLVM calls that the typed-IR verifier does not reject; the shipped helper's fixed-width
  parameters avoid this for normal callers
  ([#1207](https://github.com/den-run-ai/pystachy/issues/1207)).
- Dynamic `Any` and promoting integers remain experimental opt-ins; containment work
  continues in [#1210](https://github.com/den-run-ai/pystachy/issues/1210).
- Broader Lean bridge and descriptor-set proofs, a corpus-wide Lean gate, numeric
  value-only module policy, and PGO, native wheel, dictionary lookup and generated-code
  sanitizer prototypes are deferred to the next alpha. Libuv I/O, restricted numerical
  workers, general shared-heap threading and distributed execution are not included.
  [Release scope](https://github.com/den-run-ai/pystachy/issues/1186)

## Platforms

| Native archive | Requirements |
|---|---|
| Linux x86-64 | Ubuntu 24.04 or compatible glibc 2.39+ Linux; LLVM 18 |
| Linux AArch64 | Little-endian ARM64, Ubuntu 24.04 or compatible glibc 2.39+ Linux; LLVM 18 |
| macOS arm64 | Apple Silicon, macOS 15+, Xcode Command Line Tools; LLVM 20 |
| macOS x86-64 | Intel, macOS 15+, Xcode Command Line Tools; LLVM 20 |

Native archives and the Docker image run the compiler without Python; a source or hosted
installation needs Python 3.11+. Full verification runs on Linux x86-64 and ARM64 with
CPython 3.13.16. macOS has narrower installation and release coverage, and Intel macOS is
a secondary target.
[Installation policy](https://github.com/den-run-ai/pystachy/blob/37a9db95268b767e75f05091c5a8946a42300c77/docs/install.md)

LLVM 18 on Linux and LLVM 20 on macOS remain the defaults. Explicitly selected Linux LLVM
19–23 keeps the
[alpha.2 validation limits](https://github.com/den-run-ai/pystachy/blob/070c8137edeb610e11d8d81653e506ad64a9ce6d/docs/releases/v0.4.0-alpha.2.md#known-issues-and-experimental-scope):
LLVM 19 and 21, and other LLVM versions on macOS, are untested.

Pystachy v0.4.0-alpha.3 adds checks and inspection tools for dynamic `Any`
boundaries, replaces private TOML parser state with typed nodes, and includes an
optional native I/O source example. Pystachy remains an experimental compiler for
a typed subset of Python.

## Dynamic boundaries and compiler verification

- Store TOML namespace flags in typed recursive nodes with integer sets instead
  of dynamic dictionaries. Preserve the existing mutable parse results, callback
  order, exceptions, aliases and numeric identity. The public `parse_float`
  boundary remains open; this change reduces dynamic operations in private
  parser state without changing module identity-tracking scope or its fallback.
  [#1211](https://github.com/den-run-ai/pystachy/pull/1211)
- With `PYSTACHY_IRCHECK=1`, require an exact `float`, `str` or `bool` tag on each
  reachable typed dynamic-payload read of those types. Track guards through
  copies, private slots, joins and loop backedges. Keep opaque identity payloads
  separate from typed extraction, and restrict their uses to direct equality
  comparisons. Correct stale boolean implications across simultaneous loop-phi
  assignments in the shared proof machinery.
  [#1213](https://github.com/den-run-ai/pystachy/pull/1213)
- Add an optional Lean 4.35.0 checker for payload guards in one selected function
  from a completed inspection snapshot. Its theorem concerns the normalized
  tag-state model, including loops; the Python bridge and its correspondence to
  actual IR remain trusted. The compiler's own guard analysis is separate from
  this proof. Lean is a development dependency, not an installation or runtime
  dependency. The project's model and proofs are MIT-licensed; the external Lean
  toolchain retains its own license.
  [#1212](https://github.com/den-run-ai/pystachy/pull/1212),
  [scope, provenance and trust limits](https://github.com/den-run-ai/pystachy/blob/ad3d0c0eda3ccf2ae2a35d38c92f345205e853ab/tools/lean_boundary/README.md)
- Report the actual module identity policy, active or discarded identity-inert
  hints, full-graph fallback and exact crossing reason for each compilation
  attempt. Typed-IR footprint totals cover all generated functions independently
  of the snapshot filter. Failed or source-inconsistent attempts retain explicit
  partial/unavailable status. These are static observations, not runtime cost or
  proof of minimal containment.
  [#1214](https://github.com/den-run-ai/pystachy/pull/1214),
  [inspection guide](https://github.com/den-run-ai/pystachy/blob/ad3d0c0eda3ccf2ae2a35d38c92f345205e853ab/docs/compiler-inspection.md#dynamic-boundaries-and-numeric-identity)

The new checks do not establish source-language or LLVM equivalence, runtime
layout or lifetime safety, GC correctness, or complete identity containment.
Integer/bool shared layouts, inheritance and container payloads retain their
existing obligations. Dynamic `Any` and promoting integers remain experimental
opt-ins. The broader containment work in
[#1210](https://github.com/den-run-ai/pystachy/issues/1210) remains open.

## Optional native I/O example

- Add `examples/netio`, a separately built C bridge and source-checkout example
  for bounded IPv4 TCP, local socket pairs, binary pipe reads and persistent
  readiness with Linux epoll or macOS kqueue. Resources have explicit ownership
  and cleanup; the pipe consumer applies finite deadlines and output limits.
  This optional example adds no default dependency and does not implement the
  `socket`, `selectors` or `asyncio` standard-library modules. Native archives,
  Docker images and the installed PyPI compiler do not bundle the example.
  [#1145](https://github.com/den-run-ai/pystachy/pull/1145),
  [contract and setup](https://github.com/den-run-ai/pystachy/blob/37a9db95268b767e75f05091c5a8946a42300c77/examples/netio/README.md)
- Add compiler-pipe consumers with independent stdlib output/status comparisons,
  bounded process ownership and separate startup/transfer measurements. Batch
  drain fragments before their final join, bound fragment metadata and reject
  completions that arrive after the deadline. The extra native-to-managed receive
  copy remains. Selector file-object storage retains an `Any` boundary because
  the existing `Socket | int` compiler limitation prevents the typed replacement.
  [#1156](https://github.com/den-run-ai/pystachy/pull/1156),
  [#1161](https://github.com/den-run-ai/pystachy/pull/1161)
- Add current-compiler native checks and macOS ARM64 kqueue/pipe-drain coverage to
  existing verification jobs, retaining source-identified reports.
  [#1216](https://github.com/den-run-ai/pystachy/pull/1216)

The example requires one owner thread. DNS, IPv6, UDP, TLS, Windows and general
asynchronous Python execution remain outside its contract. The historical
[socket measurements](https://github.com/den-run-ai/pystachy/blob/37a9db95268b767e75f05091c5a8946a42300c77/examples/netio/results/README.md)
and [drain measurements](https://github.com/den-run-ai/pystachy/blob/37a9db95268b767e75f05091c5a8946a42300c77/examples/netio/results/2026-11-08-drain.md)
retain their original source, platform and workload limits; they are not new
alpha.3 timings or a general networking speedup claim.

## Platforms and toolchains

The distribution policy is unchanged:

| Native archive | Requirements |
|---|---|
| Linux x86-64 | Ubuntu 24.04 or compatible glibc 2.39+ Linux; LLVM 18 |
| Linux AArch64 | Little-endian ARM64, Ubuntu 24.04 or compatible glibc 2.39+ Linux; LLVM 18 |
| macOS arm64 | Apple Silicon, macOS 15+, Xcode Command Line Tools; LLVM 20 |
| macOS x86-64 | Intel, macOS 15+, Xcode Command Line Tools; LLVM 20 |

Docker targets Linux amd64/arm64 and includes LLVM 18. Native archives and Docker
run the compiler without Python. Source/hosted installation requires Python 3.11+;
recordings and full verification use pinned CPython 3.13.16. Full verification
runs on Linux x86-64 and ARM64. macOS has narrower installation and release-consumer
coverage, with Intel macOS a secondary target. See the
[installation policy](https://github.com/den-run-ai/pystachy/blob/37a9db95268b767e75f05091c5a8946a42300c77/docs/install.md).

Explicit Linux LLVM 19-23 selection retains the alpha.2 validation limits:
Linux x86-64 LLVM 23 has prior bootstrap/full differential evidence, and LLVM 20/22
have prior bootstrap/selected-test evidence. LLVM 19/21 and other LLVM releases
on macOS remain untested. Assertion-enabled LLVM 22/23 builds that reject the
generator intrinsic upgrade remain outside the verified configuration. CI and
distribution defaults remain LLVM 18 on Linux and LLVM 20 on macOS.
[Inherited toolchain evidence and limits](https://github.com/den-run-ai/pystachy/blob/070c8137edeb610e11d8d81653e506ad64a9ce6d/docs/releases/v0.4.0-alpha.2.md#known-issues-and-experimental-scope)

## Known issues and deferred work

- Closed standard streams retain documented differences in direct stream access
  and `print()`. When stdin is open but not readable, `input()` reports `EOFError`
  instead of CPython's `OSError`.
  [#1182](https://github.com/den-run-ai/pystachy/issues/1182)
- Manually enabling promoting integers in `lib/_pystachy_bytescan.py` can produce
  invalid LLVM calls that the typed-IR verifier does not reject. The shipped
  helper keeps fixed-width parameters, so normal opted-in callers do not trigger
  this configuration-specific gap. The new payload-guard checks do not resolve it.
  [#1207](https://github.com/den-run-ai/pystachy/issues/1207)
- Optional libuv I/O and restricted numerical-worker drafts are not included.
  They still require combined integration, ownership, cancellation, deadline,
  cleanup and platform evidence. General shared-heap threading and distributed
  execution remain outside this release.
  [Release scope](https://github.com/den-run-ai/pystachy/issues/1186)
- CI headroom remains tracked in
  [#1178](https://github.com/den-run-ai/pystachy/issues/1178),
  [#1179](https://github.com/den-run-ai/pystachy/issues/1179) and
  [#1181](https://github.com/den-run-ai/pystachy/issues/1181), with existing coverage
  and execution bounds retained.

The [Any-boundary integration evidence](https://github.com/den-run-ai/pystachy/pull/1215)
records its reviewed source and full-corpus comparison, including the narrowly
normalized ImportError checkout paths and the explained TOML/library-path changes.
The [TOML measurements](https://github.com/den-run-ai/pystachy/blob/ad3d0c0eda3ccf2ae2a35d38c92f345205e853ab/bench/toml_boundary/results/2026-11-09/README.md)
remain tied to their original measured commits. No release-wide performance
improvement is claimed.

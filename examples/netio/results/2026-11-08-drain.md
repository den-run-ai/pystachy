# Bounded drain accumulation and deadline checks

Measurements were collected on **November 8, 2026 UTC**, on Linux x86-64 with
CPython 3.13.16 and LLVM/Clang 18.1.3. This follow-up compares the original
`drain.py` from `b9ab8d9d3065b94c85952c79bada1de43a021c49` with the consumer that
batches fragments and checks elapsed deadlines across readiness processing.
The optional socket/selector wrapper, C bridge, compiler and runtime are unchanged.

## End-to-end replay

The [complete report](2026-11-08-drain-replay.json) preserves all samples, warmups,
source and executable hashes, compiler commands, payload hashes, descriptor
mappings, execution order, affinity and load. The final consumed consumer hash
matches both the initial source inventory and the source present after the run.

There are **seven measured samples per cell**, with one discarded warmup process
per cell. Each sample starts a fresh writer and consumer. All children inherit
logical CPU 0 affinity; before/after variants rotate within each payload case.
Other agents' heavy work was paused, but the host was shared. All 84 measured
samples passed exact stdout, stderr and exit-status comparison.

The compiler payload is actual `pystachy.py rt runtime.py` output, independently
captured once by the CPython-hosted compiler before timing. Its 579,360 bytes
match the runtime bootstrap IR hash. Every variant receives those same bytes.
The binary stream contains all byte values, including NUL and non-UTF-8 bytes.
CPython uses stdlib `os`/`selectors`; native AOT compiles the whole consumer with
the same optional `netio` wrapper and bridge for both revisions.

Times include writer and consumer startup, pipe I/O, buffering, hex encoding,
and parent capture/parsing. Compiler work, AOT builds, the final comparison with
the expected payload, final worker cleanup and copy-volume modeling are excluded.
These are end-to-end pipe-collection timings, not in-process socket throughput.

these results do not establish a compiler speedup or fix the earlier bulk socket
performance gap.

## Deterministic accumulation work

The original `pending[fd] += chunk` constructs a new bytes result for each
fragment. With equally sized fragments, the total native accumulation-copy
volume is the fragment size times `1 + 2 + ... + fragment_count`.
The replacement joins each batch of 256 once and joins those blocks at EOF.
No append recopies an earlier block. For the single final value used by `drain`,
each byte participates in at most two accumulation joins. Repeated standalone
`Output.value()` snapshots can of course copy the output again.

| Fixed input | Before modeled copy bytes | After modeled copy bytes | Before / after copy operations |
|---|---:|---:|---:|
| 4,096 one-byte fragments | 8,390,656 | 8,192 | 4,096 / 17 |
| 8 MiB in 8 KiB fragments | 4,299,161,600 | 16,777,216 | 1,024 / 5 |

These counters execute each consumer with deterministic reads and sized byte
proxies, counting complete native bytes-addition/join result lengths. They are
an algorithmic model, **not measured allocations, instructions or elapsed time**.
Actual pipe fragmentation can vary. Native read-buffer copies, metadata, GC and
hex encoding are excluded from the model. Real binary-data probes and replay
comparisons validate output independently.

The CI-discovered linear-copy test fails on the original consumer for both
inputs and passes after the change. Batching also prevents one-byte reads from
retaining millions of byte objects: there is at most one completed block per
256 payload bytes, plus an unfinished batch. This is a bound on retained
fragments, not a measured RSS reduction.

## Correctness and validation

Three deadline regressions failed before the fix: final EOF arriving after a
selector wait's deadline, an EOF read crossing the deadline, and expiry while
processing an earlier event in the same ready batch. They pass after checking
time before each event and after preparing an EOF message. No late completion
is emitted, and every owned descriptor closes. The launcher still bounds a
consumer stalled while writing its completion output.

An independent review also found a benchmark source-inventory race: a consumer
change between its snapshot and the initial inventory could falsely pass the
provenance check. Its controlled regression failed before the guard change and
passes now. Initial inventory and final source bytes must both match the exact
consumer snapshot used for compilation and replay.

Final validation:

- **48 focused harness tests**, covering linear-copy budgets, binary
  fragments, empty streams, exact output limits, one-byte overflow, would-block,
  read/deadline failures, process cleanup and source-inventory consistency.
- [Drain checks](2026-11-08-drain-checks.json) passed with the stdlib oracle,
  CPython bridge, JIT, AOT and both GC-stress modes. They exercise fragment-batch
  boundaries, immutable earlier snapshots, expired deadlines and completion order.
- [Real compiler collection](2026-11-08-drain-dogfood.json) passed all six modes,
  preserving IR, diagnostics and failed-worker status. Its durations are
  correctness-only and are not used as benchmark evidence here.
- Ruff passed for the entire netio example and its harness tests. Tests and
  probes use existing CI-discovered targets; no timing threshold or CI job was added.

## Reproduction and remaining cost

From a normal compiler checkout with pinned CPython and a matching LLVM toolchain:

```sh
mkdir -p build
git show b9ab8d9d3065b94c85952c79bada1de43a021c49:examples/netio/drain.py > build/drain-before.py
python3.13 -m unittest discover -s tools -p 'test_netio*.py'
python3.13 examples/netio/check_drain.py --compiler ./pystachy --json build/netio-drain-checks.json
python3.13 examples/netio/compiler_dogfood.py --compiler ./pystachy --samples 1 \
  --json build/netio-drain-dogfood.json
python3.13 examples/netio/benchmark_drain.py --before build/drain-before.py \
  --compiler ./pystachy --cpu 0 --samples 7 --warmups 1 \
  --json build/netio-drain-replay.json
```

Choose a CPU in the available affinity mask. Run timings without other heavy
builds or tests. The benchmark restores its original affinity and rejects
missing samples, mismatched output or changed consumed sources/executables.

The native receive-buffer-to-managed-bytes copy remains. The FFI forbids C writes
to borrowed `bytes`, and Pystachy has no mutable byte-buffer type. This fix does
not introduce a new ownership interface or change that receive path. The earlier
[socket results](README.md#socket-consumer) remain a separate workload.

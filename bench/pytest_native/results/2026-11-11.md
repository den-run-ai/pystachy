# Native pytest multi-suite measurements

**Historical alpha.3 measurements.** This report describes the native alpha.3
compiler at `c5cebb8bdeb71e7e099b48e4400119dd1e5b29e2` and benchmark source
`7e33fb336a6429caf089aff3bd5c684528202c26`. It does not measure alpha.4, alpha.5 or
the updated harness. The adjacent schema 2 JSON is unchanged. It retains full
lifecycle phase events, but comparative generated samples and JIT warmups had
their events validated and then discarded. It also lacks the `lljit.c` source
hash and fingerprints for `llvm-as`, `llvm-link`, `lli` and the selected `libLLVM`.
Those missing historical records have not been reconstructed. The current
harness records this evidence for future runs; no benchmark was rerun for this
clarification.

Measured test bodies and generated collection/dispatch on the same pinned inputs. These original benchmark suites do not claim full upstream pytest or package compatibility.

Ordinary pytest uses no diagnostic reporting plugin. Native JIT samples include fresh program compilation with a warm runtime cache; AOT samples use a prebuilt executable. Complete runner commands below include the independent CPython pytest oracle and request the program cache; observed hits/bypasses are reported. Every timing includes the same small native measurement launcher's exec/fork/reporting overhead.

## Reproduction and limits

Commit: `7e33fb336a6429caf089aff3bd5c684528202c26`. Python 3.13.16; pytest 9.2.0. INTEL(R) XEON(R) PLATINUM 8573C; Linux-6.18.57-x86_64-with-glibc2.41; CPU affinity [0]. 7 interleaved samples per execution; shuffle seed 20261110.

LLVM: Ubuntu clang version 18.1.3 (1ubuntu1). Compiler executable SHA-256: `65657dda88dfb5e8faa92a88db2982f81e7fd6fd68abb7bb7f7260e4d3bb9e5b`.

The adjacent JSON records exact commands, the captured source/input/compiler/sampler hashes, raw samples, full lifecycle phase outcomes, checksums, load averages, environment and first-command build/run times, subject to the historical evidence omissions above. The native sampler forks after its own exec, avoiding the Python controller's inherited pre-exec RSS floor. Peak RSS is the target's largest individual-process high-water mark from wait4, including waited descendants, not a sum of concurrent processes. Launcher RSS is retained separately in JSON. Sampler compilation is outside the timings; its exec/fork/reporting overhead is included equally in every measured command. Cold means an empty private Pystachy cache; filesystem page caches and installed Python bytecode caches remain uncontrolled. Shared-host load can affect results.

The fixture suite is intentionally small, JSON repair uses the maintained adapted port under both interpreters, and the numeric suite is a typed integer-loop workload. No combined average is meaningful across these different workloads. See the [benchmark instructions](../README.md) for the replay command and input definitions.

# JSON repair and schema refresh — 14 November 2026

Native execution is useful for repeated repair and bounded schema validation. Across these
constructed workloads, AOT beats pristine upstream CPython in every paired repair process;
compiling the adapted port does not always win. Non-ASCII repair takes 141.6 µs in AOT versus
34.6 µs in adapted CPython: native is 4.1× slower. Keep that baseline when choosing a mode.
The CPython companion measures actual extension calls, including conversion overhead.

This evaluates the unreleased stack based on [#1296](https://github.com/den-run-ai/pystachy/pull/1296),
with this refresh's static-anchor fix. It is not a measurement of released main, or a
before/after claim about the anchor change. The previous rebase comparison and older
release results remain in the [benchmark guide](../README.md).

## Method and provenance

Measured source is clean commit `becf79b1aad9cd25a56301fd6280fbdda184bdee`, tree
`8a220ce161f8350d9dff705eee827caead7abbeb`. Builds were recorded at local commit
`ea6379d57a47f7fb1e2348c818142aa7da3eb0b9`, which has exactly that tree. Preserve both
identities: publication changed commit metadata, not source or artifacts.

Baseline: pristine json_repair 0.64.9, commit
`36d7a6ed53e777b5a5b9017e33d35ea2af8b7c6e`; CPython 3.13.16; jsonschema 4.26.0;
LLVM/Clang 18.1.3; Intel Xeon Platinum 8573C, Linux x86-64, glibc 2.41. The runner pinned
all children to CPU 2 on a shared host. No other builds or tests from this work ran during
timing. CPU affinity does not reserve the CPU, and several processes varied by more than
4×. Differences of a few percent are inconclusive here.

Each table reports microseconds per public call, using the median of five process medians.
Each throughput process has two warmup and five measured batches; process order rotates across
variants. Speedup is the ratio of aggregate medians; brackets give the minimum and maximum
of five same-pair ratios, not a confidence interval. All 400 process records, all batches,
commands, source/dependency/toolchain hashes and full output witnesses are retained below.
No samples were removed. Pilot runs used only to choose batch sizes are excluded.

Timers exclude imports, fixture construction, initial validation and post-batch output
checks. They include loop bookkeeping and the public API calls. Every warmup and measured
batch checks complete final outputs outside its timer. Exact output witnesses agree across
variants. The runner verifies source, executable and declared indirect-input identity before
and after each campaign. The datasets model LLM repair features, not production frequencies.

## Repair

Ten-record rounds make 10 calls, facade rounds make 4, and scaling rounds make 1.
The raw configs record every size and round count. AOT uses `-O2`; JIT numbers here are
steady loops after compilation. Both have `PYSTACHY_PROGRAM_CACHE=0`.

| Workload | Upstream CPython µs | Adapted CPython µs | AOT µs | JIT loop µs | AOT/upstream [paired range] |
|---|---:|---:|---:|---:|---:|
| Ten mixed records | 41.4 | 45.1 | 6.5 | 7.9 | 6.3× [5.3–10.7] |
| Small malformed objects | 65.3 | 58.9 | 9.0 | 21.1 | 7.2× [1.7–7.3] |
| Malformed, serialized result | 103.4 | 60.7 | 12.9 | 20.9 | 8.0× [5.5–11.2] |
| Small valid objects | 2.8 | 2.1 | 0.7 | 1.8 | 4.1× [2.3–7.5] |
| Non-ASCII text, 2,000 units | 443.4 | 34.6 | 141.6 | 131.8 | 3.1× [1.5–4.1] |
| 2,000 escaped newlines | 8998.0 | 574.6 | 225.3 | 250.3 | 39.9× [21.7–42.7] |
| Logged repair, 1,000 units | 170.8 | 20.7 | 6.2 | 8.3 | 27.5× [5.6–33.2] |

The Unicode reversal holds in every pair: AOT is 3.5–4.5× slower than adapted CPython.
Large escaped-string and logging gains versus pristine upstream combine parser adaptations
with compilation; they are not compiler-only speedups. For example, escaped repair is
39.9× faster than upstream but 2.5× faster than adapted CPython by aggregate medians.

## Schema consumer

Each round makes four calls. Validation uses a draft 2020-12 object schema with arrays,
bounds and local JSON-pointer references: valid data, early and late errors, and mixed
`is_valid`. `check_schema` mixes valid and invalid schemas. Standard/salvage/error repair
uses a separate object schema with integer/string/boolean fields, defaults and bounds.
The upstream probe executes the same source with only the private-validator imports replaced by
jsonschema imports. Initial validator construction and metaschema-cache warmup precede
timing. Timed `check_schema` and repair still include their own public-call setup.

| Workload | Upstream CPython µs | Adapted CPython µs | AOT µs | JIT loop µs | AOT/upstream [paired range] |
|---|---:|---:|---:|---:|---:|
| Validate valid objects | 326.2 | 78.9 | 18.7 | 24.1 | 17.5× [11.1–17.5] |
| Validate early errors | 7.9 | 3.9 | 2.6 | 2.6 | 3.0× [2.1–4.2] |
| Validate late errors | 256.8 | 91.7 | 33.0 | 24.3 | 7.8× [7.6–15.0] |
| is_valid, mixed outcomes | 171.7 | 40.5 | 12.8 | 17.0 | 13.4× [12.7–15.8] |
| check_schema, valid/invalid | 709.6 | 44.2 | 28.1 | 29.6 | 25.2× [21.7–42.6] |
| Schema repair, standard | 357.3 | 165.0 | 27.9 | 37.9 | 12.8× [5.1–21.6] |
| Schema repair, salvage | 180.7 | 144.5 | 22.3 | 44.5 | 8.1× [6.0–14.1] |
| Schema repair, final error | 224.8 | 138.6 | 29.3 | 48.0 | 7.7× [6.2–12.4] |

Exception construction and first-error `.message` extraction are timed and compared. This
is the narrower consumer contract used by the port: rich error paths, contexts, traceback
formatting and jsonschema's full public API are not equivalent. Static anchors have
correctness coverage separately; this table does not benchmark anchor resolution.

## CPython companion

Each mixed round contains 16 valid and 4 malformed calls; malformed rounds contain 4 calls.
All use 1,000 rounds per batch. `companion.py` checks that the native module has an actual
extension loader and compares 24 exact typed outcomes, including nested values, key order
and complete logs. Conversion to Python objects is included for object/log APIs.

| Workload | Upstream CPython µs | Native extension µs | Speedup [paired range] |
|---|---:|---:|---:|
| Text, 80% valid | 19.7 | 6.4 | 3.1× [2.4–7.4] |
| Text, malformed | 130.7 | 10.8 | 12.1× [6.4–18.6] |
| Objects, 80% valid | 22.1 | 3.5 | 6.3× [2.2–8.5] |
| Objects, malformed | 71.6 | 10.9 | 6.6× [5.7–7.1] |
| Logs, 80% valid | 23.0 | 5.3 | 4.4× [2.8–7.4] |
| Logs, malformed | 73.6 | 15.3 | 4.8× [1.7–7.1] |

The companion remains schema-free, holds the GIL and follows its importing-thread contract.
These measurements do not establish thread-pool, subinterpreter or installed-wheel support.

## Startup and build cost

Two zero-round probes use one measured batch, no warmup, five pairs each, and retain
fixture setup and initial correctness calls. CPython process medians are 51–68 ms. Prebuilt AOT reports about 10.6 ms, at the runner's 10 ms polling floor;
this does not establish precise intrinsic startup or an exact startup speedup.
The first JIT process took 26.167 s with the initially cold runtime-cache setup. Nine later
processes using that runtime cache took a median 6.963 s (6.405–7.327 s). Program caching
was disabled, so each JIT process still compiled the application. The first-use observation
is not a repeated cold-start estimate. Use AOT or a persistent process for low latency.

Single sequential builds after compiler bootstrap, with runtime caches reused:

| Artifact | Build seconds | Bytes | Emitted IR lines |
|---|---:|---:|---:|
| schema | 29.266 | 1,307,368 | 175212 |
| bench | 27.166 | 1,281,288 | 174186 |
| facade | 26.874 | 1,281,232 | 174124 |
| scaling | 35.263 | 1,281,408 | 174463 |
| companion | 31.997 | 636,704 | not recorded |
| replay | 36.427 | 1,306,136 | 175133 |

These are absolute observations, not repeated build medians. The schema executable includes
both validation and repair. All CPython/AOT startup samples report the same 164.512 MiB
whole-child peak RSS, exposing an inherited launch floor. No memory ranking or retained-heap
claim follows from these records. General unused-code pruning is separate work in
[#1431](https://github.com/den-run-ai/pystachy/pull/1431) and was not applied here.

## Completeness and qualification

The parent stack restores upstream signatures, file APIs, JSONReturnType, schema-guided
repair and CLI behavior. Relative to upstream, 678 lines differ, including the retained
scanner and moved CLI body; the private validator adds 1,091 lines. Adaptations are explained
in [PORT.md](../../../ports/json_repair/PORT.md). This is an upstream-based repair port with
a substantial replacement for the validator dependency, not annotation-only compilation.

This refresh resolves same-resource static `$anchor` references for drafts 2019-09/2020-12,
including recursion and cross-draft validator evolution. Discovery visits schema positions
only. Duplicate/dynamic/legacy anchors and embedded-resource graphs reject explicitly;
const/default/enum data cannot masquerade as schemas. Upstream's malformed-input repair
algorithm still resolves only pointer references, so static-anchor validation does not add
anchor-guided malformed repair.

| Evidence | Result |
|---|---|
| Compiler/runtime bootstrap fixed points | 920,346 / 21,214 IR lines; pass |
| `make check-fast` | Pass, including hosted JSON regression/tool tests |
| Focused schema + anchor programs, JIT/AOT | 4/4 normal; 4/4 program GC stress |
| Validator differential fuzz, seed 1 | 2,000 schemas; 5,116 instances; zero compared differences; 17 unsupported reference comparisons excluded |
| 962-case replay | Pristine/adapted CPython, AOT, JIT; native normal and program GC stress all pass |
| Real companion extension replay | 962/962 normal and forced-GC checks pass |
| Adapted custom CLI output/status/files | 20 cases match its CPython execution in JIT and AOT; not pristine upstream/schema CLI |
| Upstream pytest in upstream CI mode | Pristine: 548 pass; adapted: 531 pass, 17 fail; both skip 25 timing tests |
| Code-head PR CI (`becf79b1`) | 17 successful checks, 2 expected skips; Verification and Lint pass |

The 17 upstream-test failures are 15 Pydantic cases and two assertions about the replaced
string accumulator's internal state. An initial pristine attempt used `--benchmark-disable`,
causing 14 assertions on missing benchmark statistics; the final comparison uses upstream
`CI=1` mode and explicitly excludes those timing tests. The initial anchor recording lacked its exit-status envelope; after correcting it, both
anchor native checks passed on rerun. Full local `make verify`, fresh wheel portability and
long-running memory retention were not run. CI is the bounded PR matrix, not exhaustive
release qualification.

| Remaining gap | Disposition |
|---|---|
| Native Pydantic models | Feed exported JSON Schema dictionaries; compiling Pydantic is separate compiler/library work. |
| External references, dynamic/legacy anchors, embedded IDs | Requires resource/URI scope resolution and qualified recursion; retrieval also needs an explicit network contract. |
| File streaming | Current APIs buffer input; `chunk_length` has no effect. Incremental parsing needs file-position and bounded-memory tests. |
| Companion schema API | Bounded follow-up requiring extension-boundary, installed-wheel and schema-oracle checks. |
| Full jsonschema API/error metadata | Add only for a concrete consumer; current first-error contract is documented. |
| Native Unicode performance | Adapted CPython is faster on the measured long-string case; retain as a regression/performance target. |

## Reproduce and inspect

Use the measured source commit, the pinned upstream checkout, Python 3.13.16 with
jsonschema 4.26.0, and LLVM 18.1.3. Bootstrap following the repository installation guide. Set `PYSTACHY_LLVM` to its complete
LLVM bin directory and `LD_LIBRARY_PATH` to the matching toolchain library directories;
the config generator requires both. The following commands assume `UPSTREAM` and `ORACLE_PY` point to those local installations:

```sh
export PYSTACHY_HOME="$PWD" PYSTACHY_PATH="$PWD/ports"
export PYSTACHY_AOT_OPT=2 PYSTACHY_PROGRAM_CACHE=0
mkdir -p build/json-refresh/pystachy_json_repair
for probe in bench facade scaling schema; do
  ./pystachy build "bench/json_repair/$probe.py" -o "build/json-refresh/$probe" \
    --emit-ir "build/json-refresh/$probe.ll"
done
cp examples/json_repair/pystachy_json_repair/__init__.py build/json-refresh/pystachy_json_repair/
./pystachy ext examples/json_repair/_native.py \
  -o build/json-refresh/pystachy_json_repair/_native.abi3.so
"$ORACLE_PY" tools/json_repair_refresh.py --upstream "$UPSTREAM" --python "$ORACLE_PY" \
  --native-dir build/json-refresh --companion-dir build/json-refresh \
  --output-dir /tmp/json-refresh-configs
```

For this run, config round counts were increased after a pilot: `unicode-malformed` to 400,
`logged-repair` to 2,000 and schema `check-schema` to 100. Apply those three overrides to
the generated JSON configs; their retained copies in the raw reports are authoritative.
Generate a startup config from repair with only `bench` args `["0"]` and `facade` args
`["valid", "0"]`, named `mixed-zero` and `valid-zero`. Start with an empty dedicated JIT
runtime-cache directory; reuse it across the serial campaigns.

```sh
"$ORACLE_PY" tools/json_repair_bench.py /tmp/json-refresh-configs/startup.json \
  --output /tmp/startup.json --pairs 5 --batches 1 --warmups 0 --cpu 2 --timeout 180
for campaign in repair schema companion; do
  "$ORACLE_PY" tools/json_repair_bench.py "/tmp/json-refresh-configs/$campaign.json" \
    --output "/tmp/$campaign.json" --pairs 5 --batches 5 --warmups 2 --cpu 2 --timeout 180
done
```

# GC locality and scalar-allocation measurements: 6 November 2026

**Findings:** the isolated atomic-allocation change improves the longer scalar-record workloads by 10.2–16.4% in median elapsed time, with about 45% less elapsed collection time. No reproducible self-frontend throughput win is established. The combined candidate changes direction between batches, and the self-frontend does not exercise the changed allocator. The block traversal remains experimental: it slows the primary self-frontend workload in every paired comparison in its headline batch. The byte-identical stores control demonstrates why small timing and RSS changes must not automatically be attributed to the patch.

Evidence: the combined-implementation run records and build metadata are preserved below. Statistics were recomputed from samples and every recorded output signature was checked. The atomic-only control is a separate batch; its measurements are reported separately.

## Variability and defensible interpretation

- **Self-frontend combined/object:** median +7.8%, with overlapping ranges and per-round relative changes of −4.9%, +18.8%, +15.9%, −0.6%, and +2.8%. The median of these paired percentage changes is only +2.8%, illustrating sensitivity to aggregation. Report “the batch median regressed 7.8%; no demonstrated self-frontend win,” not a precise causal 7.8% atomic regression. Relative median absolute deviations are 2.6% for main and 4.6% for combined/object. The median peak RSS difference is only 72 KiB, which does not establish a meaningful memory improvement.
- **Self-frontend block/object:** median +13.9%; every pair is slower (+7.1% to +19.9%), and the sampled wall-time ranges do not overlap. Collection elapsed time increases from 907.0 to 2059.8 ms (+127.1%), with the same 13 collections. This batch gives materially stronger negative evidence for enabling block traversal on the primary workload than for assigning blame to atomic allocation.
- **Scalar records:** combined/object median wall time improves 12.7% for aligned payloads and 11.2% for small payloads. Collection elapsed time falls about 60% in both, with the same 66 collections and about 0.25 MiB less peak RSS. All five small-payload pairs improve, with nonoverlapping wall ranges; four of five aligned pairs improve, with a substantial candidate outlier. This supports further isolated evaluation of scalar scan avoidance. The aligned integers are synthetic addresses, so this is not evidence of false-pointer retention being eliminated in a real application.
- **Graph:** block/object median improves 12.1% and GC elapsed falls 43.0%; GC ranges are separated. However, these process runs last only 0.13–0.18 seconds and object/block relative MADs are 7.9%/8.4%. Treat the wall win as a short synthetic signal, not a broad compiler-throughput result.
- **Stores and chain wall time:** ranges overlap substantially. In stores, the ratio-of-medians block slowdown is +12.1%, but the median paired change is −1.7%; do not present the former as a robust treatment effect. Reverse-chain block timing is directionally worse in four of five pairs. Both chain modes have consistently higher collection elapsed time under block traversal, but forward/reverse cross-workload timings were collected in separate sequential batches; they do not isolate an order effect by themselves.
- No pause distribution, allocation throughput counter, isolated GC CPU cost, low-memory failure frontier, retained RSS after shrink, or broad application suite was measured. Five rotated runs on one shared machine are insufficient to call noisy effects settled. Startup is included in sub-second AOT times. There is no measured comparison with MMTk, Julia, Go, or Whippet.

**Strongest positive evidence:** atomic-only improves all six paired runs for both scalar cases. The median paired elapsed changes are −11.4% (aligned) and −7.5% (small), compared with −16.4% and −10.2% from ratios of medians. GC elapsed falls 44.6% and 44.7%, respectively, with 333 collections in every run. For both cases, the measured atomic-only GC-time range lies below the entire main GC-time range. These matched longer runs support scalar scan avoidance on this allocation pattern; they do not establish a universal runtime improvement. Scalar RSS changes are only 0.125–0.25 MiB.

**Self-frontend mechanism is absent:** the [compiler IR audit](2026-11-06/compiler-allocation-audit.json) finds zero actual `pys_new` calls/invokes and zero declarations in the baseline, atomic-only, and combined compiler IR. Its text occurrences are code-generation literals. Therefore the observed atomic-only median −4.1% does not demonstrate a benefit from skipping scalar-object scans in this workload. The paired median is −1.5%, with three faster and three slower rounds and overlapping ranges. Combined/object changes from +7.8% against main in the first batch to −4.0% in the control batch, despite identical executable hashes and input. Host/process variation and code-layout attribution remain unresolved; there is no reproducible self-frontend throughput claim.

**Prominent negative control — stores:** main and atomic-only binaries are byte-identical, SHA-256 `33c6aa6ba871b604277d385c9a8d49d5b1fde46c0ccc4a9f9f482956d998c36a`. Nevertheless, atomic-only’s label has a +5.8% ratio-of-medians wall difference and +1 MiB median peak RSS. Its median paired wall difference is only +0.5%, with three rounds faster and three slower. This cannot be attributed to changed code from the atomic patch: it shows run/placement/context variation. Keep these apparent regressions visible rather than selecting only favorable cells. Combined/object stores is +1.5% by ratio of medians; the first batch’s larger combined/block +12.1% also had conflicting paired evidence. Neither is a settled patch effect here.

**Control output checks:** all 84 control runs (72 measured and 12 warmups) returned zero and match exact outputs within each workload; all medians were recomputed. All 21 control self-frontend IR artifacts match the same 31,409,957-byte hash as the first batch. The control one-minute host load moved from about 1.19 to 1.05. Original source IDs, commands, digests, and every sample remain in the linked raw records.

### IR comparison qualification

The initial focused comparison using each compiler's own checkout **did not pass
byte-for-byte**: 39 of 48 fixtures matched and nine differed. Full inspection of
all nine pairs found exactly one changed line per fixture, an embedded
`ImportError` string naming the absolute path to `_pystachy_weakref.py` under
`baseline/lib` versus `pystachy/lib`. Both compilers returned zero with empty
diagnostics; all other IR bytes matched.

All 90 library files (2,750,993 bytes) were then verified byte-identical. With an
explicit shared library home, the **unmodified** comparison script reported
`48 programs identical`. The original failure remains in the check record; the

# Application-focused GC experiments, 2026-11-06

## Decision

Prioritize compiler-proven pointer-free allocation. The isolated scalar-object change
improves the million-point float workload by **7.50%** in paired elapsed time. The new
`+atomicunion` experiment improves the longer retained-JSON pipeline by **8.83%**, with
**19.06% less collection time**, equal collection counts and essentially unchanged RSS.
These are the strongest production candidates after correctness and design review.
Keep atomic union allocation opt-in while that review proceeds. Neither result concerns
compilation speed. [Float evidence](2026-11-06/native/float.json),
[long JSON evidence](2026-11-06/sensitivity/union_retained_80.json).

Heap pacing has substantial application-specific effects, including memory savings
without a collector replacement. It does not justify one new global threshold. The
chunk marker establishes no throughput improvement on the two GC-heavy applications.
The restricted BDWGC binding is useful comparative infrastructure, but these results do
not justify adopting it for throughput. MMTk and Whippet were not built or benchmarked;
this experiment cannot rank collector families.

| Candidate | Most informative result | Memory consequence | Decision |
|---|---|---|---|
| Proven pointer-free scalar objects | Float: −7.50% elapsed; median GC 289.95→119.15 ms | RSS 65.72→65.52 MiB | Prioritize isolated production review |
| Proven scalar closed-union boxes | Long retained JSON: −8.83% elapsed, −19.06% paired GC | RSS 231.16→231.29 MiB | Strong compiler candidate; keep opt-in pending review |
| Native minimum 128 versus 32 MiB | Retained JSON: −18.33% elapsed | RSS +11.13%; float needs +168.65% RSS | Workload-specific tuning; no blanket default change |
| Native minimum 8 versus 32 MiB | Chaos/raytrace/dumps recover most BDWGC memory savings | About 66–67% less RSS in those cases | Investigate adaptive pacing; small minimum harms float |
| Chunk marking | Float +0.56%; retained JSON +1.74% elapsed | No reliable throughput benefit | Retain as research |
| Optional BDWGC | Retained-memory JSON: default +131.98% elapsed | Slightly more RSS; incremental policies use more | Do not adopt for measured throughput goals |

Paired elapsed/GC changes are geometric means of per-round candidate/control ratios,
minus one; negative means lower. RSS percentage changes are medians of paired ratios;
absolute values are medians. GC share is defined below. Tables and the
[native](2026-11-06/native-summary.md), [optional](2026-11-06/optional-summary.md) and
[sensitivity](2026-11-06/sensitivity-summary.md) summaries preserve the comparisons.

## Workloads and controls

The native matrix contains nine application-execution cases: existing pyperformance
adaptations of float, chaos, raytrace, JSON loads/dumps, Richards and n-body, plus retained
JSON and an adapted PyPI json_repair consumer. The [workload guide](../README.md) and
[pyperformance provenance](../../pyperformance/README.md) explain their origins and
adaptation limits. No workload explicitly forces collection. Inputs are deterministic
benchmark fixtures, not a claimed production distribution.

Retained JSON parses a page of 20,000 nested event records, computes a rollup, keeps a
four-page recent window, traverses retained records again and writes the complete final
JSON document. Its existing `changing` fixture changes scalar alternatives within the
page. The primary run ingests 40 pages; the follow-up ingests 80. Repeatedly ingesting the
same page creates controlled survival while retaining useful parse/process/encode work.
The repair consumer repairs ten constructed trace examples through the existing
json_repair port and serializes the results. [Input manifest](2026-11-06/preparation/inputs-full-manifest.json),
[repair provenance](../../../ports/json_repair/PORT.md).

The optional matrix has eight cases. It omits repair and replaces file-backed retained
JSON with `json_retained_memory`, which embeds exactly the prepared input text and prints
the complete final encoded document. This avoids the adapter's unsupported managed-file
interface, but also removes managed input allocation and file I/O. Its corresponding
native executable is the valid comparator; do not substitute file-input measurements.
[Embedding identity](2026-11-06/preparation/embedded-fixture-manifest.json),
[optional specification](2026-11-06/preparation/optional-spec.json).

All headline measurements use prebuilt AOT executables, private build/runtime caches,
CPU affinity 3 and an identical **2 GiB process address-space limit**. That limit is not
a GC heap cap. Native `PYSTACHY_GC_MIN=32` is a lower bound on collection pacing;
BDWGC's initial-heap setting is a different policy. Compare observed peak RSS, not those
settings as supposedly equivalent memory budgets. Build time is excluded. The native
matrix has six rotated measured rounds and one warmup per variant; the optional matrix
has five and one. Float/retained-JSON pacing and long JSON have six measured rounds;
chaos/raytrace/dumps pacing have four. Warmups remain in raw evidence but are excluded
from the reported statistics. [Native specification](2026-11-06/preparation/native-spec.json),
[optional specification](2026-11-06/preparation/optional-spec.json),
[sensitivity records](2026-11-06/sensitivity/).

The controller records commands, input and executable hashes, validated binary identities,
explicit environments, wall/CPU time, peak RSS and exact output hashes. Preparation
freezes compiler/runtime/library sources and dependency inputs around builds. Inherited
GC/runtime settings are sanitized. Headline runs use GC statistics; detailed profiling is
separate. Full stdout and declared artifacts are checked against CPython before timing.
Preparation records **282 passing application validations**: 162 native and 120 optional,
each case/configuration running smoke, smoke with collection at every program allocation,
and a full-scale oracle check. These are validation runs, not compilation counts.
[Preparation evidence](2026-11-06/README.md).

## Native changes and unchanged-code controls

`main` is the baseline, `main_aa` reuses its exact executable, and `scalar` isolates the
previous scalar-object allocation change. `default` includes the combined experimental
runtime in object-marking mode and the new compiler, with atomic union allocation off.
`atomic_union` enables the new lowering option. `block` reuses the `default` executable
and changes the tracing policy. Compare scalar/main, atomic_union/default and
block/default to isolate their intended changes.

| Retained JSON, 40 iterations | 38.79% | −0.26%* | −3.30%* | −3.98% | +1.74% |
| Chaos | 0.35% | −1.53%* | −0.75% | −5.73%* | −6.12% |
| Raytrace | 1.08% | −0.83%* | −0.88% | +0.25%* | −0.71% |
| JSON loads | 0.50% | +0.42%* | −2.40% | +5.53% | −0.65% |
| JSON dumps | 0.84% | −2.86%* | +6.70%* | +4.43%* | +5.56% |
| Repair traces | 0.46% | −0.07%* | +1.46% | +1.45% | +1.22% |
| Richards | 0.00% | −2.66%* | −1.56% | −0.12%* | +0.74% |

Source: [native summary and raw-file links](2026-11-06/native-summary.md).
An asterisk means identical executable bytes **and** recorded settings. Such differences
are control observations, not optimization effects. GC share is the median per-process
native collector elapsed time divided by process elapsed time.

These controls materially limit interpretation. N-body's apparent atomic-union win is
8.36%, with all six rounds lower, even though the executables/settings are identical and
no native collections occur. Chaos similarly shows an apparent 5.73% identical-code
improvement. A consistent sign alone therefore does not establish a benefit. We retain
every measured sample, report observed ranges rather than confidence intervals, and make
no significance claim or suite-wide weighted speedup.

Float provides better evidence for scalar allocation: paired elapsed is 7.50% lower
versus main and 7.82% lower versus its identical alternate control. The latter comparison
is lower in all six rounds. Median collection time drops about 59%, while both variants
perform 59 collections and retain essentially equal peak RSS. This supports reduced
tracing work as a useful application optimization. The ordinary repair batch lasts only
about 0.63 seconds and has very little collection time; it remains a correctness/library
control, not evidence resolving small performance effects. [Float](2026-11-06/native/float.json),
[repair](2026-11-06/native/repair_traces.json).

## Compiler-assisted scalar union allocation

The new lowering allocates a closed-union box as pointer-free only when a literal,
program-wide tag proves a native `int`, `float` or `bool` payload. References, runtime
union tags, optional conversions and boxes carrying a wide-integer `Mpz` retain scanned
storage. Payload layout and existing scalar/reference distinctions remain intact. The
[compiler validation](2026-11-06/compiler-validation/README.md) describes the proof
boundaries and independent reachability controls.

The emitted retained-JSON IR changes **nine of sixteen** union-box allocation sites to
the atomic helper; seven remain scanned. This establishes that ordinary typed
`json.JSONValue` scalar leaves exercise the change, without a dynamic-Any workload
rewrite. [Recorded IR sites and identities](2026-11-06/profile/ir-sites.json).

The short JSON run suggests lower collection time and RSS, but elapsed control variation
is substantial. Its atomic/default paired elapsed change is −3.98%; median GC changes
429.7→378.9 ms and RSS 232.54→221.29 MiB. Collection count changes 13→14. An unchanged
main/scalar executable also appears faster in that batch. This motivated the longer
run with a control duplicating the actual `default` binary.
[Short JSON](2026-11-06/native/json_retained.json).

| Longer JSON comparison | Paired elapsed change | Observed paired range | Lower rounds |
|---|---:|---:|---:|
| Identical default_aa/default | +3.42% | −0.55% to +6.36% | 1/6 |
| Atomic union/default | −8.83% | −11.94% to −6.99% | 6/6 |
| Atomic union/default_aa | −11.84% | −15.84% to −6.63% | 6/6 |

Median default elapsed is 2.1193 seconds versus atomic union's 1.9280 seconds. Median GC
elapsed is 906.9 versus 732.4 ms; the paired GC reduction is 19.06%. Both perform **24
collections**. RSS is 231.16 versus 231.29 MiB: the short-run memory saving does **not**
persist. This is stronger throughput evidence with roughly equal observed memory, not a
universal memory-reduction claim. All warmup/measured outputs and full artifacts match
the separate 80-iteration CPython oracle. [Long-run raw evidence](2026-11-06/sensitivity/union_retained_80.json).

Detailed profile counters require a separate qualification. In an instrumented
40-iteration run, atomic union scans fewer objects but more total heap words and performs
one additional collection. Block marking greatly reduces range pushes but increases
other work. Do not claim that every work metric improves:

| Atomic union | 14 | 16,278,623 | 79,876,053 | 16,278,623 | 0 |

simple across-run counter total from substituting for application elapsed measurements.

## Optional BDWGC: throughput and memory

The supplied BDWGC 8.2.6 dependency is pinned by headers, library and overlay identities.
This is an AOT, single-mutator research adapter using one marker, not a complete binding.
Managed files, weak references, CPython ownership/embedding and JIT are rejected. Manual
dirty tracking is disabled because Pystachy emits no corresponding write barriers;
incremental modes require usable automatic tracking. Tested incremental policies use
explicit mprotect tracking after the automatic capability probe failed.
[Overlay manifest](2026-11-06/preparation/bdwgc-aot-overlay-manifest.json),
[optional configuration](2026-11-06/preparation/optional-spec.json),
[tracking probes](../../gc_locality/results/2026-11-06/bdwgc-contract-manual-vdb.json).

## Pacing explains much of the memory tradeoff

Sensitivity runs change the native pacing minimum in the same executable. Larger values
help the retained-data cases but can waste memory or slow other applications:

| Native case | MIN128/MIN32 elapsed | MIN32→MIN128 RSS, MiB | MIN8/MIN32 elapsed | MIN32→MIN8 RSS, MiB |
|---|---:|---:|---:|---:|
| Float | −12.88% | 65.51→176.00 | +9.42% | 65.51→75.81 |
| Retained JSON | −18.33% | 232.54→258.41 | +6.54% | 232.54→229.91 |
| Chaos | −1.24% | 35.02→133.14 | −2.90% | 35.02→11.62 |
| Raytrace | +10.10% | 34.77→131.14 | −23.37% | 34.77→11.41 |
| JSON dumps | +4.99% | 36.79→133.79 | −8.89% | 36.79→12.66 |

Source: [sensitivity summary](2026-11-06/sensitivity-summary.md). The smaller floor is not
a heap cap: float's collection/live-data pattern gives it *higher* RSS and elapsed at
MIN8. Increasing MIN128 raises float RSS by 168.65% for its measured speed improvement,
while JSON pays 11.13%. This argues for workload-sensitive pacing research, not a
universal threshold change.

Direct same-batch comparisons address whether BDWGC uniquely supplies small-live-set
memory savings. Native MIN8 and default BDWGC use essentially equal RSS in chaos and
raytrace; BDWGC is respectively 46.54% and 75.55% slower, with all four pairs slower.
In the final JSON-dumps follow-up, native MIN8 uses 12.66 MiB versus BDWGC's 11.49 MiB,
while BDWGC is 26.12% slower, again in all four pairs. Native pacing reproduces most of
the earlier roughly 62% memory advantage against MIN32. Its own −8.89% elapsed change
versus MIN32 has a wide range and only three of four pairs lower; the memory finding is
clearer than that exact speed estimate. These are explicit exploratory follow-ups, not
selectively substituted primary runs.
[Chaos](2026-11-06/sensitivity/pacing_chaos.json),
[raytrace](2026-11-06/sensitivity/pacing_raytrace.json),
[dumps](2026-11-06/sensitivity/pacing_json_dumps.json).

## Correctness, unsuccessful attempts and remaining scope

The separately documented compiler work supplies **94 passing targeted native checks**:
ordinary and per-allocation-stress JIT/AOT cases plus the corrected default fixture.
Those are separate from the 282 application-preparation checks. Bootstrap fixed points,
54 archived hosted units, runtime contracts, default-IR parity and six deliberately
wrong-allocation-kind negative controls provide additional evidence; counts are not
pooled into a synthetic coverage percentage.
[Compiler validation and limitations](2026-11-06/compiler-validation/README.md).

Unsuccessful attempts remain visible. The first optional link passed an archive directly
under clang's C-input mode and failed; the corrected overlay forwards it to the linker.
The first boundary fixture used overflowing intermediate integer expressions, reproduced
on the baseline, then switched to representable signed literals. A pilot repair output
boundary was also corrected before the complete native matrix. None of these failed/pilot
timings enter headline samples.
[Preparation failures](2026-11-06/README.md#preserved-unsuccessful-preparation),
[fixture failure](2026-11-06/compiler-validation/README.md#initial-fixture-failure-and-correction).

This is a research evaluation on one Linux x86-64 environment. It establishes neither
production workload representativeness nor pause-latency guarantees. Full integrated
`make verify`, macOS/ARM execution and an entire-corpus sweep with atomic union allocation
enabled are not established by these local results. Current-head CI status belongs to
the PR, separately from this fixed evidence. Promote narrow allocation proofs only after
review and required integrated gates; retain optional collector and pacing experiments
as reproducible research.

[2] (high) Calling convention and linkage: always the default C convention (ccc; the compiler never emits fastcc). Compiled functions are `internal` unless they are runtime-mode exports. [3] (high) Layouts:
- Str is {i64 len; char s[]}, NUL-terminated and allocated atomic (never scanned). String constants are private globals {i64, [n x i8]} outside the heap.
- List is {len, cap, I *a}; the items array is a separate scanned allocation.
- Dict is {len, kind, n, size, keys*, vals*, hs*, idx*}; keys and vals are scanned, hs and idx are atomic.
- A tuple is pys_alloc(8*n) slots with no header (its length is static).
- An object is pys_alloc(sizeof %C.X): an LLVM struct of its fields, then i1 'assigned' flags. An exception class starts with hidden fields (ExcClass*, ...).
- Exc is GC-allocated, 16-byte aligned, and starts with _Unwind_Exception.

[11] (high) Exceptions:
- **One-phase forced unwind:** pys_eh_on stores xthrow. throw_ calls _Unwind_ForcedUnwind with stop_none, a stop function that never stops, so the unwind walks every frame in a single phase.
- **Personality:** pys_personality acts only on PYS_EXC exceptions in frames with an LSDA. Every pad is `catch ptr null`, so the first Pystachy landing pad wins, and pys_exc_begin(mark) runs the unwind actions.
- **No handler:** the stack is left as it was, and uncaught() prints the last traceback line and calls exit().
- **Before pys_eh_on:** every funnel (pys_fail, pys_raise, pys_exit, pys_exit_msg) prints and exits at once.
- **Foreign exceptions:** C++ exceptions and thread cancellation pass Pystachy frames without running their pads, which leaves unw/xr stale.

[12] (high) When a Pystachy exception reaches a foreign frame:

[14] (high) Runtime mode's extern mechanism:

[17] (high) Effect letters for an unknown foreign function: conservatively U, which is FXALL (every letter but N: R A U I rL wL rD wD rO wO rG wG rF wF). The compiler already assigns this to any call of a callee it did not compile. Narrower sets:
- a pure leaf that touches no Pystachy memory: none (like fabs);
- I/O or process/global state: I;
- may raise through pys_fail/pys_raise: R (and N if it never returns);
- allocates Pystachy objects: A;
- reads or writes containers passed to it: rL/wL/rD/wD;
- calls back into Pystachy code: U.
R makes a call inside a try an invoke (eh_ir).

[21] (high) Global state and threads: runtime.c has about 28 mutable statics and no locks, TLS or pthread calls (grep: 0 hits). [0] (high) The contract is a hard invariant: a program that compiles prints what CPython prints (apart from documented deviations), otherwise it gets a compile-time file:line: error. CPython's output is the specification and the tests' oracle.

[1] (high) Self-hosting is a hard invariant: stage1, stage2 and stage3 must emit byte-identical IR, for the compiler and also for runtime.py (pystachy rt). The compiler is written in the subset, and CPython runs it as stage 0.
   EVIDENCE: docs/testing.md:10,60; docs/internals.md:324-332 (Bootstrap); README.md:53,173-175; docs/runtime-in-subset.md:138-139

The established precedent for new features is pay-for-use: programs that do not use a feature keep their IR byte for byte.

[10] (high) Issue #4 §4 sets requirements for any boundary before implementation:
- an ADR comparing extension mode, explicit opaque-Python-object bridging and expansion of the independent runtime;
- a spec of identity and shared mutation, owned and borrowed references, error propagation, callbacks, buffer protocols and cross-runtime cycles;
- mutable Python objects stay Python objects by default, with explicit copies only;
- zero-copy numerical buffers come first;
- explicit eligibility diagnostics, with no invisible performance cliffs;
- completion gate: one pure-Python and one native-extension package run unchanged, and baselines are taken against mypyc, Cython and CinderX.
   EVIDENCE: GitHub issue #4 §4 checklist and 'Completion gate' (mcp__github__issue_read get, issue 4)
[11] (high) Extension mode is already sketched as a third lowering of the typed IR. An IFn is eligible when it elaborated without error and every op has a C-API lowering. Containers stay Python objects. None is Py_None. [29] (medium) (c) Embedding CPython in Pystachy programs with an opaque PyObject type: interaction with each invariant.
- Status: named in #4 §4 as "explicit opaque-Python-object bridging", to compare in the ADR; Codon is cited, where converted containers do not preserve shared mutation.
- Contract: holds only if every PyObject op has CPython semantics, and the oracle is CPython running the program natively.
- Runtime: needs an opaque type (M4's Any is not started), U+R+A+I effects on every op, PyObject* refcounts released by a sweep-time hook (as files are; __del__ never runs) and a policy for cross-runtime cycles.

- Callbacks: Python calling into Pystachy needs functions as values (M3, not supported).
- Wasm GC: not portable.

[30] (medium) (d) In-process JIT inside CPython (a Numba/LPython-style decorator): no doc mentions it.

[1] (high) @main is the only entry point. pys_init takes @main's frame address as the fixed bottom of the conservative stack scan, plus @pys.roots (the program's pointer-typed globals). A library needs an init that runs pys_init, pys_eh_on and @main.init, and a stack bottom set at every foreign entry. Initialising deep and calling shallow leaves the compiled frames above gc_bottom: the scan `for (; p < e; p++)` runs zero iterations and the process segfaults.
   EVIDENCE: pystachy.py:11075-11083 (@main calls llvm.frameaddress, then pys_init(argc, argv, %sb, @pys.roots, N), pys_eh_on, @main.init, pys_finish); runtime.c:162 and runtime.c:314. Command: `PYSTACHY_GC_STRESS=1 python3 ctypes_test.py gc_deep_init` gave [exit=139]; without stress, and gc_shallow_init with stress, printed 40000 (correct).
[2] (high) A Pystachy object reachable only from Python (a pointer held via ctypes or a capsule) is silently freed and zeroed. A pin table scanned in mark_roots fixes this.
   EVIDENCE: `PYSTACHY_GC_STRESS=1 python3 ctypes_test.py gc_held` printed `held str: ''` (it should be 'KEEP ME!'). [3] (high) An uncaught Pystachy exception, sys.exit or int overflow in a library call terminates the whole CPython process with exit(1). throw_ forced-unwinds to the end of the stack, finds no landing pad, and calls uncaught(), which calls exit(). An exception in module top-level code during init does the same.
   EVIDENCE: runtime.c:2315-2325 (throw_ → _Unwind_ForcedUnwind(stop_none) → uncaught → exit), runtime.c:2298-2309. Commands: `python3 ctypes_test.py raise` printed `ValueError: negative: -1` [exit=1], and the except clause and `after` line never ran. `ctypes_test.py overflow` printed `OverflowError: integer result does not fit in 64 bits` [exit=1]. libbad.so pyx_init (top-level `x = D["nope"]`) printed `KeyError: 'nope'` [exit=1].
[4] (high) A boundary wrapper in IR (invoke the function; `landingpad {ptr,i32} catch ptr null` under `personality @pys_personality`; pys_try_mark, pys_exc_handled, pys_exc_begin, pys_exc_restore; the Exc* returned through an out-parameter) turns every raise into a Python exception and costs nothing until a raise. The forced unwind stops at the wrapper and never walks CPython frames: cost is the same 150 C-level Python frames deep. python3.13 has no .gcc_except_table, so even an unbounded walk would enter no foreign landing pad.

[6] (high) stdout: when fd 1 is not a TTY, pys_init emulates CPython's buffering with its own 8 KiB pending buffer.    EVIDENCE: runtime.c:1852 (setbuf1 when !isatty(1)), runtime.c:1717-1726, runtime.c:1790-1808. `python3 ctypes_test.py stdout | cat` printed only `py: 1`, `py: 3`, `py: 5`; the same through `script -qc` showed `pys: 2` and `pys: 4` interleaved. [7] (high) Calling back into Python from compiled code (the Pys→Py direction, here sys.stdout.write) can release the GIL. If another thread then enters the runtime, its collector scans with the first thread's stack bottom and the process segfaults. A per-thread bottom (__thread) plus registered 'suspended spans' around call-outs fixes it; this is the Boehm GC_do_blocking / OCaml blocking-section pattern.
   EVIDENCE: thread_test.py (a SlowOut.write that calls time.sleep, plus a worker thread calling m.total). Before the fix, PYSTACHY_GC_STRESS=1 gave [exit=139]. After the fix (pys_out_begin/pys_out_end in runtime_lib.c, with __builtin_unwind_init in the hook), 3 of 3 runs printed `wrong results: 0` [exit=0] under stress, and also without stress.

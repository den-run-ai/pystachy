## API (observed)
- `parse(fnam, source=None, skip_function_bodies=False, python_version=None, platform=None,
  always_true=None, always_false=None, cache_version=0)` -> 5-tuple:
  (ast bytes, errors list[dict line/column/message/blocker], type_ignores list[(line, [codes])],
  import bytes, dict(is_partial_package, mypy_ignores, uses_template_strings, source_hash (sha1 hex
  of raw text before newline normalization), mypy_comments [(line, text)])).
  Defaults: python_version = sys.version_info[:2], platform = sys.platform.
  source None: reads file as UTF-8 (ValueError on failure); bytes source: must be UTF-8
  (UnicodeDecodeError). Universal newlines applied after hashing.
- `parse_type_string(source, range=(line,col,end_line,end_col), cache_version=0)` -> bytes;
  python_version (3,10), platform linux; every location = the range (location_override).
- mypy calls both with cache_version=5.

## Format quirks to replicate
- Locations: line, col0, end_line-line, end_col-col. Non-ASCII files: Ruff LineIndex.line_column
  gives 1-based UTF-32 column (minus 1 on line 1 if text starts with BOM); serializer then
  *double converts* (treats that number as a byte offset in the line, floors to char boundary,
  counts chars) for lines containing non-ASCII. So `é = 1` has column -1. Decorator line/column
  and decorated def/class locations use plain line_column (no double conversion).
- BinOp writes no location. Statements and expressions end with END (255) written after match.
- Big ints: decimal -> underscores stripped text; radix -> original token text (with `_`);
  values 2^63..2^64-1 -> decimal of the u64.

## Design
- Package `lib/ast_serialize/` (relative imports only; the check tool loads it under another name).
- Everything on UTF-8 bytes; offsets are byte offsets (Ruff TextSize).
- `_tokens.py` (generated by `$S/astser/scripts/gen_tokens.py`), `_unicode.py` (generated by
  `gen_unicode.py` from CPython 3.13 Unicode 15.1: deviation vs unicode-ident's Unicode 17),
  `_lexer.py` (port of lexer.rs).

## Known deviations
- .ipynb file names: no IPython mode (extension: Mode::Ipython; its serializer panics on escapes)
- argument type validation messages (PyO3's) differ
- result dict values typed as a union in Pystachy (narrow with isinstance in a function)
- parse() raises sys recursion limit to >= 20000 during the call (restores after)
- extension panics (e.g. check_surrogate_codepoint on invalid \u in raw string with U+FFFD):
  port does not panic
- error codes validation `char::is_alphanumeric` for non-ASCII approximated by str.isalnum

## Subset findings (Pystachy)
- `str | bytes | None` parameter unsupported ("bytes in a closed union"): parse()'s source is
  unannotated (specialized per call)
- fields assigned from locals/constants need annotations (`self.x: T = ...`)
- `e.strerror`/`e.errno` of OSError unsupported: parse str(e)
- dict with union values `dict[str, bool | str | list[...] | list[...]]` works
- no `str.isidentifier` (use own XID tables)
- `len(str)` counts code points (docs agree); work on bytes anyway
- unicodedata.normalize works (Unicode 15.1)

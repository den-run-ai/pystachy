# Native mypy: progress on 12 November 2026

Research branch material, not for `main`. Follows [PROGRESS-2026-11-11.md](PROGRESS-2026-11-11.md);
same inputs (mypy 2.4.1, librt 0.16.0, CPython 3.13.18, LLVM 18.1.3, a shared 4-vCPU VM).

## Does mypyc compile?

Not yet as a program. In the 11 November sweep, 13 of mypyc's 102 modules compile (the package
`__init__`s and leaves such as `mypyc.namegen`, `mypyc.crash`, `mypyc.codegen.cstring`), and
`mypyc.namegen`'s 5 upstream unit tests already run natively (`tests/upstream/pytest`, from
before this work). mypyc compiles a program by running mypy's parser, semantic analysis and
checker first, so running mypyc natively needs mypy's front end too.

The smallest mypyc closure with real content is its IR: `mypyc.ir.ops` eagerly imports 6
project modules, against 10 for `mypy.nodes` and 146 for `mypyc.irbuild.builder`. Its blocker
chain, with stand-ins and probe patches, is in
[results/2026-11-12/mypyc-ir-ops-chain.md](results/2026-11-12/mypyc-ir-ops-chain.md): seven
small typing and inference forms, runtime-length tuples of objects, class objects as values
(#805), and then generic visitors (`accept(self, visitor: RTypeVisitor[T]) -> T` over
`RTypeVisitor(Generic[T])` subclasses, #962), which also gate mypy's `NodeVisitor[T]`.

Two first blockers are larger than their counts suggest:

- `FlexibleAlias` (86 modules with stand-ins) is not an alias problem: mypy writes
  `def copy_modified(self, *, values: Bogus[list[Type]] = _dummy, ...)` with
  `_dummy: Final[Any] = object()` (`mypy/types.py:220`) and tests `values is not _dummy`. A
  parameter of a concrete type defaulting to a sentinel of another type needs a representation
  (a hidden "passed" flag, say) before `Bogus = FlexibleAlias[T, T]` helps.
- `mypy/util.py:374` (33 modules) is `fields_cache: Final[dict[type[object], list[str]]]` for
  `get_class_descriptors()` and `replace_object_state()`, which use `inspect.getmembers`,
  `__dict__` assignment and `setattr`/`getattr` by computed names. Class objects as keys
  (#805) are only the first of these.

Generic visitors (#962): #1298 covers visitors whose type arguments are concrete. Still open:
generic pass-through bases (`class BaseAnalysisVisitor(OpVisitor[GenAndKill[T]])`), multiple
generic bases (mypy's `NodeVisitor`, mypyc's `IRVisitor(ExpressionVisitor[Value],
StatementVisitor[None])`), a visitor held where its base is declared over two return-type
families, and subclasses of generic classes whose `__init__` binds type variables.

## The `mypyc.ir.ops` chain with all open PRs

An integration tree of `main` (`8434a911`) with every open PR above (two textual conflicts
resolved: the python-int sweep manifest and #1277's `init_template` argument) bootstraps to its
fixed points. The sweeps do not move (29 of 242 with stand-ins, 28 without): the first blockers
are still upstream of these changes (`FlexibleAlias` 86, `util.py:374` 33, `inspect` 31; without
stand-ins `pprint` 100, `importlib` 55). The chain of 12 November, with only the `util.py:374`
probe patch left, now passes steps 1 and 3 to 9 (tuples of objects, joins, `ClassVar`, `and`
with an imported constant, generic visitors) and stops at:

1. `rtypes.py:543`: a joined `tuple[Capsule, ...]` passed as `tuple[Dependency, ...] | None`;
   CPython's tuples are covariant. Added to #1297 (a new tuple of union boxes).
2. `rtypes.py:759`: `RInstance.__init__(self, class_ir: ClassIR)` where `ClassIR` is imported
   only under `if TYPE_CHECKING:` (a circular import: `class_ir` imports `rtypes`). Pystachy
   drops such bodies (`docs/language/modules.md`), so the annotation names nothing. mypy uses
   the same pattern throughout; the next structural item after #962's visitors.

## After the type-only imports (#1317)

#1317 lets annotations name classes that `if TYPE_CHECKING:` imports bind, where the program
imports their module anyway. With it and the fixes of the afternoon (#1293's item-slot rule,
#1297's indexed reads), [the chain of `import mypyc.ir.class_ir`](results/2026-11-12/mypyc-class-ir-chain.md)
gets through `rtypes`, `ops` and `func_ir`'s own code and stops at `inspect` (a stand-in now),
then at `defaultdict(set)` held by a `dict` annotation (`errorcodes.py:14`, a probe patch), then
at `mypy/visitor.py:363`: `NodeVisitor`'s four generic, method-only bases.

The sentinel defaults come after those (a minimal reproduction fails with `expected list[int],
got object` at the default): 53 parameters of `mypy/types.py`, used only in
`x if x is not _dummy else y` (28), `y if x is _dummy else x` (8), `if x is _dummy: x = ...` (3)
and two longer conditional expressions. Design notes: a parameter `p: T = S` (S a module
`object()` sentinel) could hold a pointer that is either S or a T (boxed if T is a scalar), narrowed
by `p is S` / `p is not S` with `Gen.narrowed` as `x is None` narrows an optional, and rejected
where read un-narrowed. Virtual dispatch matters: `TypeVarLikeType.copy_modified(self, *, id,
**kwargs)` is overridden by three classes with sentinel parameters.

### `import mypy.types` compiles with probe patches

With #1352 (implicitly generic subclasses) too, and probe patches standing in for the remaining
rows above (class tuples inlined, `FakeInfo.__getattribute__` removed, both `deserialize_map`
reflections replaced by empty dicts, `ANY_STRATEGY` imported from `mypy.type_visitor`,

import mypy.types` compiles to IR (13,910 lines: module initialization; import compilation, not
working APIs). Two more rows to the table: `types.py:4417` repeats the `globals()` reflection
(`names = globals().copy()` for its own `deserialize_map`), and `types.py:2744` is the only
`NewType` in mypy and mypyc. The mypyc chain (`import mypy.fixup; import mypyc.ir.class_ir`) then
stops at `mypyc/ir/rtypes.py:759`: `RVec.buf_type` is assigned `vec_buf_types[item_type]` and two
module-level `RStruct(...)` objects defined further down (`VecNestedBufObject`,
`VecTBufObject`), and field inference cannot type it.

How this was measured
  • Commits: end-of-day points on main and every release tag from 7 October to 11 November 2026, each built with its own bootstrap (CPython 3.13 hosting stage 1, LLVM 18.1.3) in a separate worktree and checked at its own fixed point.
  • CPython test methods: today's tools/cpython_test_methods.py extracted 9,855 unittest methods from the 144 pinned CPython 3.13.16 test files of tests/upstream/core-methods.sha256; 5,905 complete under CPython 3.13.18 and form the denominator. A method passes when the commit's JIT prints CPython's stdout and stderr and exits the same way, including on a retry with promoting ints. The latest commit reproduces the repository's own census within one method.
  • Language and builtins tests are the 60 files that test syntax, builtins and core types (test_set, test_patma, test_builtin, test_exceptions and the like); the rest test standard-library modules.
  • Performance: today's 25 adapted pyperformance ports and the six original microbenchmarks, built AOT by each commit and run pinned to one core on an otherwise idle 4-vCPU x86-64 VM, every commit interleaved in each repetition with CPython 3.13.18. Ports report pyperf's timed region; microbenchmarks report process wall time. Every run's output must equal CPython's. unpack_sequence is left out because AOT removes its timed loop.
  • Repetitions: five per port and seven per microbenchmark at every commit, medians reported. Between a benchmark's second-fastest and second-slowest run the spread was typically 1–10% (up to about 25% for the shortest programs), so index changes under about 5% are within noise.
  • The core set is the 16 ports whose output matched at every sampled commit since the first one with ten working ports (15 October). The pyperformance index uses only that set, so its points compare the same programs.
  • Compile time: pystachy build of nbody (day-one), richards and raytrace, two runs each pinned to one CPU; JIT end-to-end runs of the six day-one programs with the program cache off and a warm runtime cache.
  • Causes are assigned from the text of the first compiler error. A method needs every blocker removed, and only the first is visible, so the categories show what is in front, not everything that remains.

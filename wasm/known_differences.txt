# Corpus programs whose output in tests/run.sh's Wasm modes differs from CPython's recording
# (wasm/README.md, "What differs from a native build"): NAME REASON [MODE...], in both modes,
# wasm and wasm-tir, unless MODEs are named. wasm/check_corpus.py fails on any other difference
# and names the entries that now match, which can then go. Reasons:
#   errno         WASI's errno numbers and messages (ENOENT is 44), which also choose OSError's subclass
#   dev-full      /dev/full through Node's WASI: ENOSPC is 51, and some writes fail at a later flush
#   process       no processes: os.system, subprocess, and files or FIFOs a shell command makes
#   descriptors   no dup, dup2 or descriptor inheritance
#   enosys        another call that wasi_stubs.c fails with ENOSYS (chmod)
#   signal        no signals: SIGINT never arrives
#   select        no select()
#   thread        no threads
#   closed-stdio  a standard descriptor closed at the start is open in the guest
#   gc            the collector is off: weak references stay alive and dropped files stay open
#   stack         V8's own stack limit ends deep recursion first
#   libm          wasi-libc's libm differs from glibc's in the last place of some results
#   nan-sign      float('-nan') has no sign bit
#   unexplained   a buffered binary file's position or error after a seek, truncate or read at
#                 its end (not yet diagnosed: wasi-libc's stdio)
#   #N            a bug that pull request #N fixes
